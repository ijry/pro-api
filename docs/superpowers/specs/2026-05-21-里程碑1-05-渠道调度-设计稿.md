# 里程碑 M1-05 渠道调度

## 1. 目标与范围

### 1.1 一句话

**统一管理 N 个"上游 API key + 模型映射 + 优先级权重"组合,在每次请求时选出最优渠道,熔断异常渠道,允许故障转移**。

### 1.2 模块定位

`internal/channel/` 是 M1 代理流程的**调度层**:

- **输入**:客户端模型名 + 用户/令牌 hint(分组、tag、已失败 channel 列表)
- **输出**:一个可立刻调用的 `*Channel` 对象(已解密的 credentials + 模型映射 + provider 信息)
- **不输出**:不直接调用 adapter — 调度只挑出渠道,adapter 调用由 [M1-04 适配器层](./2026-05-21-里程碑1-04-适配器层-设计稿.md) 与 `internal/relay/` 协作完成

调度层向下隔离 DB(channel CRUD)与 Redis(熔断状态),向上为 `relay/` 提供 `Selector + WithRetry` 两件套。

### 1.3 范围(本 spec 必须实现)

属于本 spec 的(11 件事):

1. **DB schema**:`channels` 与 `channel_model_mappings` 两张表的 migration
2. **CRUD 仓储**:`internal/channel/repo.go` — channel + mapping 的 ORM 层(含 credentials 加密透明读写)
3. **本地缓存**:`internal/channel/cache.go` — `channelsByModel map[string][]*Channel`,启动时全表预热,Pub/Sub 单条失效
4. **Selector**:`internal/channel/selector.go` — 优先级分组 + 加权随机,自动跳过熔断 OPEN 与 Excluded
5. **Breaker**:`internal/channel/breaker.go` — 三态状态机 + Redis Hash 存储 + Pub/Sub 广播
6. **HALF_OPEN 探针抢令牌**:`SET NX channel:probe_lock:{id} ... EX <timeout>`
7. **故障转移 helper**:`internal/channel/retry.go` — `WithRetry(ctx, attempts, fn)`,M1-04/M1-06 调用
8. **渠道测试**:`internal/channel/tester.go` — `Test(channelID)` 发一条 "Hello" chat,返回 latency / error;bypass 计费 / 限流
9. **批量测试**:`/api/admin/channels/batch_test` — goroutine + semaphore 并发上限 5
10. **HTTP handlers**:`internal/server/handler/admin/channel.go` — 10 个 admin 端点
11. **健康分接口预留**:`internal/channel/health.go` — 仅 `interface HealthScorer` 占位,M3 实现

### 1.6 关键术语(对齐 [§11 术语表](./2026-05-21-里程碑1-总体设计纲要.md#11--共识术语表))

| 术语 | 定义 |
|---|---|
| channel | 一个 API key + 模型映射 + 优先级权重的组合;对应 `channels` 表一行 |
| mapping | client_model → upstream_model 的映射;对应 `channel_model_mappings` 表一行;一个 channel 可有多 mapping |
| credentials | 加密落库的凭证 JSON;字段 `{api_key, secret, region, base_url, extra}` |

| excluded | 本次请求已失败的 channel id 集合,用于 retry 时跳过 |
| probe | HALF_OPEN 期间的"试探请求",抢令牌成功才能放行 |
| WithRetry | 故障转移外壳函数,统一包装"Select → adapter call → 失败 → 报告 → 重试" |

PG `migrations/postgres/000006_create_channels.up.sql`:

```sql
CREATE TABLE IF NOT EXISTS channels (
    id          BIGINT       NOT NULL PRIMARY KEY,
    name        VARCHAR(64)  NOT NULL,
    provider    VARCHAR(32)  NOT NULL,
    base_url    VARCHAR(256) NOT NULL DEFAULT '',
    credentials TEXT         NOT NULL,
    priority    SMALLINT     NOT NULL DEFAULT 0,
    weight      INT          NOT NULL DEFAULT 1,
    status      SMALLINT     NOT NULL DEFAULT 0,
    tags        JSONB        NOT NULL,
    extra       JSONB        NOT NULL,

    updated_at  TIMESTAMPTZ  NOT NULL,
    deleted_at  TIMESTAMPTZ  NULL
);
CREATE INDEX IF NOT EXISTS idx_channel_provider_status ON channels (provider, status);
CREATE INDEX IF NOT EXISTS idx_channel_priority_weight ON channels (priority, weight);
CREATE INDEX IF NOT EXISTS idx_channel_deleted ON channels (deleted_at);
```

down(MySQL/PG 相同):

```sql
DROP TABLE IF EXISTS channels;
```

**索引选择理由**:

- `idx_channel_provider_status`:管理端列表筛选(按 provider / status 过滤)主入口
- `idx_channel_priority_weight`:启动时按 `priority DESC, weight DESC` 预热 cache 时排序友好;真正运行时不查 DB
- `idx_channel_deleted`:软删后台过滤、定期清理用

**为什么不在 channels 上索引 `name`**:`name` 仅用于后台展示与搜索,搜索由 LIKE 完成(channels 总量 < 1000),不必要。

### 2.4 GORM 模型

`internal/channel/channel.go`:

```go
package channel

import (
    "encoding/json"
    "time"
)

// Channel 是 channels 表的 ORM 模型 + 领域值对象。
//
// 与 [总纲 §4.3](../里程碑1-总体设计纲要.md#43-channel-selector) 中 Selector 输出的 Channel 是同一类型 — 这里加上
// ORM tag 即可。
type Channel struct {
    ID          int64           `gorm:"primaryKey;column:id"                                            json:"id"`
    Name        string          `gorm:"column:name;size:64"                                             json:"name"`
    Provider    string          `gorm:"column:provider;size:32"                                         json:"provider"`
    BaseURL     string          `gorm:"column:base_url;size:256"                                        json:"base_url"`
    Credentials string          `gorm:"column:credentials;type:text"                                    json:"-"` // 加密串
    Priority    int16           `gorm:"column:priority"                                                 json:"priority"`
    Weight      int             `gorm:"column:weight"                                                   json:"weight"`
    Status      int8            `gorm:"column:status"                                                   json:"status"`
    Tags        json.RawMessage `gorm:"column:tags;type:json"                                           json:"tags"`
    Extra       json.RawMessage `gorm:"column:extra;type:json"                                          json:"extra"`
    CreatedAt   time.Time       `gorm:"column:created_at"                                               json:"created_at"`
    UpdatedAt   time.Time       `gorm:"column:updated_at"                                               json:"updated_at"`
    DeletedAt   *time.Time      `gorm:"column:deleted_at;index"                                         json:"deleted_at,omitempty"`

    // 应用层运行时字段(不持久化):
    Cred           Credential               `gorm:"-" json:"-"`  // Credentials 解密后
    ModelMap       map[string]string        `gorm:"-" json:"-"`  // 预聚合的 client_model→upstream_model
    ModelOverrides map[string]ModelOverride `gorm:"-" json:"-"`  // 单渠道倍率覆盖
}

func (Channel) TableName() string { return "channels" }

// ModelMapping 是 channel_model_mappings 表的 ORM 模型。
type ModelMapping struct {
    ID             int64     `gorm:"primaryKey;column:id"`
    ChannelID      int64     `gorm:"column:channel_id"`
    ClientModel    string    `gorm:"column:client_model;size:128"`
    UpstreamModel  string    `gorm:"column:upstream_model;size:128"`
    InputRatio     *float64  `gorm:"column:input_ratio;type:decimal(10,4)"`
    OutputRatio    *float64  `gorm:"column:output_ratio;type:decimal(10,4)"`
    CachedRatio    *float64  `gorm:"column:cached_ratio;type:decimal(10,4)"`
    ReasoningRatio *float64  `gorm:"column:reasoning_ratio;type:decimal(10,4)"`
    CreatedAt      time.Time `gorm:"column:created_at"`
    UpdatedAt      time.Time `gorm:"column:updated_at"`
}

func (ModelMapping) TableName() string { return "channel_model_mappings" }

// Credential 是渠道凭证的应用层解构,落库时序列化为 JSON 再 AES-GCM 加密。
// 字段对齐 [总纲 §4.1 Credential](../里程碑1-总体设计纲要.md#41-adapter)。
type Credential struct {
    APIKey  string            `json:"api_key"`
    Secret  string            `json:"secret,omitempty"`
    Region  string            `json:"region,omitempty"`
    BaseURL string            `json:"base_url,omitempty"`
    Extra   map[string]string `json:"extra,omitempty"`
}

// ModelOverride 是单渠道模型倍率覆盖,nil 字段表示用模型字典默认值。
type ModelOverride struct {
    InputRatio     *float64
    OutputRatio    *float64
    CachedRatio    *float64
    ReasoningRatio *float64
}
```

### 2.5 credentials 序列化与加密

应用层规则:

1. 输入(handler / 测试):`Credential` 结构体
2. 序列化:`json.Marshal(cred)` → `{"api_key":"sk-...","region":"eastus","extra":{"deployment":"gpt-4o"}}`
3. 加密:`Application.Crypto.Encrypt([]byte(jsonStr))` → `ENC(v1,<nonce>,<ct>)` 字符串
4. 落库:写入 `channels.credentials` 列(text)
5. 读取反序:`Application.Crypto.Decrypt(raw)` → JSON → `json.Unmarshal` 回 `Credential`

`Channel.Credentials` 字段在 ORM 层始终是密文。`Channel.Cred` 字段是应用层运行时解密后的值,**不参与持久化**(GORM tag `-`)。

写流程在 `repo.SaveChannel`:

```go
func (r *repo) SaveChannel(ctx context.Context, c *Channel) error {
    if !c.Cred.IsZero() {
        b, err := json.Marshal(c.Cred)
        if err != nil { return apierr.New(apierr.CodeInvalidParam, "encode credentials: "+err.Error()) }
        enc, err := r.crypto.Encrypt(b)
        if err != nil { return apierr.New(apierr.CodeInternal, "encrypt credentials: "+err.Error()) }
        c.Credentials = enc
    }
    if c.ID == 0 { c.ID = r.id.Generate() }
    c.UpdatedAt = r.clock.Now().UTC()
    return r.db.WithContext(ctx).Save(c).Error
}
```

读流程在 `repo.LoadChannel` 与 `cache.Warmup`:

```go
func (r *repo) hydrate(ch *Channel) error {
    if ch.Credentials == "" { return nil }
    raw, err := r.crypto.Decrypt(ch.Credentials)
    if err != nil {
        return apierr.New(apierr.CodeChannelMisconfig, "decrypt credentials failed for channel "+strconv.FormatInt(ch.ID, 10))
    }
    return json.Unmarshal(raw, &ch.Cred)
}
```

**异常处理**:某条 channel 解密失败时,**不让全局 cache 加载失败** — 把该条置为 `Status=1`(手动禁用)记录 audit `channel.misconfig`,继续加载其他渠道(否则一个坏的渠道阻塞整个服务启动)。

### 2.6 ID 生成

channels / channel_model_mappings 主键用 `Application.IDGen.Generate()`(Snowflake),非自增。落库前由 service 层填充 id,Migration 不带 `AUTO_INCREMENT`。

### 2.7 软删除约定

`channels.deleted_at`:

- `NULL` = 正常
- 非 NULL = 已软删

仓储 / Selector / cache 全部用 `WHERE deleted_at IS NULL` 过滤。Mapping 表**不软删**(channel 软删时联动 cache 重建,mappings 留 DB 不影响 — 真要清理由后续 M2 周期 job)。

GORM 软删除约定:**不**使用 GORM 内置 `gorm.DeletedAt` 机制(否则 PG/MySQL 行为略有差异)。改用裸 `*time.Time` 字段 + 仓储显式 WHERE。

```go
import (
    "context"
    "time"

    Create(ctx context.Context, in CreateInput, actorID int64) (*Channel, error)
    Get(ctx context.Context, id int64) (*Channel, error)                        // 含解密的 Cred
    List(ctx context.Context, q ListQuery) ([]*Channel, int64, error)
    Patch(ctx context.Context, id int64, p PatchInput, actorID int64) (*Channel, error)
    Delete(ctx context.Context, id int64, actorID int64) error                   // 软删

    // ===== 状态 =====
    Enable(ctx context.Context, id int64, actorID int64) error
    Disable(ctx context.Context, id int64, actorID int64) error                  // status → 1 manual_disabled

    // ===== 模型映射 =====
    ListMappings(ctx context.Context, channelID int64) ([]*ModelMapping, error)
    ReplaceMappings(ctx context.Context, channelID int64, mappings []*ModelMapping, actorID int64) error // 批量替换

    Test(ctx context.Context, id int64) (TestResult, error)                       // 单渠道
    BatchTest(ctx context.Context, ids []int64) ([]TestResult, error)             // 并发 ≤ 5

    // ===== 健康 =====
    Health(ctx context.Context, id int64) (HealthSnapshot, error)

    // ===== Selector / Breaker / Retry =====
    Selector() Selector
    Breaker() Breaker
}

type CreateInput struct {
    Name     string
    Provider string
    BaseURL  string
    Cred     Credential
    Priority int16
    Weight   int
    Status   int8           // 0/1;不允许直接设为 2(auto_broken,由 breaker 写)
```

### 3.2 Selector(对齐总纲 §4.3)

签名 100% 沿用 [总纲 §4.3](./2026-05-21-里程碑1-总体设计纲要.md#43-channel-selector):

```go
type Selector interface {
    Select(ctx context.Context, model string, hint SelectHint) (*Channel, error)
    ReportSuccess(channelID int64, latency time.Duration)
    ReportFailure(channelID int64, err error)
}
```

实现要点(详见 §4.2):

- `Select` 命中本地缓存 `channelsByModel[model]`,O(候选数) 过滤
- `ReportSuccess` / `ReportFailure` 转给 `Breaker.RecordSuccess / RecordFailure`,异步统计 + 触发状态转移
- 选中后返回 `Channel` 的 **deep copy**,避免 caller 改字段污染缓存(如 caller 把 ID 加入 Excluded、或修改 ModelMap)

### 3.3 Breaker

`internal/channel/breaker.go`:

```go
package channel

import (
    "context"
    "time"
)

type BreakerState string

const (
    StateClosed   BreakerState = "closed"
    StateOpen     BreakerState = "open"
    StateHalfOpen BreakerState = "half_open"
)

// Breaker 是单实例视角的熔断器。多实例通过 Redis Hash 共享状态。
type Breaker interface {
    // State 返回某 channel 的当前熔断状态(读本地缓存,默认 closed)。
    State(channelID int64) BreakerState

    // Snapshot 返回完整快照,用于 /health 接口。
    Snapshot(channelID int64) HealthSnapshot

    // RecordSuccess / RecordFailure 是 Selector 在 retry 中调用的入口。
    // 内部会:
    //   - 异步累加 Redis Hash 计数
    //   - 触发状态转移(必要时)
    //   - 转移时 Publish 广播
    RecordSuccess(channelID int64, latency time.Duration)
    RecordFailure(channelID int64, err error)

    // AcquireProbe 在 HALF_OPEN 状态下抢令牌。
    //   - 返回 (true, releaseFn) 表示当前请求是探针,可放行;调用方在 adapter 调用结束后 release
    //   - 返回 (false, nil) 表示别人已经抢走,本次直接当作"不可用",由 Selector 返 CodeNoChannel(或换下一个 channel)
    AcquireProbe(ctx context.Context, channelID int64, timeout time.Duration) (acquired bool, release func(), err error)

    // ForceTransition 强制状态转换(后台手工启用渠道时调用,把状态 reset 回 closed)。
    ForceTransition(channelID int64, to BreakerState) error
}
```

参数(从 [总纲 §7.2](./2026-05-21-里程碑1-总体设计纲要.md#72--运行时配置system_settings-表) 读):

- `channel.breaker.window_seconds`(默认 60)
- `channel.breaker.fail_threshold`(默认 5)
- `channel.breaker.cool_down_seconds`(默认 30)

热加载:Breaker 启动时缓存上述 3 个值,订阅 `setting.Subscribe(ctx)` channel,key 命中时 reload。

```go
        i, id := i, id

        go func() {

            defer func() { <-sem }()
```

## 4. 关键算法

### 4.1 本地缓存:全表预热 + Pub/Sub 单条失效

**为什么"单条更新"而不是"全量 reload"**:

- channels 总量 < 1000,但每次 Patch 就全表扫一次浪费 IO
- Pub/Sub payload 含 `channel_id`,接收端只重 SELECT 1 行,**O(1) 复杂度**
- 多实例之间无需"原子性同步" — 短窗口不一致可接受

**数据结构**:

```go
type cache struct {
    repo   *repo
    rdb    *redis.Client
    log    *zap.Logger
    clock  clock.Clock

    mu               sync.RWMutex
    byID             map[int64]*Channel             // channel id → *Channel(完整,含解密 Cred)
    channelsByModel  map[string][]*Channel          // client_model → 候选(只持指针,排序后存)
    decryptFailedIDs map[int64]struct{}             // 自动禁用集

    pubsub *redis.PubSub
    stop   chan struct{}
}
```

**Warmup 流程**(`channel.Service.New` 内同步调用):

```
1. SELECT * FROM channels WHERE deleted_at IS NULL
2. SELECT * FROM channel_model_mappings WHERE channel_id IN (...)
3. 对每个 channel:
   3.1 decrypt credentials → Cred;失败则 status=1 + audit + 记 decryptFailedIDs
   3.2 ModelMap = {mapping.ClientModel: mapping.UpstreamModel}
   3.3 ModelOverrides = {mapping.ClientModel: ModelOverride{...}} (4 个 ratio)
4. 构建 channelsByModel:
   for each channel c:
       for clientModel in c.ModelMap.keys():
           append c to channelsByModel[clientModel]
   for each model:
       sort channelsByModel[model] by (priority DESC, weight DESC)  (排序仅 cosmetic,Selector 仍要二次过滤)
5. 写 cache.byID + cache.channelsByModel
6. 启动 Pub/Sub 订阅
```

**失败兜底**:

- 任何一条解密失败 → 跳过该条,记 audit,继续
- mapping 表 SELECT 失败 → 整个 Warmup 失败,启动报错(因为没 mapping 就无法路由,不如不启动)
- channels 表 SELECT 失败 → 同上

**Reload 单条**:

```go
func (c *cache) Reload(ctx context.Context, id int64) error {
    ch, err := c.repo.GetByIDIncludingDeleted(ctx, id)   // 含 deleted_at!=nil 的也要拉,用于判断"该删了"
    if err != nil { return err }

    c.mu.Lock()
    defer c.mu.Unlock()

    // 先从旧索引中移除
    old, ok := c.byID[id]
    if ok {
        for clientModel := range old.ModelMap {
            c.channelsByModel[clientModel] = removeChannel(c.channelsByModel[clientModel], id)
            if len(c.channelsByModel[clientModel]) == 0 {
                delete(c.channelsByModel, clientModel)
            }
        }
        delete(c.byID, id)
    }

    // 如果已软删 / 不存在,直接结束
    if ch == nil || ch.DeletedAt != nil {
        return nil
    }

    // 重新 hydrate(解密 + 加载 mappings)
    if err := c.hydrate(ctx, ch); err != nil {
        c.log.Warn("cache: reload hydrate failed", zap.Int64("id", id), zap.Error(err))
        return nil  // 不让一条坏的影响 reload 不报错
    }

    c.byID[id] = ch
    for clientModel := range ch.ModelMap {
        list := c.channelsByModel[clientModel]
        list = append(list, ch)
        sort.SliceStable(list, func(i, j int) bool {
            if list[i].Priority != list[j].Priority { return list[i].Priority > list[j].Priority }
            return list[i].Weight > list[j].Weight
        })
        c.channelsByModel[clientModel] = list
    }
    return nil
}
```

**Pub/Sub 接收循环**:

```go

```

**Pub/Sub 丢消息兜底**:Redis Pub/Sub 是 best-effort。M1 设两道保险:

1. 启动时全量 Warmup(本来就有)
2. cron 30 分钟一次 `channel.Service` 内部跑 `cache.Warmup` 重建一次(配置 `channel.cache.refresh_interval_seconds`,默认 1800;0 表示关掉)

> 决策:M1 暂不启用 cron 兜底(简单第一),只在 cache 接口预留 `RefreshAll(ctx)` 方法,M2 加 scheduler 后再接。

**ChannelsByModel 调用 deepcopy**:

```go
func (c *cache) ChannelsByModel(model string) []*Channel {
    c.mu.RLock()
    list := c.channelsByModel[model]
    c.mu.RUnlock()

    out := make([]*Channel, len(list))
    for i, ch := range list {
        cp := *ch         // 浅拷
        cp.ModelMap = cloneStringMap(ch.ModelMap)
        cp.ModelOverrides = cloneOverrideMap(ch.ModelOverrides)
        cp.Cred = ch.Cred // value copy(Extra map 也要拷)
        cp.Cred.Extra = cloneStringMap(ch.Cred.Extra)
        out[i] = &cp
    }
    return out
}
```

**为什么 deep copy**:Selector 返回的 channel 给上层后,上层可能:

- 把 ID 加进 Excluded(不会改 channel 本身,可)
- 改 ModelMap(不应该,但 deepcopy 防意外)
- 把 Cred 传给 adapter,adapter 不修改

所以 deep copy 是**防御性的**;成本可接受(channels 总量小,候选数通常 < 10)。

### 4.2 Selector — 优先级分组 + 加权随机

实现 [总纲 §5.4](./2026-05-21-里程碑1-总体设计纲要.md#54-渠道选择优先级--加权随机) 算法。完整代码:

```go
package channel

import (
    "context"
    "math/rand"
    "sync"

    "github.com/proapi/proapi/pkg/apierr"
)

type selector struct {
    cache   *cache
    breaker Breaker

    randMu sync.Mutex
    rnd    *rand.Rand  // 独立 rand,避免 math/rand 全局锁
}

func newSelector(c *cache, b Breaker, seed int64) *selector {
    return &selector{
        cache:   c,
        breaker: b,
        rnd:     rand.New(rand.NewSource(seed)),
    }
}

func (s *selector) Select(ctx context.Context, model string, hint SelectHint) (*Channel, error) {
    candidates := s.cache.ChannelsByModel(model)
    if len(candidates) == 0 {
        return nil, apierr.New(apierr.CodeNoChannel, "no channel configured for model "+model)
    }

    var filtered []*Channel
    for _, c := range candidates {
        if c.Status != 0 { continue }                              // 跳过禁用 / 自动熔断
        if inInt64Slice(hint.Excluded, c.ID) { continue }          // 已失败过
        if s.breaker.State(c.ID) == StateOpen { continue }          // 熔断 OPEN
        if !tagsMatch(c.Tags, hint.Tags) { continue }              // tag 过滤
        filtered = append(filtered, c)
    }
    if len(filtered) == 0 {
        return nil, apierr.New(apierr.CodeNoChannel, "no available channel for model "+model+" (all filtered)")
    }

    // 取最高优先级一组
    topPrio := filtered[0].Priority
    for _, c := range filtered {
        if c.Priority > topPrio { topPrio = c.Priority }
    }
    var pool []*Channel
    for _, c := range filtered {
        if c.Priority == topPrio { pool = append(pool, c) }
    }

    // 加权随机
    return s.weightedRandom(pool), nil
}

func (s *selector) weightedRandom(pool []*Channel) *Channel {
    total := 0
    for _, c := range pool { total += maxInt(c.Weight, 1) }
    s.randMu.Lock()
    r := s.rnd.Intn(total)
    s.randMu.Unlock()
    for _, c := range pool {
        w := maxInt(c.Weight, 1)
        if r < w { return c }
        r -= w
    }
    return pool[len(pool)-1]  // 兜底,float 误差不会发生但保险
}

func (s *selector) ReportSuccess(channelID int64, latency time.Duration) {
    s.breaker.RecordSuccess(channelID, latency)
}

func (s *selector) ReportFailure(channelID int64, err error) {
    s.breaker.RecordFailure(channelID, err)
}
```

**tag 过滤策略**:

```go
func tagsMatch(channelTagsJSON json.RawMessage, required []string) bool {
    if len(required) == 0 { return true }
    var tags []string
    _ = json.Unmarshal(channelTagsJSON, &tags)  // 失败当空数组
    for _, req := range required {
        found := false
        for _, t := range tags {
            if t == req { found = true; break }
        }
        if !found { return false }  // 要求"所有 required 都在"
    }
    return true
}
```

**HALF_OPEN 状态怎么处理**:Selector 中 `breaker.State(c.ID) == StateOpen` 才跳过,**HALF_OPEN 不跳过** — 真正放行控制在 `WithRetry` 中,选到 HALF_OPEN 渠道后调用 `Breaker.AcquireProbe`,抢到才执行 fn。

### 4.3 Breaker 状态机

#### 4.3.1 状态存储

主存 Redis Hash `channel:breaker:{channel_id}`,字段:

| field | value | 说明 |
|---|---|---|
| state | "closed" / "open" / "half_open" | 当前状态 |
| opened_at | unix_ms | 转入 OPEN 时戳;CLOSED 时 = 0 |
| consec_fail | int | 自上次成功以来的连续失败次数(滑动重置:CLOSED→success 重置为 0) |
| last_probe_at | unix_ms | 上次 HALF_OPEN 放行探针的时间(诊断用) |
| success_count | int | 最近 window 内成功数(诊断/health 接口) |
| failure_count | int | 最近 window 内失败数 |
| window_start_ms | unix_ms | 当前统计窗口起点 |

每实例本地缓存:

```go
type breaker struct {

    setting setting.Store
    pub     *redis.PubSub
    clock   clock.Clock
    log     *zap.Logger

    mu     sync.RWMutex

}

type localState struct {
    state        BreakerState
    openedAt     time.Time
    consecFail   int
    lastProbeAt  time.Time
    successCount int
    failureCount int
    windowStart  time.Time
}
```

#### 4.3.2 状态转移规则

完整重述(对齐 [总纲 §5.3](./2026-05-21-里程碑1-总体设计纲要.md#53-渠道熔断状态机)):

```
CLOSED 状态:
  RecordSuccess: consec_fail = 0; 不变
  RecordFailure(retryable err):
    consec_fail += 1
    如果 consec_fail >= fail_threshold:
      → 转 OPEN, opened_at = now
      PUBLISH proapi:channel:breaker {id, "open", now}
      同时把 channels.status 更新为 2 (auto_broken)?
        [决策] 不更新 DB.status — DB 的 status 反映"人工意图",breaker 状态是"运行时" — Selector 已同时检查两者
        但 Status=2 列保留给 M2 的"长期熔断 → 自动禁用"自动化运维路径

OPEN 状态:
  Selector 跳过该 channel(算法第 2 步过滤)
  cron(每 5s 扫一次本地 states 表):
    如果 now - opened_at >= cool_down_seconds:
      → 转 HALF_OPEN, last_probe_at = 0(尚未放行探针)
      PUBLISH proapi:channel:breaker {id, "half_open", now}

HALF_OPEN 状态:
  Selector 允许选中
  WithRetry 调用 AcquireProbe:
    SETNX channel:probe_lock:{id} <random> EX <timeout>
    抢到 → release fn 内 DEL key;放行 adapter 调用
    没抢到 → 当前请求不走该 channel,直接换下一个(本次循环 Excluded 加入该 id)
  RecordSuccess:
    → 转 CLOSED, consec_fail=0
    PUBLISH proapi:channel:breaker {id, "closed", now}
  RecordFailure(retryable err):
    → 转回 OPEN, opened_at=now
    PUBLISH proapi:channel:breaker {id, "open", now}
```

> ⚠️ **HALF_OPEN 期间多个请求并发到来**:正常 Selector 都会选中该 channel(它没在 OPEN),但只有抢到 probe_lock 的那个走 adapter。没抢到的:`WithRetry` 把该 channel 加入 Excluded,继续选下一个候选 — 如果没下一个,返 `CodeNoChannel`。

#### 4.3.3 transition 内部实现

```go
func (b *breaker) transition(channelID int64, to BreakerState, reason string) {
    key := redisKey(channelID)
    now := b.clock.Now().UnixMilli()

    pipe := b.rdb.TxPipeline()
    pipe.HSet(ctx, key, "state", string(to))
    switch to {
    case StateOpen:
        pipe.HSet(ctx, key, "opened_at", now)
    case StateClosed:
        pipe.HSet(ctx, key, "opened_at", 0)
        pipe.HSet(ctx, key, "consec_fail", 0)
        pipe.HSet(ctx, key, "last_probe_at", 0)
    case StateHalfOpen:
        pipe.HSet(ctx, key, "last_probe_at", 0)
    }
    pipe.Expire(ctx, key, 24*time.Hour)  // 防止永久占用,1 天没活动自动清
    if _, err := pipe.Exec(ctx); err != nil {
        b.log.Error("breaker: transition redis failed", zap.Error(err))
        // 不 return — 本地仍然更新,等下个 cron 同步
    }

    b.mu.Lock()
    s := b.states[channelID]
    s.state = to
    if to == StateOpen { s.openedAt = b.clock.Now() }
    if to == StateClosed { s.consecFail = 0; s.openedAt = time.Time{} }
    b.states[channelID] = s
    b.mu.Unlock()

    // 广播
    payload, _ := json.Marshal(map[string]any{
        "channel_id": channelID,
        "state":      to,
        "ts":         now,
        "reason":     reason,
    })
    if err := b.rdb.Publish(ctx, "proapi:channel:breaker", payload).Err(); err != nil {
        b.log.Warn("breaker: publish failed", zap.Error(err))
    }
    b.log.Info("breaker transitioned",
        zap.Int64("channel_id", channelID),
        zap.String("to", string(to)),
        zap.String("reason", reason))
}
```

#### 4.3.4 接收广播 + cron 探活

`breaker.loop` 同时跑两件事:

```go
func (b *breaker) loop(ctx context.Context) {
    sub := b.pub.Channel()
    cronTick := b.clock.NewTicker(5 * time.Second)
    defer cronTick.Stop()

    for {
        select {
        case <-b.stop:
            return
        case msg, ok := <-sub:
            if !ok { return }
            b.handlePubSub(msg)
        case <-cronTick.C():
            b.scanOpenForTransition()
        }
    }
}

func (b *breaker) handlePubSub(msg *redis.Message) {
    var payload struct {
        ChannelID int64        `json:"channel_id"`
        State     BreakerState `json:"state"`
        TS        int64        `json:"ts"`
    }
    if err := json.Unmarshal([]byte(msg.Payload), &payload); err != nil { return }

    b.mu.Lock()
    defer b.mu.Unlock()
    s := b.states[payload.ChannelID]
    s.state = payload.State
    if payload.State == StateOpen {
        s.openedAt = time.UnixMilli(payload.TS)
    }
    if payload.State == StateClosed {
        s.consecFail = 0
        s.openedAt = time.Time{}
    }
    b.states[payload.ChannelID] = s
}

// scanOpenForTransition 在本地遍历 OPEN 渠道,看是否到了 cool_down,该转 HALF_OPEN。
// 为什么本地扫:Redis Pub/Sub 不会触发"时间到了"。
func (b *breaker) scanOpenForTransition() {
    coolDown := time.Duration(b.cfg.CoolDownSeconds) * time.Second
    now := b.clock.Now()

    b.mu.RLock()
    var transit []int64
    for id, s := range b.states {
        if s.state == StateOpen && now.Sub(s.openedAt) >= coolDown {
            transit = append(transit, id)
        }
    }
    b.mu.RUnlock()

    // 调 transition 时只允许"本实例首个发现的"成功 — 用 Redis SETNX 抢一次锁
    for _, id := range transit {
        b.tryHalfOpen(id)
    }
}

func (b *breaker) tryHalfOpen(channelID int64) {
    lockKey := fmt.Sprintf("channel:breaker:transition_lock:%d", channelID)
    ok, err := b.rdb.SetNX(ctx, lockKey, "1", 10*time.Second).Result()
    if err != nil || !ok { return }  // 别的实例已经抢了
    defer b.rdb.Del(ctx, lockKey)

    // 二次检查 Redis state — 别人可能在等锁期间已经转了
    state, _ := b.rdb.HGet(ctx, redisKey(channelID), "state").Result()
    if state != string(StateOpen) { return }
    b.transition(channelID, StateHalfOpen, "cool_down_elapsed")
}
```

#### 4.3.5 AcquireProbe

```go
func (b *breaker) AcquireProbe(ctx context.Context, channelID int64, timeout time.Duration) (bool, func(), error) {
    lockKey := fmt.Sprintf("channel:probe_lock:%d", channelID)
    val := fmt.Sprintf("%d-%d", b.clock.Now().UnixNano(), rand.Int63())  // 唯一持有者凭证

    ok, err := b.rdb.SetNX(ctx, lockKey, val, timeout).Result()
    if err != nil {
        return false, nil, apierr.New(apierr.CodeCache, "acquire probe: "+err.Error())
    }
    if !ok { return false, nil, nil }

    release := func() {
        // 仅当 value 仍是自己时才删(避免误删别人续期的锁)
        script := `if redis.call("get", KEYS[1]) == ARGV[1] then return redis.call("del", KEYS[1]) else return 0 end`
        _, _ = b.rdb.Eval(context.Background(), script, []string{lockKey}, val).Result()
    }
    return true, release, nil
}
```

#### 4.3.6 RecordFailure 分类

```go
func (b *breaker) RecordFailure(channelID int64, err error) {
    e, ok := apierr.As(err)
    if !ok { return }  // 非 apierr 不计入(防御性)
    switch e.Code {
    case apierr.CodeUpstreamError,
         apierr.CodeUpstreamTimeout,
         apierr.CodeUpstreamUnavail:
        // 计入
    case apierr.CodeUpstreamRateLimit:
        // 计入 — 但权重小一点?M1 简单处理,同等计入(后续 M2 优化)
    default:
        return  // 4xx 不计入
    }

    pipe := b.rdb.TxPipeline()
    pipe.HIncrBy(ctx, redisKey(channelID), "consec_fail", 1)
    pipe.HIncrBy(ctx, redisKey(channelID), "failure_count", 1)
    cmd := pipe.HGet(ctx, redisKey(channelID), "state")
    cmdFail := pipe.HGet(ctx, redisKey(channelID), "consec_fail")
    if _, err := pipe.Exec(ctx); err != nil && err != redis.Nil {
        b.log.Warn("breaker: record failure pipe failed", zap.Error(err))
        return
    }
    state := cmd.Val()
    consec, _ := strconv.Atoi(cmdFail.Val())

    if state == string(StateClosed) && consec >= b.cfg.FailThreshold {
        b.transition(channelID, StateOpen, "consec_fail >= threshold")
    } else if state == string(StateHalfOpen) {
        b.transition(channelID, StateOpen, "half_open probe failed")
    }
}
```

#### 4.3.7 RecordSuccess

```go
func (b *breaker) RecordSuccess(channelID int64, latency time.Duration) {
    pipe := b.rdb.TxPipeline()
    pipe.HSet(ctx, redisKey(channelID), "consec_fail", 0)
    pipe.HIncrBy(ctx, redisKey(channelID), "success_count", 1)
    cmd := pipe.HGet(ctx, redisKey(channelID), "state")
    _, _ = pipe.Exec(ctx)

        b.transition(channelID, StateClosed, "half_open probe succeeded")
    }
}
```

### 4.4 故障转移 WithRetry 完整实现

```go
func WithRetry(
    ctx context.Context,
    sel Selector,
    attempts int,
    model string,
    hint SelectHint,
    fn RetryFn,
) error {
    if attempts < 1 { attempts = 1 }

    var lastErr error
    excluded := append([]int64{}, hint.Excluded...)

    for i := 0; i < attempts; i++ {
        if err := ctx.Err(); err != nil { return err }

        h := hint
        h.Excluded = excluded
        ch, err := sel.Select(ctx, model, h)
        if err != nil {
            // 没有可用渠道 — 直接返回(不再 retry)
            if lastErr != nil { return lastErr }  // 用 retryable err 比 NoChannel 信息更多
            return err
        }

        // HALF_OPEN 抢令牌
        var release func()
        breaker := sel.(*selector).breaker  // selector 实现一定持有 breaker
        if breaker.State(ch.ID) == StateHalfOpen {
            acquired, rel, _ := breaker.AcquireProbe(ctx, ch.ID, defaultProbeTimeout)
            if !acquired {
                // 没抢到 — 把它列入 excluded,选下一个
                excluded = append(excluded, ch.ID)
                continue
            }
            release = rel
        }

        start := time.Now()
        err = fn(ctx, ch)
        elapsed := time.Since(start)
        if release != nil { release() }

        if err == nil {
            sel.ReportSuccess(ch.ID, elapsed)
            return nil
        }

        // 失败处理
        if !isRetryable(err) {
            // 比如 4xx 客户端错 — 不重试,直接返
            sel.ReportFailure(ch.ID, err)
            return err
        }
        sel.ReportFailure(ch.ID, err)
        lastErr = err
        excluded = append(excluded, ch.ID)
    }
    return lastErr
}
```

边界场景:

- `attempts=1` 且第一次失败:不再选,直接返
- `attempts=3` 但只有 1 个可用 channel 且 ReportFailure 后被熔断:第二次 Select 会跳过 → `CodeNoChannel`,WithRetry 返 `lastErr`(retryable err 信息量大)
- 选到 HALF_OPEN 没抢到 probe:不计入失败,不报告,加入 excluded 重选(本次循环不消耗 attempt)

> **决策**:HALF_OPEN 没抢到 probe **不消耗 attempt**(因为没有真的发请求出去)。所以 `for i := 0; i < attempts; i++` 在 continue 路径上 `i` 不递增?— **递增,继续 i++**,但 hint.Excluded 已加入,下次 select 走下一个。这样保留 attempts 语义,避免无限循环(如果一直没抢到 probe 而又总选到 HALF_OPEN,attempts 用完即 return)。

### 4.5 channels.status 与 breaker state 的关系

3 个状态层叠:

| 字段 | 来源 | 含义 | Selector 是否跳过 |
|---|---|---|---|
| `channels.status = 0` | DB | 正常 | 否 |
| `channels.status = 1` | DB,人工 | 管理员禁用 | 跳过(且 breaker 不自动恢复) |
| `channels.status = 2` | DB,预留 | M2 才用 — "被自动判定长期不可用,需人工处置" | 跳过 |
| Breaker.State == OPEN | Redis,运行时 | 短期熔断,自动恢复 | 跳过 |
| Breaker.State == HALF_OPEN | Redis,运行时 | 试探恢复中 | 不跳过(走 probe) |

**Selector 跳过逻辑** = `Status != 0 OR Breaker.State == OPEN`。

人工 `Enable(id)` 会:
1. UPDATE channels SET status=0 WHERE id=?
2. Breaker.ForceTransition(id, StateClosed)
3. PUBLISH invalidate

人工 `Disable(id)` 会:
1. UPDATE channels SET status=1
2. PUBLISH invalidate
3. **不**改 breaker 状态(breaker 状态机仍由运行时驱动)

### 4.6 渠道测试 — 选哪个模型?

策略(顺序):

1. 该 channel 第一条 mapping 的 client_model(如果存在且能从 `model_catalogs` 查到 family 是 `chat` 系)
2. 若 mapping 都是 embed 类:用 embed 测(发一个短文本 embed)
3. 若 channel 无 mapping:用 provider 的"默认 ping 模型"(由 [M1-04 adapter](./2026-05-21-里程碑1-04-适配器层-设计稿.md) 在 `adapter.Adapter` 上增加方法 `DefaultPingModel() string`)
4. 都没有:返 `TestResult{OK: false, ErrCode: CodeChannelMisconfig, ErrMsg: "no mapping and provider has no default model"}`

> 这里跨依赖了 M1-04 的 `DefaultPingModel`。本 spec 声明依赖,M1-04 spec 在 Adapter 接口上补这个方法即可。

### 4.7 关于 Selector 排序的随机性

`math/rand` 是非加密随机,M1 足够。`Selector.weightedRandom` 用独立 `rand.Rand` 避免全局锁。种子用 `time.Now().UnixNano() + idgen.NodeID` 保证多实例分散。

### 11.4 接口反向暴露

`channel.Service` 是 facade,其他模块通过 `Application.ChannelSvc` 取值。为避免 cycle:

- `M1-04 adapter` import `channel` ❌ — 错!应反过来,本 spec 持有 `adapter.Registry`

`Application.ChannelSvc` 字段在 M1-01 是 `any`,本 spec 在 `wire.WireChannel` 强类型填值:

```go
// internal/app/wire_channel.go (本 spec 提供)
func WireChannel(app *Application, adapters adapter.Registry) error {
    svc, err := channel.New(channel.Config{
        DB:       app.DB,
        Cache:    app.Cache,
        Log:      app.Log,
        IDGen:    app.IDGen,
        Crypto:   app.Crypto,
        Clock:    app.Clock,
        Setting:  app.Setting,
        Audit:    app.Audit,
        Adapters: adapters,
    })
    if err != nil { return fmt.Errorf("channel: %w", err) }
    app.ChannelSvc = svc
    app.AddCloser(svc.Close)
    return nil
}
```

`cmd/proapi/main.go`(由 M1-01 起的装配链)中插入:

```go
// ... M1-01 / M1-02 / M1-03 ...
if err := WireAdapter(app); err != nil { fatal(err) }       // M1-04
if err := WireChannel(app, app.AdapterReg.(adapter.Registry)); err != nil { fatal(err) }  // 本 spec
// ... 后续 M1-06 / M1-07 / M1-08 ...
```

- 2 个实例:在 A 触发 breaker → OPEN,B 实例同步 OPEN,Selector 跳过
- 后台批量测试 50 个 channel,观察 goroutine 同时执行数 ≤ 5(可通过日志或测试断言)
- 软删一个 channel 后:`GET /channels/{id}` 返 404;`GET /channels` 不含;`Selector` 不再选中;Redis `channel:breaker:{id}` 被清
