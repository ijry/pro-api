# 1 / M1 范围与交付物

## 1.1 M1 一句话定位

**OpenAI 格式入口 + 9 家上游 + 完整用户/令牌/计费/日志/限流/后台/前台 + 手动充值,可对外发布"测试版"**。

## 1.2 M1 涵盖能力清单

### 后端

- 用户系统:邮箱密码注册登录 / 邮箱验证码 / GitHub OAuth / Session(Redis)
- API 令牌:`pa-xxx` 生成/吊销/限额/IP 白名单/模型白名单/过期
- 适配器 9 家:`openai / azure / anthropic / gemini / deepseek / moonshot / zhipu / qwen / doubao`
- 渠道:CRUD / 优先级 / 权重 / 模型映射 / 熔断
- 计费:Lua 原子扣 quota / 模型倍率 / 分组倍率
- 日志:请求+消费明细同表分区 / 错误日志独立
- 限流:用户 / 令牌 / IP / 模型 四维度
- 公告
- 手动充值(用户提单 → 管理员审批 → 加额度)
- 兑换码(管理员批量生成 → 用户兑换)

### 前端

- **admin**:仪表盘 / 用户 / 分组 / 渠道 / 模型字典 / 令牌(全局) / 日志 / 公告 / 充值审批 / 兑换码 / 系统设置
- **user**:控制台 / 令牌 / 消费日志 / 个人设置 / 手动充值申请 / 兑换码兑换

### 入口协议

- 仅 **OpenAI 格式**:`/v1/chat/completions` / `/v1/completions` / `/v1/embeddings` / `/v1/models`
- Anthropic / Gemini 入口推到 M2

### 多模态

- 仅 **chat + completions + embeddings**
- DALL-E / TTS / STT / MJ / Suno 全部推到 M2

### 鉴权

- 邮箱密码 + 邮箱验证码 + GitHub OAuth 三种登录
- 用户 Session 后端化(Session+Redis,自定义 token,非 JWT)

## 1.3 M1 排除项

明确**不做**的(避免 scope creep):

- ❌ 三协议互转(只 OpenAI 入口)
- ❌ Anthropic / Gemini 适配器(在 M2 才加)
- ❌ 其余上游(腾讯/讯飞/MiniMax/Groq/Mistral/Cohere/OpenRouter/零一/HF — 9 家放 M2)
- ❌ DALL-E / TTS / STT / MJ / Suno / Rerank
- ❌ Stripe / 支付宝 / 微信支付 / 邀请返佣
- ❌ 部门预算(M3) / SSO(M3) / 审计(M3)
- ❌ Playground / 模型广场 / 文档站完整化(放 M2)
- ❌ Otel(M3) / ClickHouse(M3) / 健康分(M3)
- ❌ asynq 异步任务系统(MJ/Suno 才用,M2 引入)

# 2 / 完整数据模型(M1 表 schema)

每张表给出**字段最终定稿**、索引、迁移命名。各模块 spec 不再重复定义,只引用本节锚点。

总体路线图 §4 列出了 30 个逻辑实体 / 29 张物理表。**M1 涉及其中 20 张**;剩下的(部门、SSO、邀请、CH、async_tasks、payouts、stripe/支付宝/微信订单等)推到 M2/M3。

## 2.0 通用约定

- ID:`BIGINT`,业务表用 Snowflake(`internal/util/idgen`),非自增
- 时间戳:MySQL `DATETIME(3)`(毫秒精度) / PG `TIMESTAMPTZ`
- 时区:存 UTC,展示层做时区
- 金额:`BIGINT`,单位"厘"(1 元 = 10000 厘)
- quota:`BIGINT`,无小数,单位见 §11
- JSON:MySQL 用 `JSON`,PG 用 `JSONB`(GORM tag `serializer:json`)
- 软删除:核心业务表带 `deleted_at`,日志表硬删
- 字符集:MySQL `utf8mb4 / utf8mb4_unicode_ci`

## 2.1 `users`

`migrations/.../000002_create_users_full.up.sql`(在 M0 已建的最小 users 上 ALTER,或 DROP+CREATE)。

考虑 M0 只建了骨架,M1 直接 ALTER 增加 wallet 关联等字段,**避免 DROP**。

```

           │           │             └── selector
```

# 4 / 跨模块接口契约(Go interface)

下面所有接口签名是**最终定稿**。各模块 spec 必须使用同样的签名,若需调整必须先回改本节。

## 4.1 Adapter

```go
package adapter

import (
    "context"
    "io"

    "github.com/ijry/pro-api/internal/protocol/ir"
)

// Capability 表示一个 adapter 支持的能力。
type Capability uint32

const (
    CapChat       Capability = 1 << iota // /v1/chat/completions
    CapStream                              // 流式
    CapCompletion                          // /v1/completions (legacy)
    CapEmbedding                           // /v1/embeddings
    CapVision                              // chat 内含 image
    CapToolUse                             // chat 内含 tools
)

// Credential 是渠道凭证的应用层解构。adapter 只读不写。
type Credential struct {
    APIKey   string
    Secret   string            // 部分厂商需要 secret + key 双因子
    Region   string            // Azure / Bedrock 需要
    BaseURL  string            // 渠道覆盖的 endpoint,空串=用 adapter 默认
    Extra    map[string]string // provider-specific(Azure deployment 映射等)
}

// Adapter 是单个上游适配器的统一接口。每家厂商实现一份。
type Adapter interface {
    Name() string                    // "openai" / "anthropic" / ...
    Capabilities() Capability
    SupportedModels() []string       // 静态列表 + 通配,详见各 adapter spec

    Chat(ctx context.Context, req *ir.ChatRequest, cred Credential) (*ir.ChatResponse, error)
    ChatStream(ctx context.Context, req *ir.ChatRequest, cred Credential) (StreamReader, error)
    Embed(ctx context.Context, req *ir.EmbedRequest, cred Credential) (*ir.EmbedResponse, error)
}

// StreamReader 是流式响应的迭代器。
//
//   for {
//       chunk, err := reader.Next(ctx)
//       if err == io.EOF { break }
//       if err != nil { return err }
//       // chunk 是 IR 中间表示;encoder 负责转回入口协议
//   }
//
// Close 必须在调用方 defer 调用,以确保 HTTP 连接归还。
type StreamReader interface {
    Next(ctx context.Context) (*ir.ChatChunk, error) // io.EOF 表示流末
    Close() error
}

// Registry 是按 provider 名查 adapter 的注册中心。
type Registry interface {
    Register(a Adapter)
    Get(name string) (Adapter, bool)
    List() []Adapter
}
```

**实现约定**:
- adapter 包内必须有一个 `init()` 把自己 register 到全局 registry 还是显式注册?**决策:显式**(`adapter.Register(&openai.OpenAI{})` 在 `cmd/proapi/main.go` 装配阶段调用)— 测试更易隔离。
- adapter **不负责** 计费 / 限流 / 日志 — 它只做"协议转换 + HTTP 调用 + 错误归类"。
- adapter 收到 5xx / 网络错误时返回 `*apierr.Error` 包装 `CodeUpstreamError / CodeUpstreamTimeout`,详见 §8。

# 5 / 关键算法定稿

## 5.1 计费 Lua 脚本(定稿)

放在 `internal/billing/lua/`。

### reserve.lua

```lua
-- KEYS[1] = wallet:{user_id}     hash {balance, reserved, consumed}
-- KEYS[2] = reservation:{rid}    string value=reserved_quota
-- ARGV[1] = est_cost              要预扣的 quota
-- ARGV[2] = ttl_seconds
-- 返回 {ok, balance_after}
--   ok=1 成功;ok=0 余额不足

local balance = tonumber(redis.call('HGET', KEYS[1], 'balance') or '0')
local est = tonumber(ARGV[1])
if balance < est then
    return {0, balance}
end
redis.call('HINCRBY', KEYS[1], 'balance', -est)
redis.call('HINCRBY', KEYS[1], 'reserved', est)
redis.call('SET', KEYS[2], est, 'EX', tonumber(ARGV[2]))
return {1, balance - est}
```

### commit.lua

```lua
-- KEYS[1] = wallet:{user_id}
-- KEYS[2] = reservation:{rid}
-- ARGV[1] = actual_cost
-- 返回 {ok, refund}
--   ok=1 提交成功,refund=退还的差额(可为 0)
--   ok=-1 reservation 不存在(已过期或已 commit/refund)
--   ok=-2 actual > reserved(异常,应该不会发生)

local reserved = tonumber(redis.call('GET', KEYS[2]) or '0')
if reserved <= 0 then return {-1, 0} end
local actual = tonumber(ARGV[1])
if actual > reserved then return {-2, 0} end
local refund = reserved - actual
redis.call('HINCRBY', KEYS[1], 'reserved', -reserved)
if refund > 0 then redis.call('HINCRBY', KEYS[1], 'balance', refund) end
redis.call('HINCRBY', KEYS[1], 'consumed', actual)
redis.call('DEL', KEYS[2])
return {1, refund}
```

### refund.lua

```lua
-- KEYS[1] = wallet:{user_id}
-- KEYS[2] = reservation:{rid}
-- 返回 {ok, refunded}
--   ok=1 成功;ok=-1 reservation 不存在

local reserved = tonumber(redis.call('GET', KEYS[2]) or '0')
if reserved <= 0 then return {-1, 0} end
redis.call('HINCRBY', KEYS[1], 'reserved', -reserved)
redis.call('HINCRBY', KEYS[1], 'balance', reserved)
redis.call('DEL', KEYS[2])
return {1, reserved}
```

### 异步 ledger 入库

每次 commit/refund 后,业务 Go 代码异步推一条事件到 `cache.Pipeline` 或简单 channel,batch worker 每 100 条或 1s 写入 `ledger_entries` + 同步更新 `wallets` 表(对账)。

### 回收(过期 reservation)

cron job(`internal/billing/reconcile.go`),每 30s 跑一次:

```sql
SELECT id, wallet_id, reserved_quota FROM quota_reservations
WHERE status = 0 AND expires_at < NOW()
LIMIT 100;
```

对每条:
1. 查 Redis 看是否仍有 reservation key(超时已被 Redis 删,但 Wallet hash 的 reserved 仍占着;commit/refund 路径会清,但崩溃可能漏)
2. 调 refund.lua(幂等)
3. 标记 `quota_reservations.status = 3` (expired)
4. 写 audit:`reservation.expired`

## 5.2 滑动窗口限流 Lua

```lua
-- KEYS[1] = ratelimit:{dim}:{key}     sorted set
-- ARGV[1] = window_seconds
-- ARGV[2] = limit
-- ARGV[3] = now_ms
-- ARGV[4] = cost  (默认 1;TPM 可为 token 数)
-- 返回 {ok, count_after, limit, reset_ms}
--   ok=1 通过;ok=0 拒绝

local now = tonumber(ARGV[3])
local window = tonumber(ARGV[1]) * 1000
local limit = tonumber(ARGV[2])
local cost = tonumber(ARGV[4])

redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, now - window)
local count = redis.call('ZCARD', KEYS[1])
local oldest = redis.call('ZRANGE', KEYS[1], 0, 0, 'WITHSCORES')
local reset = now + window
if oldest[2] then reset = tonumber(oldest[2]) + window end

if count + cost > limit then
    return {0, count, limit, reset}
end

for i = 1, cost do
    redis.call('ZADD', KEYS[1], now, now .. ':' .. (i + math.random(0, 999999)))
end
redis.call('PEXPIRE', KEYS[1], window + 1000)
return {1, count + cost, limit, reset}
```

**注意**:成员名加 `math.random` 避免完全同毫秒同 cost 重复。TPM 用 cost = token 数实现"加权计数"。

## 5.3 渠道熔断状态机

状态存 Redis Hash `channel:breaker:{channel_id}`:

```
field            value
state            "closed" | "open" | "half_open"
opened_at        unix_ms     (state = open 时)
consec_fail      int         (滑动统计)
last_probe_at    unix_ms     (state = half_open 时)
```

转移规则(`internal/channel/breaker.go`):

```
CLOSED:
  on success                  → 不变
  on failure(类别 ∈ {5xx, timeout, network})
                              → consec_fail++
                              → consec_fail >= threshold → state=OPEN, opened_at=now

OPEN:
  on Select 调用              → 直接跳过(返回不可用)
  on cron(每 5s 扫一次)      → now - opened_at >= cool_down → state=HALF_OPEN, last_probe_at=now

HALF_OPEN:
  on Select 调用              → 用 SETNX channel:probe_lock:{id} 抢令牌(TTL=请求超时);抢到才放行
  on success                  → state=CLOSED, consec_fail=0
  on failure                  → state=OPEN, opened_at=now
```

默认参数(可在 system_settings 覆盖):
- `channel.breaker.window_seconds = 60`
- `channel.breaker.fail_threshold = 5`
- `channel.breaker.cool_down_seconds = 30`

可计入失败的错误:`apierr.CodeUpstreamError / CodeUpstreamTimeout / CodeUpstreamUnavail`。计入"成功"包括 4xx(客户端错误,不是渠道的锅)。

**广播**:状态变化时 `PUBLISH proapi:channel:breaker {channel_id, state}`,其他实例订阅刷新本地缓存(避免每次 select 都查 Redis)。

## 5.4 渠道选择(优先级 + 加权随机)

```go
func (s *selector) Select(ctx, model string, hint SelectHint) (*Channel, error) {
    candidates := s.cache.ChannelsByModel(model)              // 本地缓存
    candidates = filter(candidates, func(c *Channel) bool {
        return c.Status == 0 &&
               !contains(hint.Excluded, c.ID) &&
               s.breaker.State(c.ID) != "open" &&
               (len(hint.Tags) == 0 || channelTagsMatch(c.Tags, hint.Tags))
    })
    if len(candidates) == 0 {
        return nil, apierr.New(apierr.CodeNoChannel, "no available channel for model "+model)
    }
    top := highestPriority(candidates)
    pool := filterByPriority(candidates, top)
    return weightedRandom(pool), nil
}

func weightedRandom(pool []*Channel) *Channel {
    total := 0
    for _, c := range pool { total += max(c.Weight, 1) }
    r := rand.Intn(total)
    for _, c := range pool {
        w := max(c.Weight, 1)
        if r < w { return c }
        r -= w
    }
    return pool[len(pool)-1]
}
```

## 5.6 流式响应处理与计费(完整流程)

```go
func StreamChat(ctx context.Context, irReq *ir.ChatRequest, w http.ResponseWriter) (e *apierr.Error) {
    // 1. 估算最大消耗
    inputTokens := tokenize(irReq.Messages)    // 本地 tokenizer
    maxOut := irReq.MaxTokens
    if maxOut == 0 { maxOut = pricing.DefaultMaxOut(irReq.Model) }
    estCost := pricing.EstimateMax(irReq.Model, inputTokens, maxOut, irReq.Stream)

    // 2. Reserve(失败 → 402)
    rid, err := biller.Reserve(ctx, userID, estCost)
    if err != nil { return apierrFromErr(err) }
    refunded := false
    defer func() {
        if !refunded && e != nil {
            _ = biller.Refund(context.Background(), rid)  // 用新 ctx,避免主 ctx 已取消
        }
    }()

    // 3. 选渠道 + 调 adapter(retry 包装)
    var ch *channel.Channel
    stream, err := relay.WithRetry(ctx, func(c *channel.Channel) (StreamReader, error) {
        ch = c
        return registry.Get(c.Provider).ChatStream(ctx, mapModel(irReq, c), c.Cred)
    })
    if err != nil { return apierrFromErr(err) }
    defer stream.Close()

    // 4. SSE 转发
    flusher := w.(http.Flusher)
    setSSEHeaders(w)
    var outTokens int
    var lastUsage *ir.Usage
    for {
        chunk, e2 := stream.Next(ctx)
        if e2 == io.EOF { break }
        if e2 != nil { /* 流中断:把已发部分计费,error 事件追加 */ ... }
        outTokens += countDeltaTokens(chunk.Delta)
        if chunk.Usage != nil { lastUsage = chunk.Usage }
        write(w, encodeOpenAI(chunk)); flusher.Flush()
    }
    write(w, "data: [DONE]\n\n"); flusher.Flush()

    // 5. 实际 cost
    actualUsage := ir.Usage{PromptTokens: inputTokens, CompletionTokens: outTokens}
    if lastUsage != nil { actualUsage = *lastUsage }  // 上游给的优先
    result := pricing.Compute(pricing.ComputeInput{Model: irReq.Model, Channel: ch, ...})
    if err := biller.Commit(ctx, rid, result.Quota); err != nil { return apierrFromErr(err) }
    refunded = true  // commit 已自动退差额,这里只是状态标记

    // 6. 异步写日志
    log.Write(ctx, log.Event{...event_type=1 usage..., Ratios=result.Ratios, ...})
    return nil
}
```

# 11 / 共识术语表

| 术语 | 中文 | 定义 |
|---|---|---|
| quota | 额度 | 内部记账单位,整数;`1 美元 = base_quota_per_dollar`(默认 50w) |
| ratio / 倍率 | 倍率 | `quota = tokens × ratio × group_ratio`,float |
| 厘 | 厘 | 金额最小单位,`1 元 = 10000 厘` |
| pa-xxx | API 令牌 | 客户端调代理用的 token,前缀 `pa-` |
| sess_xxx | session id | 用户登录态 token,前缀 `sess_` |
| reservation | 预扣记录 | 一次请求开始时锁定的 quota,UUID 标识 |
| ledger | 流水/账本 | 每条资金变动的不可变记录 |
| breaker | 熔断器 | 渠道连续失败后自动跳过 |
| half_open | 半开 | 熔断恢复期,放一个探针 |
| adapter | 适配器 | 一家上游厂商的实现 |
| channel | 渠道 | 一个 API key + 一组模型映射 + 优先级权重 |
| IR | 中间表示 | adapter 与 protocol 共用的请求/响应数据结构 |
| RPM | 每分请求数 | rate limit 维度 |
| TPM | 每分 token 数 | rate limit 维度,cost = token 数 |
| audit | 审计 | 谁改了什么的记录 |
| seed | 种子 | 首次启动时写入的预置数据(分组、模型字典、设置默认值) |
