```
M2: chat | embed | image | audio | rerank | multimodal
```

## 3.1 新增表：`payment_orders`

M1 总纲已规划此表，M2b 激活：

```sql
-- MySQL
CREATE TABLE IF NOT EXISTS payment_orders (
    id              BIGINT        NOT NULL,
    user_id         BIGINT        NOT NULL,
    provider        VARCHAR(16)   NOT NULL,   -- stripe | alipay | wechat | manual
    out_trade_no    VARCHAR(64)   NOT NULL UNIQUE,
    amount_cent     BIGINT        NOT NULL,   -- 分
    currency        VARCHAR(8)    NOT NULL DEFAULT 'CNY',
    amount_quota    BIGINT        NOT NULL DEFAULT 0,
    status          TINYINT       NOT NULL DEFAULT 0,  -- 0=pending 1=paid 2=failed 3=refunded
    pay_url         VARCHAR(512),
    raw_response    TEXT,
    paid_at         DATETIME(3),
    created_at      DATETIME(3)   NOT NULL,
    updated_at      DATETIME(3)   NOT NULL,
    PRIMARY KEY (id),
    KEY idx_payment_user (user_id, status),
    KEY idx_payment_out_trade (out_trade_no),
    KEY idx_payment_status (status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- PostgreSQL
CREATE TABLE IF NOT EXISTS payment_orders (
    id            BIGINT        PRIMARY KEY,
    user_id       BIGINT        NOT NULL,
    provider      VARCHAR(16)   NOT NULL,
    out_trade_no  VARCHAR(64)   NOT NULL UNIQUE,
    amount_cent   BIGINT        NOT NULL,
    currency      VARCHAR(8)    NOT NULL DEFAULT 'CNY',
    amount_quota  BIGINT        NOT NULL DEFAULT 0,
    status        SMALLINT      NOT NULL DEFAULT 0,
    pay_url       VARCHAR(512),
    raw_response  TEXT,
    paid_at       TIMESTAMPTZ,
    created_at    TIMESTAMPTZ   NOT NULL,
    updated_at    TIMESTAMPTZ   NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_payment_user ON payment_orders (user_id, status);
CREATE INDEX IF NOT EXISTS idx_payment_out_trade ON payment_orders (out_trade_no);
CREATE INDEX IF NOT EXISTS idx_payment_status ON payment_orders (status, created_at);
```

# 4 / 三协议互转引擎设计

## 4.1 架构

M1 已有的 `relay` 包处理 OpenAI 入口。M2a 在此基础上：

```
                 ┌────────────── relay 入口路由 ──────────────┐
                 │                                            │
   /v1/*         │  /v1/messages   /v1/messages/count_tokens  │  /v1beta/models/*
(M1 已有)        │  (Anthropic 入口)                           │  (Gemini 入口)
                 │        │                                   │        │
                 │  anthropic.Decode()              gemini.Decode()   │
                 │        │                                   │        │
                 └────────┴──────────► IR ◄───────────────────┘
                                        │
                               relay(渠道/限流/计费 — 已有)
                                        │
                              任意上游 adapter
                                        │
                                       IR → 响应
                                        │
                          ┌─────────────┴────────────┐
                    openai.Encode()       anthropic.Encode() / gemini.Encode()
                   (依入口协议选择编码器)
```

**关键规则**：
- 入口协议与上游协议**完全解耦**：Anthropic 入口 → 可路由到 OpenAI 上游
- 响应编码器在 relay 层注入，与 handler 绑定

## 4.2 新增文件

```
internal/protocol/
├── openai/          (M1 已有)
├── anthropic/       (M2a 新增：入口)
│   ├── decode.go    Anthropic Messages API → ir.ChatRequest
│   ├── encode.go    ir.ChatResponse → Anthropic Messages API response
│   └── stream.go    ir.ChatChunk → Anthropic SSE event stream
└── gemini/          (M2a 新增：入口)
    ├── decode.go    Gemini generateContent → ir.ChatRequest
    ├── encode.go    ir.ChatResponse → Gemini response
    └── stream.go    ir.ChatChunk → Gemini SSE stream
```

> **注意区分**：
> - `internal/adapter/anthropic/` = 后端适配器（把 IR 发给 Claude API）→ M1 已有
> - `internal/protocol/anthropic/` = 入口解码器（把 Anthropic 客户端请求转成 IR）→ M2a 新增

## 4.3 Anthropic Messages API 入口规范

### 请求 decode 要点

```
Anthropic 请求                          → IR
─────────────────────────────────────────────
messages[].role = "user"/"assistant"   → Message.Role
messages[].content = string            → []ContentPart{Type:"text"}
messages[].content = []ContentBlock   → 按 type 映射
  {type:"text"}                        → ContentPart{Type:"text"}
  {type:"image", source:{...}}         → ContentPart{Type:"image_url"}
  {type:"tool_use"}                    → ToolCall
  {type:"tool_result"}                 → Message(role="tool")
system = string                        → messages 头部插 {role:"system"}
tools[].input_schema                   → Tool.Function.Parameters
tool_choice.type                       → ToolChoice
max_tokens                             → MaxTokens
temperature / top_p / top_k            → 同名字段
stream                                 → Stream
```

### 响应 encode 要点

```
IR                                      → Anthropic 响应
─────────────────────────────────────────────────────
ChatResponse.Choices[0].Message        → content[{type:"text",text:"..."}]
ToolCalls                              → content[{type:"tool_use",...}]
Usage.PromptTokens                     → usage.input_tokens
Usage.CompletionTokens                 → usage.output_tokens
```

### 流式 encode

Anthropic 流格式（对比 OpenAI）：
```
event: message_start\ndata: {...}\n\n
event: content_block_start\ndata: {...}\n\n
event: content_block_delta\ndata: {delta:{type:"text_delta",text:"..."}}\n\n
event: message_delta\ndata: {usage:{output_tokens:42}}\n\n
event: message_stop\ndata: {}\n\n
```

## 4.4 Gemini API 入口规范

### 请求 decode 要点

```
Gemini 请求                              → IR
────────────────────────────────────────────
contents[].role = "user"/"model"        → Message.Role("user"/"assistant")
contents[].parts[]{text}                → ContentPart{Type:"text"}
contents[].parts[]{inline_data}         → ContentPart{Type:"image_url"}
contents[].parts[]{function_call}       → ToolCall
systemInstruction.parts[0].text         → messages[0]{role:"system"}
tools[].functionDeclarations[]          → Tool
generationConfig.maxOutputTokens        → MaxTokens
generationConfig.temperature            → Temperature
generationConfig.topP                   → TopP
```

### 响应 encode 要点

```
candidates[0].content.parts[0].text    ← IR.Choices[0].Message.Content
candidates[0].content.parts[0].functionCall ← ToolCalls
usageMetadata.promptTokenCount         ← Usage.PromptTokens
usageMetadata.candidatesTokenCount     ← Usage.CompletionTokens
```

# 5 / 新增适配器策略

## 5.1 OpenAI 兼容适配器(复用基础)

以下 5 家直接继承 openai adapter，只需配置 base_url 和 supported_models：

| Provider | Base URL | 特殊说明 |
|---|---|---|
| groq | `https://api.groq.com/openai/v1` | 无 |
| mistral | `https://api.mistral.ai/v1` | 无 |
| yi | `https://api.lingyiwanwu.com/v1` | 无 |
| openrouter | `https://openrouter.ai/api/v1` | 需加 `HTTP-Referer` 和 `X-Title` 请求头 |
| huggingface | `https://api-inference.huggingface.co/v1` | Bearer token 认证，需要 model endpoint |

**实现方式**：

```go
// internal/adapter/groq/adapter.go
type Adapter struct {
    *openai.Adapter  // 直接嵌入 openai
}

func New() adapter.Adapter {
    return &Adapter{
        Adapter: openai.NewWithBase("https://api.groq.com/openai/v1"),
    }
}

func (a *Adapter) Name() string { return "groq" }
func (a *Adapter) SupportedModels() []string {
    return []string{"llama-3.3-70b-versatile", "llama-3.1-70b-versatile", "mixtral-8x7b-32768", ...}
}
```

## 5.2 OpenAI 兼容但有差异

| Provider | 差异点 |
|---|---|
| minimax | 需要 `GroupID` 参数(从 Credential.Extra 读)；响应格式微差 |
| cohere | Chat API 格式不同；支持 Rerank(M2a-03 多模态)；Command/Embed 系列 |
| tencent | 混元 API 有腾讯自定义鉴权(HMAC-SHA256)；响应格式独立 |

**实现方式**：各自独立实现，不继承 openai，但可复用 SSE 解析逻辑。

## 5.3 排除

**讯飞星火**：使用 WebSocket 协议，与现有 HTTP streaming 架构不兼容，工程量大且市场需求有限，推迟到 M3。

Cohere 是 M2a 唯一同时提供 Chat + Rerank 的厂商：


# 6 / 多模态 IR 扩展

## 6.1 新增 IR 类型

```go
package ir

// ===== 图像生成(DALL-E) =====
type ImageRequest struct {
    Model   string
    Prompt  string
    N       int    // 1-10
    Size    string // "256x256" | "512x512" | "1024x1024" | "1792x1024" | "1024x1792"
    Quality string // "standard" | "hd"
    Style   string // "vivid" | "natural"
    Format  string // "url" | "b64_json"
    User    string
    ExtraParams map[string]any
}

type ImageResponse struct {
    Created int64
    Data    []ImageData
}

type ImageData struct {
    URL           string
    B64JSON       string
    RevisedPrompt string
}

// ===== TTS =====
type SpeechRequest struct {
    Model   string
    Input   string  // 最长 4096 字符
    Voice   string  // alloy | echo | fable | onyx | nova | shimmer
    Format  string  // mp3 | opus | aac | flac | wav | pcm
    Speed   float64 // 0.25-4.0，默认 1.0
    ExtraParams map[string]any
}

type SpeechResponse struct {
    AudioData   []byte
    Format      string
    ContentType string
}

// ===== STT =====
type TranscribeRequest struct {
    Model       string
    AudioData   []byte
    Filename    string
    Language    string
    Prompt      string
    Format      string // json | text | srt | verbose_json | vtt
    Temperature float64
    ExtraParams map[string]any
}

type TranscribeResponse struct {
    Text        string
    Language    string
    Duration    float64
    Segments    []TranscribeSegment // verbose_json 时有
    Words       []TranscribeWord
}

type TranscribeSegment struct {
    ID    int; Start float64; End float64; Text string
}
type TranscribeWord struct {
    Word  string; Start float64; End float64
}

// ===== Rerank =====
type RerankRequest struct {
    Model       string
    Query       string
    Documents   []RerankDocument  // string 或 {text: string}
    TopN        int
    ReturnDocuments bool
    ExtraParams map[string]any
}

type RerankDocument struct {
    Text string
}

type RerankResponse struct {
    ID      string
    Results []RerankResult
    Usage   RerankUsage
}

type RerankResult struct {
    Index          int
    RelevanceScore float64
    Document       *RerankDocument  // ReturnDocuments=true 时有
}

type RerankUsage struct {
    TotalTokens int
}
```

# 7 / 支付统一抽象

## 7.1 Provider 接口

```go
// internal/payment/provider/provider.go
package provider

type Provider interface {
    Name() string   // "stripe" | "alipay" | "wechat"

    // CreateOrder 创建支付订单，返回前台跳转 URL 或二维码数据
    CreateOrder(ctx context.Context, in CreateInput) (*OrderResult, error)

    // HandleWebhook 解析并验证支付平台回调，返回标准化的支付事件
    HandleWebhook(ctx context.Context, body []byte, headers map[string]string) (*PayEvent, error)

    // QueryOrder 主动查询订单状态（用于补单/对账）
    QueryOrder(ctx context.Context, outTradeNo string) (*OrderStatus, error)
}

type CreateInput struct {
    OutTradeNo  string         // 系统唯一流水号(Snowflake ID hex)
    AmountCent  int64          // 金额(分)
    Currency    string         // CNY | USD
    Description string
    NotifyURL   string         // /api/webhook/{provider}
    ReturnURL   string         // 前台回跳
    Extra       map[string]any // provider 特有参数
}

type OrderResult struct {
    PayURL     string // Stripe: checkout session URL; 支付宝: 跳转 URL
    QRCodeURL  string // 微信: 二维码 URL
    FormHTML   string // 支付宝: H5 表单 HTML（选用）
}

type PayEvent struct {
    OutTradeNo  string
    Status      string  // "paid" | "refunded" | "failed"
    AmountCent  int64
    PaidAt      time.Time
    RawPayload  string  // 原始 webhook 数据，存入 payment_orders.raw_response
}

type OrderStatus struct {
    OutTradeNo  string
    Status      string
    AmountCent  int64
    PaidAt      *time.Time
}
```

## 7.2 充值流程

```
1. 用户选择支付方式 + 金额 → POST /api/user/payment/orders
2. PaymentService.CreateOrder:
   a. 生成 out_trade_no(Snowflake hex)
   b. 计算 amount_quota = amount_cent * (base_quota_per_dollar / 100 / exchange_rate)
   c. 写 payment_orders(status=pending)
   d. 调 provider.CreateOrder → 返回 pay_url/qr_code
3. 前台跳转到支付页 / 扫码
4. 支付成功 → provider 回调 /api/webhook/{provider}
5. WebhookHandler:
   a. 验签(Stripe/支付宝/微信各自方式)
   b. provider.HandleWebhook → PayEvent
   c. 幂等更新 payment_orders(status=paid, paid_at=...)
   d. wallet.Credit(userID, quota, "payment", orderID, "在线充值")
   e. 触发邀请返佣(若 invited_by 不为空)
6. 用户前台看到余额增加
```

## 7.3 三种支付实现特点

### Stripe

```go

// 依赖: github.com/stripe/stripe-go/v81
// CreateOrder → stripe.CheckoutSession.New(mode=payment)
// HandleWebhook → stripe.Event.ConstructEvent → checkout.session.completed
// QueryOrder → stripe.CheckoutSession.Get
```

```go

// 依赖: github.com/smartwalle/alipay/v3
// CreateOrder → alipay.TradePagePay(电脑网站)
```


# 8 / 邀请返佣机制

## 8.1 设计原则

- 邀请人获得被邀请人**每次充值金额的固定比例 quota**（不是现金）
- 比例由 `invite.rebate_ratio`(system_settings)控制，后台管理员可随时调整
- 纯 quota 返还，走 `wallet.Credit(inviterID, rebate, "invite_commission", orderID, "...")`
- 无提现功能

## 8.2 数据流

```go
// 在 PaymentService.onPaid(orderID) 中
func (s *Service) onPaid(ctx context.Context, order *model.PaymentOrder) error {
    // 1. 给买家加 quota
    if err := s.wallet.Credit(ctx, order.UserID, order.AmountQuota, "payment", order.ID, "在线充值"); err != nil {
        return err
    }

    // 2. 查邀请关系
    user, _ := s.users.Get(ctx, order.UserID)
    if user.InvitedBy == nil {
        return nil  // 无邀请人，结束
    }

    // 3. 计算返佣
    ratio := s.setting.GetFloat(ctx, "invite.rebate_ratio", 0.1)
    rebateQuota := int64(float64(order.AmountQuota) * ratio)
    if rebateQuota <= 0 {
        return nil
    }

    // 4. 给邀请人加 quota
    if err := s.wallet.Credit(ctx, *user.InvitedBy, rebateQuota, "invite_commission", order.ID, "邀请返佣"); err != nil {
        s.log.Warn("invite rebate failed", zap.Error(err))
        // 不影响主流程
    }

    // 5. 写 invite_records
    _ = s.invites.Create(ctx, &model.InviteRecord{
        InviterID:   *user.InvitedBy,
        InviteeID:   order.UserID,
        TriggerType: "every_recharge",
        RebateQuota: rebateQuota,
        RefOrderID:  &order.ID,
    })
    return nil
}
```

## 8.3 邀请码规则

- 格式：`pa-invite-<8位随机>` 或直接用用户 ID 的 Base62 编码（简洁）
- 推荐：用户 ID 的 Base62(8位)，全局唯一，不需要额外表
- 注册时 URL 参数 `?ref=<code>` → 解码出 inviter_id → 写入 `users.invited_by`

# 10 / 限流补全维度

M1 已有：user / token / IP / model 四维度。M2a 补全三个维度：

```
ratelimit:group:{group_id}:rpm     分组级（VIP 高配）
ratelimit:group:{group_id}:tpm

ratelimit:channel:{channel_id}:rpm 渠道级（保护上游）
ratelimit:channel:{channel_id}:tpm

ratelimit:global:rpm               全局（总闸）
ratelimit:global:tpm
```

**维度链执行顺序**（M1 有 4 个，M2a 扩到 7 个）：

```
global → group → user → token → IP → model → channel
```

全局 / 分组 / 渠道的阈值全部从 `system_settings` 读取：
- `ratelimit.global_rpm` / `ratelimit.global_tpm`
- 分组级：从 `user_groups.ratio` 推算（ratio×user_default）
- 渠道级：`channel.max_rpm` / `channel.max_tpm`（存在 `channels.extra` JSON 字段）
