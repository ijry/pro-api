# 里程碑 M1-03 API 令牌

## 1. 目标与范围

### 1.1 一句话

**实现 `pa-xxx` API 调用令牌** — 生成 / 哈希存储 / 缓存校验 / IP & 模型白名单 / RPM·TPM 限制位 / 增量统计(`last_used_at` / `quota_used`),并对内通过 `token.Store` 接口、对外通过 HTTP handler(用户侧 + 管理员侧)统一暴露。

令牌是代理 API(`/v1/*`)鉴权的唯一入口;本 spec **不**承担"按令牌扣额度"的钱包计费(那是 M1-06),也**不**实现"按令牌限流"的实际 Lua 调用(那是 M1-07),但本 spec 为这两个模块准备契约:
- M1-06 在请求 commit 时调 `IncrementUsage(tokenID, delta)`
- M1-07 在 middleware 链中读 `Token.RPMLimit / TPMLimit` 作为维度参数

### 1.2 范围

属于本 spec 的(11 件事):

1. `api_tokens` 表 migration(MySQL + PG):`000005_create_api_tokens.{up,down}.sql`
2. `internal/token/` GORM 仓储 + `Store` 接口实现([总纲 §4.9](./2026-05-21-里程碑1-总体设计纲要.md#49-tokenstore))
3. 明文 key 生成 + sha256 入库;`Regenerate` / `Revoke` 的原子语义
4. Redis 缓存(`token:{key_hash}` TTL 5 分钟)+ 失效广播
5. `last_used_at` 异步聚合 batch(内存 map → 30s flush → UPSERT → Pub/Sub 失效)
6. `quota_used` 异步累加 batch(`IncrementUsage(tokenID, delta)`,M1-06 commit 调用)
7. `TokenAuth` 中间件:`Authorization: Bearer pa-xxx` → 注入 ctx{user_id, token_id, group_id}
8. IP 白名单校验(CIDR,`net/netip`),空数组 = 不限
9. 模型白名单 helper:`AssertModelAllowed(t, model) error`,handler 选 model 后调用;支持末尾 `*` 通配
10. 用户侧 + 管理员侧 HTTP handler(`/api/user/tokens/*` 与 `/api/admin/tokens/*`)
11. 代理入口 `GET /v1/models` — 返回当前令牌可调用的模型列表(channel + 模型字典聚合 + 令牌白名单过滤)

### 1.3 排除项(明确边界)

- ❌ **计费扣减** — 见 M1-06。本 spec 只暴露 `IncrementUsage` 接口
- ❌ **令牌限流的 Redis key 与 Lua** — 见 M1-07。本 spec 只在 `Token` 上挂 `RPMLimit / TPMLimit` 字段供 middleware 使用
- ❌ **令牌前端 UI** — 见 M1-09(管理员)/ M1-10(用户)
- ❌ **复杂 glob 模式**(`gpt-?-*` / `**/v2`)— M1 仅支持末尾 `*` 一种通配
- ❌ **令牌"自动过期"状态机** — 表上有 `status=2` 占位,但**周期 job 同步**放 M2;M1 读取时实时判断 `expires_at < now()` 决定是否拒绝(`CodeTokenExpired`)

## 3. 接口契约

### 3.1 token.Store

总纲 [§4.9](./2026-05-21-里程碑1-总体设计纲要.md#49-tokenstore) 已定签名。本 spec 完整化:

```go
// internal/token/store.go
package token

import (
    "context"
    "time"
)

type Store interface {
    // Authenticate 用明文 key 校验。
    //   - key 形式必须是 "pa-xxx..."
    //   - 错误:apierr.CodeInvalidToken(格式错/不存在/已禁用) / CodeTokenExpired
    //   - 命中后 schedule last_used_at flush(异步)
    Authenticate(ctx context.Context, plaintextKey string) (*View, error)

    // Create 创建令牌。
    //   - 内部生成明文 + sha256 + prefix,Token.UserID 必填
    //   - 返回明文 key(只此一次,后续永远不可读)
    Create(ctx context.Context, in CreateInput) (plaintextKey string, view *View, err error)

    // List 列我的(用户侧)或全部(管理员侧,通过 filter.UserID==0 视为全部)。
    List(ctx context.Context, filter ListFilter) ([]*View, int64, error)

    // Get 按 id 取详情。不存在返回 apierr.CodeNotFound。
    Get(ctx context.Context, id int64) (*View, error)

    // Update 全字段可选更新。
    //   - 任一字段 nil 表示不更新
    //   - 返回更新后的 View
    Update(ctx context.Context, id int64, patch UpdatePatch) (*View, error)

    // Revoke 软禁用(status=1)。不删表,key_hash 仍占用以避免重用。
    Revoke(ctx context.Context, id int64) error

    // Regenerate 原 key_hash 失效,生成新明文。
    //   - 原 Token 其他字段保留
    //   - 立即从 Redis 删 token:{old_hash}
    Regenerate(ctx context.Context, id int64) (plaintextKey string, view *View, err error)

    // IncrementUsage 给 M1-06 调:本次消费的 quota 累加到 quota_used。
    //   - 内部 batch,30s flush 一次;flush 时 SQL: UPDATE … quota_used = quota_used + ?
    //   - 同步即返,不阻塞调用方
    //   - 优雅关停时 final flush
    IncrementUsage(tokenID int64, delta int64)

    // TouchLastUsed 给 TokenAuth 中间件调:仅更新 last_used_at = max(old, now)。
    //   - 内部 batch + Pub/Sub 失效本地 cache 的 last_used 字段
    TouchLastUsed(tokenID int64, t time.Time)

    // Close 关停 batch flusher + Pub/Sub 订阅。final flush 同步完成。
    Close() error
}

type CreateInput struct {
    UserID        int64
    Name          string
    QuotaLimit    *int64
    AllowedModels []string
    AllowedIPs    []string  // 必须是有效 CIDR(IPv4/IPv6),解析失败返回 CodeInvalidParam
    RPMLimit      int
    TPMLimit      int
    ExpiresAt     *time.Time
}

type UpdatePatch struct {
    Name          *string
    QuotaLimit    *int64    // 想清零传 *int64(0);想置为无限传 nil(并设 ClearQuotaLimit=true)
    ClearQuotaLimit bool
    AllowedModels *[]string
    AllowedIPs    *[]string
    RPMLimit      *int
    TPMLimit      *int
    ExpiresAt     *time.Time
    ClearExpiresAt bool
    Status        *int8     // 仅 0/1 合法;2 由 Authenticate 实时判定,不可手动设
}

type ListFilter struct {
    UserID  int64    // 0 = 不限(管理员)
    Status  *int8    // nil = 不限
    Keyword string   // 名称模糊匹配
    Page    int      // 1-based
    Size    int      // 默认 20,最大 100
}
```

### 3.3 Allow helper

```go
// internal/token/allow.go
package token

import (
    "net/netip"
    "strings"

    "github.com/ijry/pro-api/pkg/apierr"
)

// AssertIPAllowed 校验 ip 是否在 token.AllowedIPs(CIDR 列表)中。
//   - 空数组 = 不限,直接通过
//   - ip 形式可为 "1.2.3.4" / "1.2.3.4:1234" / "[::1]:8080" / "::1";解析失败按"不通过"
//   - 任一 CIDR 解析失败,跳过这条规则(配置错误不应整体放行)
func AssertIPAllowed(t *View, ip string) error {
    if len(t.AllowedIPs) == 0 {
        return nil
    }
    addr, ok := parseAddr(ip)
    if !ok {
        return apierr.New(apierr.CodeIPNotAllowed, "ip address invalid: "+ip)
    }
    for _, cidr := range t.AllowedIPs {
        p, err := netip.ParsePrefix(cidr)
        if err != nil {
            // 单条 IPv4/IPv6 单地址兼容
            if a, err2 := netip.ParseAddr(cidr); err2 == nil {
                if a == addr { return nil }
            }
            continue
        }
        if p.Contains(addr) { return nil }
    }
    return apierr.New(apierr.CodeIPNotAllowed, "ip not in allowlist")
}

func parseAddr(s string) (netip.Addr, bool) {
    // 处理 "1.2.3.4:1234" / "[::1]:8080"
    if a, err := netip.ParseAddr(s); err == nil { return a, true }
    if ap, err := netip.ParseAddrPort(s); err == nil { return ap.Addr(), true }
    return netip.Addr{}, false
}

// AssertModelAllowed 校验 model 是否在 token.AllowedModels 中。
//   - 空数组 = 不限,直接通过
//   - 精确匹配优先于通配
//   - 通配仅支持末尾 "*" (例:"gpt-4*" 匹配 "gpt-4o" / "gpt-4-turbo")
//   - 大小写敏感(总纲明确 OpenAI 模型名规范)
func AssertModelAllowed(t *View, model string) error {
    if len(t.AllowedModels) == 0 {
        return nil
    }
    // 先精确
    for _, p := range t.AllowedModels {
        if !strings.HasSuffix(p, "*") && p == model { return nil }
    }
    // 后通配
    for _, p := range t.AllowedModels {
        if strings.HasSuffix(p, "*") {
            prefix := strings.TrimSuffix(p, "*")
            if strings.HasPrefix(model, prefix) { return nil }
        }
    }
    return apierr.New(apierr.CodeModelNotAllowed, "model "+model+" not allowed for this token")
}
```

### 3.5 TokenAuth 中间件

```go
// internal/token/middleware.go
package token

import (
    "net/http"
    "strings"

    "github.com/gin-gonic/gin"
    "github.com/ijry/pro-api/internal/server/middleware"
    "github.com/ijry/pro-api/pkg/apierr"
)

const (
    // CtxKey 由 handler 取出。
    CtxKeyToken   = "proapi:token"   // *View
    CtxKeyUserID  = "proapi:user_id"  // int64
    CtxKeyGroupID = "proapi:group_id" // int64(由 user 模块在 user lookup 时填)
)

// TokenAuth 接受 Bearer pa-xxx,解析后注入 ctx。
//   - 失败 → SetErr(CodeInvalidToken / CodeTokenExpired) → Abort
//   - 成功 → c.Set(CtxKeyToken, view); c.Set(CtxKeyUserID, view.UserID); c.Next()
//   - IP 校验在这里立即做(读 RealIP);AllowedModels 不在这里做(等 handler 选 model 后)
func TokenAuth(s Store, userLookup UserLookup) gin.HandlerFunc {
    return func(c *gin.Context) {
        auth := c.GetHeader("Authorization")
        key, ok := extractBearer(auth)
        if !ok {
            middleware.SetErr(c, apierr.New(apierr.CodeInvalidToken, "missing bearer token"))
            return
        }
        view, err := s.Authenticate(c.Request.Context(), key)
        if err != nil {
            middleware.SetErr(c, apierr.Wrap(err))
            return
        }
        ip := realIP(c.Request)
        if err := AssertIPAllowed(view, ip); err != nil {
            middleware.SetErr(c, apierr.Wrap(err))
            return
        }
        // 用户级 group 信息(M1-02 暴露 UserLookup)
        if userLookup != nil {
            if gid, ok := userLookup(c.Request.Context(), view.UserID); ok {
                c.Set(CtxKeyGroupID, gid)
            }
        }
        c.Set(CtxKeyToken, view)
        c.Set(CtxKeyUserID, view.UserID)
        c.Next()
    }
}

// UserLookup 由 M1-02 提供;失败返回 ok=false 不阻断鉴权(group 不强依赖)。
type UserLookup func(ctx context.Context, userID int64) (groupID int64, ok bool)

func extractBearer(h string) (string, bool) {
    const prefix = "Bearer "
    if len(h) < len(prefix) || !strings.EqualFold(h[:len(prefix)], prefix) {
        return "", false
    }
    s := strings.TrimSpace(h[len(prefix):])
    if !strings.HasPrefix(s, "pa-") { return "", false }
    return s, true
}

// realIP 从 Header / RemoteAddr 取真实 IP。
//   - 优先 X-Forwarded-For 第一段
//   - 否则 X-Real-IP
//   - 否则 RemoteAddr
//   - 反向代理是否可信由 setting "server.trust_proxy" 控制(默认 true 在容器环境)
//   - 实际实现读 request.RemoteAddr 兜底;校验时去端口
func realIP(r *http.Request) string {
    if xff := r.Header.Get("X-Forwarded-For"); xff != "" {
        return strings.TrimSpace(strings.SplitN(xff, ",", 2)[0])
    }
    if xr := r.Header.Get("X-Real-IP"); xr != "" { return xr }
    return r.RemoteAddr
}
```

## 4. 关键算法

### 4.1 明文 key 生成

```go
// internal/token/keygen.go
package token

import (
    "crypto/rand"
    "crypto/sha256"
    "encoding/base64"
    "encoding/hex"
    "fmt"
)

const (
    keyByteLen   = 36   // 36 字节 random → base64url 48 char
    keyPrefixLit = "pa-"
)

// newPlaintext 生成 "pa-<48 字符 base64url>"
func newPlaintext() (plaintext string, hash string, err error) {
    buf := make([]byte, keyByteLen)
    if _, err := rand.Read(buf); err != nil {
        return "", "", fmt.Errorf("rand: %w", err)
    }
    body := base64.RawURLEncoding.EncodeToString(buf)
    plaintext = keyPrefixLit + body
    h := sha256.Sum256([]byte(plaintext))
    hash = hex.EncodeToString(h[:])  // 小写 hex 64 字符
    return
}

// prefixForDisplay 把明文转成展示形态 "pa-xxxxxxxx****xxxx"。
//   - 前 showLen 位明文(含 "pa-" 前缀本身)
//   - 中间 4 位 "*"
//   - 末 4 位明文
//   - 不足时全展示(理论上不会发生)
func prefixForDisplay(plaintext string, showLen int) string {
    if showLen <= 0 { showLen = 8 }
    if len(plaintext) <= showLen+4 { return plaintext }
    head := plaintext[:showLen]
    tail := plaintext[len(plaintext)-4:]
    return head + "****" + tail
}
```

> **决策**:`base64.RawURLEncoding`(无 `=` 填充)产 48 字符,URL safe。`hex.EncodeToString` 小写,长度 64 — 与 `VARCHAR(64)` 列长精确匹配。

### 4.2 Authenticate 流程

```
Authenticate(ctx, key):
  1. 校验前缀 "pa-" + 长度合规;否 → CodeInvalidToken
  2. h = sha256_hex(key)
  3. 查 Redis cache "token:{h}":
     - hit:JSON 反序列化 View → 校验 status & expires_at(后续 §4.4)
     - miss:走 DB
  4. DB SELECT WHERE key_hash = h AND deleted_at IS NULL
     - 未找到 → 缓存 negative token "token:{h}" = "0" TTL 30s,返 CodeInvalidToken
     - 找到 → 写 cache(JSON,TTL 5min)
  5. 状态校验:
     - status == StatusDisabled → CodeInvalidToken
     - expires_at != NULL && expires_at < now() → CodeTokenExpired
  6. 异步:s.TouchLastUsed(token.ID, now)
  7. 返回 View
```

**负缓存**:无效 key 短 TTL(30s),防止 token 字典爆破打爆 DB;参数可调(`setting "token.negative_cache_ttl_seconds"`,默认 30)。

### 4.3 缓存 key 与失效广播

```
Redis key:
  token:{key_hash}         JSON(View 的快照)   TTL 5min
  token:lastused:{token_id} unix_ms(冗余,异步聚合的写穿)  TTL 5min
  
Pub/Sub channel:
  proapi:token:invalidate  payload = "{key_hash}"  // 显式失效(Revoke / Regenerate / Update 调用)
  proapi:token:lastused    payload = "{token_id}:{unix_ms}"  // last_used 异步同步
```

订阅者(每个实例的 token.store 内部):
- `invalidate`:Redis DEL `token:{hash}` + 本地 lru cache 删
- `lastused`:更新本地 View 的 LastUsedAt 字段(若有缓存)

> 实际上**本 spec 不引入本地 LRU**(让 Redis 5min TTL 兜底);只在 `Authenticate` 路径有"本地 View 临时变量",上述 lastused 失效只影响 Redis 的 token JSON 中嵌入的 last_used_at 字段 — 即下次 cache miss 重读时见到。

### 4.4 last_used_at 异步聚合

```go
// internal/token/flusher.go
package token

import (
    "context"
    "sync"
    "time"
)

type flusher struct {
    mu         sync.Mutex
    lastUsed   map[int64]time.Time   // tokenID → max time
    quotaDelta map[int64]int64       // tokenID → delta
    
    interval time.Duration  // 默认 30s
    stop     chan struct{}
    done     chan struct{}
    
    db    *gorm.DB
    log   *zap.Logger
    clock clock.Clock
    pub   *redis.Client
}

func (f *flusher) TouchLastUsed(tokenID int64, t time.Time) {
    f.mu.Lock()
    if cur := f.lastUsed[tokenID]; t.After(cur) {
        f.lastUsed[tokenID] = t
    }
    f.mu.Unlock()
}

func (f *flusher) IncrementUsage(tokenID int64, delta int64) {
    if delta == 0 { return }
    f.mu.Lock()
    f.quotaDelta[tokenID] += delta
    f.mu.Unlock()
}

// run 在 New 启动一个 goroutine 循环。
func (f *flusher) run() {
    ticker := f.clock.NewTicker(f.interval)
    defer ticker.Stop()
    for {
        select {
        case <-ticker.C():
            f.flushOnce(context.Background())
        case <-f.stop:
            f.flushOnce(context.Background())  // final flush
            close(f.done)
            return
        }
    }
}

func (f *flusher) flushOnce(ctx context.Context) {
    f.mu.Lock()
    lu := f.lastUsed; f.lastUsed = make(map[int64]time.Time, 64)
    qu := f.quotaDelta; f.quotaDelta = make(map[int64]int64, 64)
    f.mu.Unlock()
    
    // 1. last_used_at:批量 UPDATE … CASE WHEN id = ? THEN ? END
    if len(lu) > 0 {
        if err := f.flushLastUsed(ctx, lu); err != nil {
            f.log.Warn("token: flush last_used failed", zap.Error(err))
        } else {
            // Pub/Sub 通知其他实例失效
            for id, t := range lu {
                f.pub.Publish(ctx, "proapi:token:lastused",
                    fmt.Sprintf("%d:%d", id, t.UnixMilli()))
            }
        }
    }
    
    // 2. quota_used:批量 UPDATE … quota_used = quota_used + delta
    if len(qu) > 0 {
        if err := f.flushQuota(ctx, qu); err != nil {
            f.log.Warn("token: flush quota_used failed", zap.Error(err))
        }
    }
}
```

**批量 SQL 实现**(MySQL + PG):

```go
// flushLastUsed:用 CASE WHEN 单条 UPDATE 完成批量(数量 < 200 时高效)
func (f *flusher) flushLastUsed(ctx context.Context, m map[int64]time.Time) error {
    if len(m) == 0 { return nil }
    ids := make([]int64, 0, len(m))
    case_ := strings.Builder{}
    case_.WriteString("CASE id ")
    for id, t := range m {
        ids = append(ids, id)
        fmt.Fprintf(&case_, "WHEN %d THEN ? ", id)
    }
    case_.WriteString("END")
    args := make([]any, 0, len(m))
    for _, id := range ids { args = append(args, m[id]) }
    return f.db.WithContext(ctx).Exec(
        "UPDATE api_tokens SET last_used_at = "+case_.String()+" WHERE id IN ?",
        append(args, ids)...,
    ).Error
}

// flushQuota:同样 CASE WHEN
func (f *flusher) flushQuota(ctx context.Context, m map[int64]int64) error {
    if len(m) == 0 { return nil }
    ids := make([]int64, 0, len(m))
    case_ := strings.Builder{}
    case_.WriteString("CASE id ")
    for id, delta := range m {
        ids = append(ids, id)
        fmt.Fprintf(&case_, "WHEN %d THEN quota_used + %d ", id, delta)
    }
    case_.WriteString("END")
    return f.db.WithContext(ctx).Exec(
        "UPDATE api_tokens SET quota_used = "+case_.String()+" WHERE id IN ?",
        ids,
    ).Error
}
```

> 注:CASE WHEN 写法对 200 个 id 批量 UPDATE 一次 RTT;PG / MySQL 都支持。若批次超过 200 自动分片(`for chunk := range chunks(ids, 200) { ... }`)。

**优雅关停**:`Close()` 关 `stop` channel 后等 `done` 关闭 — 这保证 final flush 同步完成,主进程才退出。

### 4.5 last_used_at 单调性

并发场景:多个 worker 都调 `TouchLastUsed(id, t)`,内存 map 只保留 max。flush 时若 DB 已有更新值(其他实例),写入可能"回退"。

**缓解**:flush SQL 改为 `last_used_at = GREATEST(IFNULL(last_used_at, '1970-01-01'), ?)` — MySQL 支持;PG 同名函数 `GREATEST` 也存在。本 spec 采用此写法,代价是 CASE WHEN 内嵌 GREATEST:

```sql
UPDATE api_tokens SET last_used_at = GREATEST(IFNULL(last_used_at, '1970-01-01'), CASE id WHEN 1 THEN ? ... END) WHERE id IN (...);
```

### 4.6 Regenerate 原子性

```
Regenerate(id):
  1. 取旧 token row(锁定 user_id / 其他字段)
  2. 生成新 plaintext + hash + prefix
  3. UPDATE api_tokens SET key_hash = ?, key_prefix = ?, updated_at = NOW() WHERE id = ?
  4. Redis DEL token:{old_hash} + PUBLISH invalidate
  5. audit.Log(action="token.regenerate", target=id, before={hash:old_hash[:8]}, after={hash:new_hash[:8]})
  6. 返回新 plaintext
```

不显式开事务 — 单 UPDATE 即原子;DEL 与 PUBLISH 失败仅影响"旧 hash 在 cache 过 5min 才失效"(短窗口可接受)。

### 4.7 Revoke 与软禁用

```
Revoke(id):
  1. UPDATE api_tokens SET status = 1, updated_at = NOW() WHERE id = ?
  2. SELECT key_hash FROM api_tokens WHERE id = ?  -- 或在 UPDATE 时 returning(PG)/ 先查再更
  3. Redis DEL token:{hash} + PUBLISH invalidate
  4. audit.Log(action="token.revoke", target=id)
```

> 不删行 — 保留历史用于审计与日志 `token_id` 关联。

### 4.8 模型可调用列表(GET /v1/models)

```
listAvailableModels(ctx, view):
  1. 查 channel 模块:GetActiveModels(ctx) → []string(去重所有 enabled + 非熔断渠道 channel_model_mappings.client_model)
     - 该 helper 由 M1-05 提供;本 spec 在 wire 时注入 ModelLister 接口
  2. 用 view.AllowedModels 过滤:
     - 空 → 不过滤
     - 否则保留 ∈ 精确集 ∪ 通配命中
  3. 转 OpenAI /v1/models 响应格式
```

**ModelLister 接口**(本 spec 定义,M1-05 实现):

    ActiveModels(ctx context.Context) []string  // 所有可调用的 client_model;按字典序
    ModelInfo(model string) (ModelMeta, bool)   // 用于 /v1/models 响应里的 created/owned_by 等元数据
}

type ModelMeta struct {

### 4.9 IncrementUsage 与 quota_limit 关系

`quota_used` 仅作**统计**用;**真正的额度拦截在 M1-06 钱包层**,本 spec 不在 `Authenticate` 路径校验 `quota_used >= quota_limit`。理由:
- 钱包是用户级,扣费走 reservation;token 维度的 `quota_limit` 是"软上限",超过仅触发预警与限流(M2 加预警邮件)
- 严格拦截需要 Redis 实时计数(类似限流),复杂度高,M1 不做
- 用户可在前台看到"令牌已用 X/quota_limit",超过则可手动提额或新建令牌

> M1 仅在管理员页 / 用户页展示 `quota_used / quota_limit` 比例。M1-06 commit 时调本 spec 的 `IncrementUsage`,batch 写库即可。

## 11. 关键决策

### 11.1 plaintext 编码 / 长度

**决策**:`pa-` + `base64.RawURLEncoding(36 字节 random)` = `pa-` + 48 字符。

理由:
- 36 字节 = 288 bit 熵,远超暴力枚举(2^128 安全线)
- RawURLEncoding 无 `=`,可直接放 URL / Bearer 头不需 escape
- 48 字符长度适中,展示与复制都不臃肿

不选 hex(72 字符,长);不选 base32(更长且大小写非全保留);不选自定义字符表(无标准库支持)。

### 11.2 key_hash 编码

**决策**:`hex.EncodeToString(sha256(plaintext))` — 小写,64 字符。

理由:
- hex 一定大小写一致(避免 base64 编码后 collation 比较坑)
- 64 字符正好匹配 `VARCHAR(64)`
- DB unique index 上 hex 与 binary 性能差异可忽略

不选 base64:MySQL 默认 collation 大小写敏感但 PG `text` 大小写敏感,实际匹配无问题,但人眼检查 / 日志输出更友好。

### 11.3 key_prefix 展示策略

**决策**:`pa-xxxxxxxx****xxxx` — 前 8 位明文 + `****` + 末 4 位明文。

- "前 8 位明文"含 `pa-` 前缀本身(其实是 `pa-` + 5 明文 char)
- showLen 可配,通过 `setting "token.prefix_show_len"`(默认 8)
- 末 4 位固定 — 保证有"指纹感"防止用户混淆多个相似令牌

> 类比 GitHub PAT 的 `ghp_…` + 后 4 char 显示策略。

### 11.4 last_used_at / quota_used 异步聚合

**决策**:内存 map + 30s flush,**final flush on close**。

替代方案与权衡:
- 同步 UPDATE 每次请求 → DB QPS 暴涨 ~10x;否决
- Redis incr 即时,DB 异步对账 → 引入 Redis-DB 一致性环节,故障复杂度高;否决
- 异步 batch 当前方案 → 30s 内崩溃丢失 last_used 一批;`quota_used` 因 batch sum 可能在 commit 重复时多算一次(M1-06 commit 已是幂等 → 一致;丢一批可接受,统计精度不要求亚秒)

**优雅关停** SIGTERM:
1. `srv.Shutdown(ctx)` → 不再接受新请求
2. `app.Shutdown(ctx)` → `app.TokenStore.Close()`
3. `Close()` 关 `stop`,等 `done` close(=final flush 完成,同步)
4. 退出

### 11.5 通配规则:只支持末尾 `*`

**决策**:仅 `prefix*`,实现 `strings.HasPrefix(model, prefix)`。

不支持的:
- `*-turbo`(后缀通配)— 复杂度 +1 但实际场景"按家族过滤"够用
- `gpt-?-*`(`?` 单字符)— 实际无用例
- `**` glob — 用户难以理解
- 正则 — 太强,易触发 ReDoS

如果未来需要,在 `allow.go` 升级到 `filepath.Match` 即可,**保持向后兼容**(纯 prefix 模式继续工作)。当前为简化和用户认知一致性,M1 限制最严。

### 11.6 IP 字段:同时接受 CIDR 和单 IP

**决策**:`allowed_ips` 数组每个元素先尝试 `netip.ParsePrefix`,失败再 `netip.ParseAddr` 当 `/32` / `/128`。

理由:用户更习惯写 `"1.2.3.4"` 而非 `"1.2.3.4/32"`,降低门槛。

### 11.7 缓存层级:仅 Redis,不做应用内 LRU

**决策**:`token:{hash}` Redis TTL 5min;**不**加进程内 LRU。

理由:
- 进程内 LRU 多实例失效复杂(Pub/Sub 串台风险)
- Redis 命中 RTT 通常 < 1ms,够快
- 节省内存(每个实例 ~100k 令牌每个 ~1KB View = 100MB,不必要)

代价:每个请求一次 Redis GET。可接受。M2 性能压榨时再加 LRU。

### 11.8 quota_used 不在 Authenticate 路径校验上限

**决策**:`Authenticate` 只看 `status / expires_at`,**不**校验 `quota_used >= quota_limit`。

理由:
- 钱包是用户级,真正限额走 M1-06 的 reservation;令牌级 `quota_limit` 是软上限
- 校验要从 batch 数据精确读取 → 必须 Redis 实时计数 → 复杂度高、易出错
- 用户可在前台看比例,自助提额或新建令牌

> M2 可以加 `enforce_quota_limit` setting + Redis 实时 counter。

### 11.9 Regenerate 不删旧请求日志

**决策**:Regenerate 只换 `key_hash`,**保留** `id`;`request_logs.token_id` 永远指向同一行。

理由:用户视角"还是这个令牌,只是换了 key";审计与日志连续性更好。

### 11.10 管理员不允许 Regenerate 他人令牌

**决策**:`/api/admin/tokens/{id}/regenerate` **不存在**;管理员只能 Revoke。

理由:
- 管理员 regenerate 会让用户客户端突然 401 且不知所以,体验差
- 真要让用户重置:`Revoke` 后用户自己 `Create` 新令牌即可
- 防止管理员账户被攻陷后批量 regenerate 钓鱼(攻击者拿到新明文 → 替换用户客户端)

### 11.11 与 M1-06 解耦:接口而非 import

**决策**:M1-06 拿 `app.TokenStore`(`any`),做类型断言 `t, _ := app.TokenStore.(token.Store)`;**不**直接 `import "internal/token"` 在 billing 包。

实际写法:在 M1-06 spec 内定义一个本地的 `UsageIncrementer` 接口:

```go
package billing
type UsageIncrementer interface {
    IncrementUsage(tokenID int64, delta int64)
}
```

在 billing `New` 时接受 `UsageIncrementer` 参数,wire 时传入 `app.TokenStore.(token.Store)`(它满足接口)。这样:
- billing 测试用 mock UsageIncrementer
- 不出现 billing → token 包依赖,符合总纲 §3.2 模块边界

### 11.12 cache JSON 反序列化的 `LastUsedAt` 字段

**决策**:cache 中存的 View JSON **不含** `LastUsedAt`,只在 `repo` 层从 DB 读时填(认为缓存对 last_used 不敏感)。

理由:
- last_used 异步刷新,缓存 vs DB 必有偏差;若缓存承担会被反复失效抖动
- 用户列表页 last_used 由 `GET /api/user/tokens` 走 DB 实时查(不通过 cache,这条路径只在 Authenticate 走)
- 简化:缓存只服务 Authenticate;管理列表走 DB

### 11.13 中间件中 `realIP` 的可信度

**决策**:M1 默认信任 `X-Forwarded-For` 头第一段,假设部署在 Nginx / 网关后。

理由:
- proapi 在容器/k8s 部署中通常前面有 Ingress / LB,直接读 RemoteAddr 拿不到真实客户端 IP
- 若直接暴露(无代理),客户端可伪造 XFF 绕过 IP 白名单
- 缓解:加 setting `server.trust_proxy` (默认 true),false 时只读 `RemoteAddr`;M2 增强为支持白名单代理 IP 列表
- 本 spec 不实现该 setting 的读取,先按"信任"假设运行;**回写 M1-01 seed**:加 `server.trust_proxy = true` 默认值

### 11.14 Bearer 大小写

**决策**:`Bearer` 关键字大小写不敏感(`extractBearer` 用 `EqualFold`);`pa-` 前缀大小写**敏感**。

理由:OpenAI 官方 SDK 严格用 `Bearer` 大写,但少数客户端可能 `bearer` 全小写;放宽 Authorization scheme 大小写以避免 false negative。`pa-` 前缀本身是我们的设计,必须严格小写,与 hash 比较一致。
