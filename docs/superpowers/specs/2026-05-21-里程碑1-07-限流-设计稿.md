# 里程碑 M1-07 限流

## 1. 目标与范围

### 1.1 一句话

**给代理 API 链路加上 user / token / ip / model 四维滑动窗口限流**,RPM 维度作为 gating(超限直接 429),TPM 维度作为 limiting(请求结束后扣计数,影响下次请求)。底层用 Redis sorted-set + Lua 原子脚本(由 [M1-01 §3.1](./2026-05-21-里程碑1-01-基础设施增量-设计稿.md#31-cacheluascripts) 的 `cache.LuaScript` 加载)。

### 1.2 范围

属于本 spec 的(8 件事):

1. **`internal/ratelimit/` 包**:`Limiter` 接口实现、`Check` / `Decision` 数据结构、`DimensionPlan` helper
2. **滑动窗口 Lua 脚本**:基于 [总纲 §5.2](./2026-05-21-里程碑1-总体设计纲要.md#52-滑动窗口限流-lua) 给的伪码加固为可投产版本,由 `cache.LuaScript` 加载
3. **维度键命名**:严格遵守 [总纲 §6.2](./2026-05-21-里程碑1-总体设计纲要.md#62-限流维度键命名)
4. **`RateLimit` 中间件**:挂在代理 API 链(`/v1/*`),次序参见 [总纲 §6.1](./2026-05-21-里程碑1-总体设计纲要.md#61-中间件顺序m1-最终定稿),RPM 入口阻断、TPM 出口计数
5. **阈值推导**:从 `token` 字段 / `user_groups.ratio` / `setting.Store` 三层合成生效阈值,并在 setting 变更时通过 Pub/Sub 失效本地缓存
6. **HTTP 响应头**:被拒时写 `X-RateLimit-Limit-{Dim}` / `X-RateLimit-Remaining-{Dim}` / `X-RateLimit-Reset` / `Retry-After`
7. **管理 API**:`GET /api/admin/ratelimit/keys/:key/stats` 查窗口内 ZCARD;`POST /api/admin/ratelimit/keys/:key/reset` 清空计数
8. **测试**:单元(算法 + helper)+ 集成(Redis 真跑高并发一致性)+ 中间件 e2e

不属于本 spec 的(明确边界):

- ❌ group / dept / global / channel 维度(M2 起补)
- ❌ 健康分动态调节(M3)
- ❌ 令牌桶 / 漏桶(M1 用滑动窗口够用)
- ❌ 限流配额可视化大盘(M1-08 日志页可看 429 计数)
- ❌ TokenAuth 中间件(由 [M1-03](./2026-05-21-里程碑1-03-API令牌-设计稿.md) 提供,本 spec 假设 ctx 上已有 `user / token / group` 三件套)
- ❌ IPAllowlist / ModelAllowlist(M1-03 提供,本 spec 不实现)

## 2. 数据模型

**本 spec 不新增任何持久化表。**

唯一的"数据"是 Redis 中的 sorted-set 计数键 + 应用本地一份阈值缓存:

| 类型 | 键 | 值 | TTL | 说明 |
|---|---|---|---|---|
| Redis ZSET | `ratelimit:user:{user_id}:rpm` | 时间戳 → 唯一成员 | window+1s | 用户每分钟请求数 |
| Redis ZSET | `ratelimit:user:{user_id}:tpm` | 时间戳 → 唯一成员(权重 = 1 个 token) | window+1s | 用户每分钟 token 数 |
| Redis ZSET | `ratelimit:token:{token_id}:rpm` | 同上 | 同上 | |
| Redis ZSET | `ratelimit:token:{token_id}:tpm` | 同上 | 同上 | |
| Redis ZSET | `ratelimit:ip:{cidr}:rpm` | 同上 | 同上 | IP 截断到 /24(v4)或 /64(v6) |
| Redis ZSET | `ratelimit:model:{model}:rpm` | 同上 | 同上 | |
| Redis ZSET | `ratelimit:model:{model}:tpm` | 同上 | 同上 | |
| Redis PUBSUB | `proapi:setting:invalidate` | key | — | 复用 M1-01 setting 通道 |
| 进程内 sync.Map | `limit-cache:{dim}:{id}` | `int + ts` | 30s | 本地阈值缓存,避免每次都查 setting.Store |

约定:**所有 ZSET 的成员名格式为 `<now_ms>:<rand_uint16>`**,避免同毫秒同 cost 时 ZADD 因成员重复被忽略(详见 §4.1)。

### 2.1 阈值缓存数据结构

```go
// internal/ratelimit/threshold.go

// thresholdEntry 是单条本地阈值缓存。
type thresholdEntry struct {
    limit  int       // 0 表示不限
    window time.Duration
    ts     time.Time // 写入时间,TTL 检查
}

type thresholdCache struct {
    mu  sync.RWMutex
    m   map[string]thresholdEntry
    ttl time.Duration
}
```

key 形如 `user_rpm` / `token_rpm` / `ip_rpm` / `model_rpm:gpt-4o` —— **模型 RPM/TPM 阈值按模型名分别缓存**,其它维度按维度名一份(用户 / token 阈值随调用方传入的 token 字段动态决定,所以本地缓存只缓存 setting 默认值)。

### 2.2 不持久化的产物

- 429 触发记录:不写专表;由 [M1-08 日志](./2026-05-21-里程碑1-总体设计纲要.md#28-request_logs--usage_logs) 的 `request_logs` 在 `event_type=0` + `error_code` 中体现
- 限流命中统计:不维护历史;管理 API 直接查当前窗口的 ZCARD(M2 加 Prometheus metrics)

## 3. 接口契约

### 3.1 ratelimit.Limiter

[总纲 §4.6](./2026-05-21-里程碑1-总体设计纲要.md#46-ratelimiter) 已定核心签名,本 spec 给完整实现细节并补两个辅助方法:

```go
// internal/ratelimit/limiter.go
package ratelimit

import (
    "context"
    "time"
)

// Dimension 是维度的语义标识(用于日志 / 响应头),非 redis key 一部分。
type Dimension string

const (
    DimUserRPM  Dimension = "user_rpm"
    DimUserTPM  Dimension = "user_tpm"
    DimTokenRPM Dimension = "token_rpm"
    DimTokenTPM Dimension = "token_tpm"
    DimIPRPM    Dimension = "ip_rpm"
    DimModelRPM Dimension = "model_rpm"
    DimModelTPM Dimension = "model_tpm"
)

// IsTPM 区分 RPM / TPM。
func (d Dimension) IsTPM() bool {
    return d == DimUserTPM || d == DimTokenTPM || d == DimModelTPM
}

// HeaderSuffix 用于 X-RateLimit-* 响应头。
// 例:DimUserRPM → "User-RPM";DimModelTPM → "Model-TPM"。
func (d Dimension) HeaderSuffix() string

// Check 是单维度一次检查的输入。
type Check struct {
    Dimension Dimension
    Key       string        // 完整 redis key(由 DimensionPlan 拼装)
    Limit     int           // 阈值;0 = 不限,直接通过
    Window    time.Duration // 窗口长度
    Cost      int           // 默认 1;TPM 可为 token 数
}

// Decision 是 AllowMulti 的整体结果。
type Decision struct {
    Allowed   bool      // 任一维度被拒 → false
    Denied    *Check    // 被拒的那一维度;Allowed=true 时 nil
    Remaining int       // 被拒维度剩余配额;Allowed=true 时为最紧张维度的余量
    Limit     int       // 被拒维度阈值
    Reset     time.Time // 被拒维度窗口结束时间;Allowed=true 时为最紧张维度的 reset
    Dimension Dimension // 被拒维度;Allowed=true 时为最紧张维度
    Per       []PerDimDecision // 每维度的明细(供 stats / 日志使用)
}

type PerDimDecision struct {
    Dimension Dimension
    Allowed   bool
    Count     int       // 写入后(或被拒前)的实际计数
    Limit     int
    Reset     time.Time
}

// Limiter 是 4 维滑动窗口限流的统一入口。
type Limiter interface {
    // AllowMulti 短路语义:遇到第一个被拒立即返回(不再扣后续维度)。
    AllowMulti(ctx context.Context, checks []Check) Decision

    // ConsumeTPM 仅扣 TPM 维度,不阻塞调用方(返回 nil error 表示已写入)。
    // 用于请求结束后的"事后计数"。
    ConsumeTPM(ctx context.Context, checks []Check) error

    // Stats 查某个完整 redis key 的当前窗口内计数。供管理 API 使用。
    Stats(ctx context.Context, key string) (count int, oldestAt time.Time, err error)

    // Reset 清空某个 key(DEL)。供管理 API 使用。
    Reset(ctx context.Context, key string) error
}
```

**关键决策**:
- 短路:`AllowMulti` 遇到第一个被拒立即返回,**不回滚已写入的较小维度**(滑动窗口天然容忍少量误计;若严格回滚,Lua 需要双向脚本,代价不值)
- TPM 不阻塞:`ConsumeTPM` 即使某维度 `count + cost > limit` 也照写入(因为目的是"让下一次请求被拒"),Lua 脚本在 TPM 模式下行为不同(详见 §4.1)
- `Stats` / `Reset` 接受完整 redis key 字符串(由调用方组装或直接拷贝),避免 admin handler 重复实现拼装逻辑

### 3.2 DimensionPlan helper

```go
// internal/ratelimit/plan.go
package ratelimit

import (
    "context"
    "fmt"
    "time"

    "github.com/proapi/proapi/internal/setting"
)

// PlanInput 是构造 Check 列表所需的上下文。
// 由 RateLimit 中间件从 gin.Context 拼装(M1-03 TokenAuth 后字段都齐)。
type PlanInput struct {
    UserID    int64
    TokenID   int64
    GroupID   int64           // 0 表示走默认分组(ratio=1)
    IP        string          // 原始 IP(IPv4 / IPv6 / 带端口都接受)
    Model     string          // 客户端传的 client_model;空串表示当前请求与模型无关
    // 来自 token 字段的覆盖值;0 表示用全局默认。
    TokenRPMOverride int
    TokenTPMOverride int
    // 来自 user_groups.ratio 的折算系数;0 或 1.0 表示不调整。
    GroupRatio float64
}

// Plan 把 PlanInput 翻译成 RPM 维度的 Check 列表(用于请求开始的 AllowMulti)。
// 阈值为 0 的维度被跳过(不下发到 Limiter)。
// 顺序:user → token → ip → model(与总纲 §6.1 中间件顺序一致)。
func (p *Planner) PlanRPM(ctx context.Context, in PlanInput, now time.Time) []Check

// PlanTPM 同上,但产生 TPM 维度;cost 由调用方在 ConsumeTPM 时填(plan 阶段只生成 key+limit+window)。
// 注:plan 阶段 Cost 字段留 0,调用方在 ConsumeTPM 前批量回填实际 token 数。
func (p *Planner) PlanTPM(ctx context.Context, in PlanInput, now time.Time) []Check

// FillTPMCost 把 Check.Cost 统一改写为 totalTokens(便于一次 ConsumeTPM)。
func FillTPMCost(checks []Check, totalTokens int) []Check {
    out := make([]Check, len(checks))
    for i, c := range checks {
        c.Cost = totalTokens
        out[i] = c
    }
    return out
}

// Planner 内部缓存 setting 中的默认阈值;响应 Pub/Sub invalidate 自动刷新。
type Planner struct {
    setting setting.Store
    cache   *thresholdCache
}

// NewPlanner 启动一个 planner,内部订阅 setting.Store.Subscribe 失效本地阈值。
func NewPlanner(s setting.Store) *Planner
```

阈值合成规则:

| 维度 | 来源 | 备注 |
|---|---|---|
| user_rpm | `TokenRPMOverride > 0 ? override : default × (1 / max(GroupRatio, 0.01))` | VIP `ratio=0.8` → 用户 RPM 上限 ÷ 0.8 = 1.25 ×(总纲 §1.2) |
| user_tpm | `TokenTPMOverride > 0 ? override : default × (1 / max(GroupRatio, 0.01))` | 同上 |
| token_rpm | `TokenRPMOverride > 0 ? override : default` | 不应用 group ratio(token 维度独立于 group) |
| token_tpm | `TokenTPMOverride > 0 ? override : default` | 同上 |
| ip_rpm | `setting.ratelimit.ip_rpm`(全局,与用户无关) | 0 = 不限 |
| model_rpm | `setting.ratelimit.model_default_rpm` | 0 = 不限;M2 可加 per-model 覆盖 |
| model_tpm | `setting.ratelimit.model_default_tpm` | 同上,M1 默认 0 |

> **决策**:user 与 token 阈值可能相同(都 60 RPM)— 中间件仍然走两次 ZADD,因为 token 可以单独被吊销时清空,而 user 维度跨 token 累计;两份计数是互补的(实测开销 < 0.5ms / 维度)。

### 3.3 IP 截断

```go
// internal/ratelimit/ip.go
package ratelimit

import "net/netip"

// CanonicalIP 把入参 IP / IP:port 转成限流键用的 cidr 字符串。
//   - IPv4 → /24,例 "1.2.3.4" → "1.2.3.0/24"
//   - IPv6 → /64,例 "2001:db8::1" → "2001:db8::/64"
//   - 解析失败 → 返回原串(不带 /24,后续脚本仍能跑;打 warn 日志)
func CanonicalIP(raw string) string

// canonicalCIDR 内部实现,返回 netip.Prefix。
func canonicalCIDR(raw string) (netip.Prefix, bool)
```

实现:

```go
func CanonicalIP(raw string) string {
    // 去 port:支持 "1.2.3.4:5678" / "[::1]:5678"
    if h, _, err := net.SplitHostPort(raw); err == nil {
        raw = h
    }
    addr, err := netip.ParseAddr(raw)
    if err != nil {
        return raw // fallback,不阻断业务
    }
    bits := 24
    if addr.Is6() && !addr.Is4In6() {
        bits = 64
    }
    p := netip.PrefixFrom(addr, bits).Masked()
    return p.String()
}
```

> **决策**:IP `unspecified` / `loopback` 也限流(开发环境调试可临时把 `ratelimit.ip_rpm` 调大)。私网 IP 不豁免,避免内部测试绕过限流暴露 bug。

## 4. 关键算法

### 4.1 滑动窗口 Lua(投产版本)

[总纲 §5.2](./2026-05-21-里程碑1-总体设计纲要.md#52-滑动窗口限流-lua) 给的伪码有 3 处需要加固:

1. 成员名冲突:`now .. ':' .. (i + math.random(0, 999999))` 在同毫秒同 cost 下可能重复(`random` 可能撞);用入参 `nonce_base` + 循环 index 保证唯一
2. 0 cost 写入:cost=0 时不应写任何成员
3. TPM "事后计数"模式:即使超额也要写入(用第 5 个 argv `enforce` 开关区分 gating / counting 语义)

最终脚本(`internal/ratelimit/lua/sliding_window.lua`):

```lua
-- KEYS[1] = ratelimit:{dim}:{key}   sorted set
-- ARGV[1] = window_ms       窗口长度(毫秒)
-- ARGV[2] = limit           阈值(0 = 不限)
-- ARGV[3] = now_ms          调用方时钟(避免 Redis / app 时钟漂移)
-- ARGV[4] = cost            本次写入数量(>=0)
-- ARGV[5] = enforce         1 = gating(超额不写返回 0);0 = counting(超额也写返回 0 但已写)
-- ARGV[6] = nonce_base      调用方给的随机基数(uint64 字符串),避免成员名冲突
--
-- 返回 {ok, count_after, limit, reset_ms, wrote}
--   ok = 1            通过
--   ok = 0            被拒(enforce=1 时未写;enforce=0 时已写)
--   count_after       窗口内现有计数(写入后或被拒前)
--   limit             入参回显
--   reset_ms          最早成员的过期时刻(now + window 若无成员)
--   wrote             本次实际写入数量(被 enforce 拒时 = 0)

local key       = KEYS[1]
local window    = tonumber(ARGV[1])
local limit     = tonumber(ARGV[2])
local now       = tonumber(ARGV[3])
local cost      = tonumber(ARGV[4])
local enforce   = tonumber(ARGV[5])
local nonce     = ARGV[6]

-- limit = 0 表示该维度不限,直接通过 + 不写入
if limit <= 0 then
    return {1, 0, 0, now + window, 0}
end

-- cost < 0 防御
if cost < 0 then cost = 0 end

-- 清理过期成员
redis.call('ZREMRANGEBYSCORE', key, 0, now - window)

local count = redis.call('ZCARD', key)
local reset = now + window
if count > 0 then
    local oldest = redis.call('ZRANGE', key, 0, 0, 'WITHSCORES')
    if oldest[2] then
        reset = tonumber(oldest[2]) + window
    end
end

-- gating 模式:超额不写,直接返回 0
if enforce == 1 and (count + cost) > limit then
    return {0, count, limit, reset, 0}
end

-- 写入 cost 个成员
local wrote = 0
if cost > 0 then
    -- ZADD 多成员;成员名 = now:nonce:i,保证唯一
    local args = {}
    for i = 1, cost do
        table.insert(args, now)
        table.insert(args, now .. ':' .. nonce .. ':' .. i)
    end
    redis.call('ZADD', key, unpack(args))
    wrote = cost
    -- 仅在窗口最大值的两倍 TTL 内续命(防 key 永驻)
    redis.call('PEXPIRE', key, window + 1000)
end

local newCount = count + wrote
local ok = 1
if newCount > limit then
    ok = 0   -- counting 模式下超额标记,但已写入
end

return {ok, newCount, limit, reset, wrote}
```

**为什么 `now` 由调用方传**:Redis 集群里多个分片机器时钟可能漂移;Lua 内的 `redis.call('TIME')` 在 cluster 中是 master 时钟,但 app 端是统一时钟。本系统单 Redis,所以两者本质等价,但显式传入便于测试(可注入 mock clock)。

**为什么 nonce_base 由 Go 传**:Lua 5.1 的 `math.random` 在 Redis 中是 deterministic(每次脚本启动种子相同),并发时多个 EVALSHA 会产生相同 nonce → ZADD 成员重复被忽略 → count 漏算。Go 端用 `rand.Uint64()` 生成一次 nonce 传入,保证全局唯一性。

### 4.2 多维度执行(短路 + Pipeline 折中)

```go
// internal/ratelimit/limiter.go (节选)

func (l *redisLimiter) AllowMulti(ctx context.Context, checks []Check) Decision {
    if len(checks) == 0 {
        return Decision{Allowed: true}
    }
    per := make([]PerDimDecision, 0, len(checks))
    now := l.clock.Now()
    nonceBase := l.nextNonce()
    for _, ck := range checks {
        if ck.Limit <= 0 || ck.Cost == 0 {
            // 不限或 0 cost,跳过 redis 调用,记为通过
            per = append(per, PerDimDecision{
                Dimension: ck.Dimension, Allowed: true, Limit: 0,
                Reset: now.Add(ck.Window),
            })
            continue
        }
        res, err := l.scripts.sliding.RunInts(ctx,
            []string{l.fullKey(ck)},
            int64(ck.Window/time.Millisecond),
            int64(ck.Limit),
            now.UnixMilli(),
            int64(ck.Cost),
            int64(1), // enforce = 1 (gating)
            strconv.FormatUint(nonceBase, 10),
        )
        if err != nil {
            // 限流脚本失败 fail-open:打日志,记为通过(避免 Redis 抖动导致 100% 拒绝)
            l.log.Warn("ratelimit script failed, fail-open",
                zap.Error(err),
                zap.String("dim", string(ck.Dimension)),
            )
            per = append(per, PerDimDecision{
                Dimension: ck.Dimension, Allowed: true, Limit: ck.Limit,
                Reset: now.Add(ck.Window),
            })
            continue
        }
        // res = [ok, count_after, limit, reset_ms, wrote]
        ok, count, lim, resetMs := res[0], int(res[1]), int(res[2]), res[3]
        reset := time.UnixMilli(resetMs)
        pd := PerDimDecision{
            Dimension: ck.Dimension,
            Allowed:   ok == 1,
            Count:     count,
            Limit:     lim,
            Reset:     reset,
        }
        per = append(per, pd)
        if ok == 0 {
            return Decision{
                Allowed:   false,
                Denied:    &ck,
                Dimension: ck.Dimension,
                Remaining: 0,
                Limit:     lim,
                Reset:     reset,
                Per:       per,
            }
        }
        nonceBase++ // 每维度递增,避免单批内冲突
    }
    // 全部通过 — 找最紧张的(remaining 最小)填到顶层字段供响应头
    tightest := selectTightest(per)
    return Decision{
        Allowed:   true,
        Dimension: tightest.Dimension,
        Remaining: max(tightest.Limit-tightest.Count, 0),
        Limit:     tightest.Limit,
        Reset:     tightest.Reset,
        Per:       per,
    }
}

// nextNonce 返回一个全局唯一的 uint64,基于全局随机数池。
func (l *redisLimiter) nextNonce() uint64 {
    return atomic.AddUint64(&l.nonceCtr, 1) ^ l.nonceSeed
}

// fullKey 把 Check.Key 拼到 redis 前缀。Check.Key 已包含维度路径(由 Planner 拼装)。
func (l *redisLimiter) fullKey(ck Check) string {
    if strings.HasPrefix(ck.Key, "ratelimit:") {
        return ck.Key
    }
    return "ratelimit:" + ck.Key
}
```

**fail-open 决策**:Redis 不可用时,**所有限流维度直接通过**(写 warn 日志 + 计数 metric `proapi_ratelimit_failopen_total`)。理由:Redis 是限流的硬依赖,但**不应让限流故障变成 100% 拒绝**(违反"开放服务"语义);而 Redis 不可用时,业务上 Reservation / channel 选择等其它路径已经失败,真实 RPS 不会高到危险水平。M2 可加 "circuit-break 到本地令牌桶" 兜底。

### 4.3 TPM 事后计数

```go
// ConsumeTPM 在 c.Next() 后由中间件调用。
func (l *redisLimiter) ConsumeTPM(ctx context.Context, checks []Check) error {
    if len(checks) == 0 {
        return nil
    }
    now := l.clock.Now()
    nonceBase := l.nextNonce()
    var lastErr error
    for _, ck := range checks {
        if ck.Limit <= 0 || ck.Cost == 0 {
            continue
        }
        _, err := l.scripts.sliding.RunInts(ctx,
            []string{l.fullKey(ck)},
            int64(ck.Window/time.Millisecond),
            int64(ck.Limit),
            now.UnixMilli(),
            int64(ck.Cost),
            int64(0), // enforce = 0,counting 模式
            strconv.FormatUint(nonceBase, 10),
        )
        if err != nil {
            l.log.Warn("ratelimit tpm consume failed",
                zap.Error(err),
                zap.String("dim", string(ck.Dimension)),
                zap.String("key", ck.Key),
            )
            lastErr = err
            // 继续写下一维度;不短路
        }
        nonceBase++
    }
    return lastErr
}
```

**关键差别**:`enforce=0`,即使超额也写入。下一次请求的 `AllowMulti` 看到 ZCARD > limit 才会被拒。

**为什么不在 c.Next() 后调 AllowMulti**:`c.Next()` 已经把响应 flush 出去,中间件无法再修改 HTTP status 或追加响应头。如果想"严格阻断超 TPM 的请求",必须在 RPM 阶段就估算 token 数 — 但流式请求的实际 token 在调用上游前未知。所以采用"事后计数 + 下次阻断" 的最终一致语义。

### 4.4 阈值刷新:setting 变更感知

```go
// internal/ratelimit/threshold.go (节选)

func NewPlanner(s setting.Store) *Planner {
    p := &Planner{
        setting: s,
        cache:   newThresholdCache(30 * time.Second),
    }
    // 复用 setting.Store 已经启动的 Pub/Sub;不再单独订阅
    go p.watchInvalidate()
    return p
}

func (p *Planner) watchInvalidate() {
    ch := p.setting.Subscribe(context.Background())
    if ch == nil {
        return // setting.Store 关停
    }
    for key := range ch {
        if strings.HasPrefix(key, "ratelimit.") {
            p.cache.purge() // 简单粗暴:清整个本地缓存
        }
    }
}

func (p *Planner) defaultUserRPM(ctx context.Context, groupRatio float64) int {
    if v, ok := p.cache.get("user_rpm_default"); ok {
        return scaleByGroup(v.limit, groupRatio)
    }
    raw := p.setting.GetInt(ctx, "ratelimit.user_default_rpm", 60)
    p.cache.set("user_rpm_default", raw, time.Minute)
    return scaleByGroup(raw, groupRatio)
}

func scaleByGroup(limit int, ratio float64) int {
    if limit <= 0 {
        return 0
    }
    if ratio <= 0 || ratio >= 1.0 {
        return limit
    }
    return int(float64(limit) / ratio) // VIP ratio=0.8 → 1.25x
}
```

**为什么 ratio 倒数**:`group.ratio` 在计费上意义是"折扣"(VIP 0.8 表示同样请求只扣 80% quota),映射到限流应该是"宽松"(同等 quota 下能发更多请求),所以 RPM/TPM 上限 = 默认 ÷ ratio。

> 决策:M1 不在 `user_groups` 表存独立限流阈值;仅以 ratio 倒数推导。M2 可加 `user_groups.rpm_limit / tpm_limit` 字段(独立配)。

### 4.5 IP 截断的边界情形

```
input              → output
"1.2.3.4"          → "1.2.3.0/24"
"1.2.3.4:5678"     → "1.2.3.0/24"        (SplitHostPort 去 port)
"::1"              → "::/64"
"2001:db8::1"      → "2001:db8::/64"
"[2001:db8::1]:80" → "2001:db8::/64"
"::ffff:1.2.3.4"   → "1.2.3.0/24"        (IPv4-mapped 视为 v4)
"localhost"        → "localhost"          (解析失败,原样返回 + warn)

```

> 决策:空 IP / 无效 IP 共用一个桶 — 对正常流量无影响(都填 X-Forwarded-For 解析出的真实 IP),仅在反代未设 trust 时退化 — 总体上是合理的兜底。

### 4.6 Redis 内存评估

滑动窗口 ZSET 每个成员约 80 字节(score 8 + member 字符串 ~40 + ziplist 元数据),按"成员总数 = limit"估算稳态内存:

| 维度 | 典型 limit | 单 key 内存 | 1k 活跃实体内存 |
|---|---|---|---|
| user_rpm | 60 | 4.8 KB | 4.8 MB |
| user_tpm | 100,000 | 8 MB | 8 GB ⚠️ |
| token_rpm | 60 | 4.8 KB | 4.8 MB |
| token_tpm | 100,000 | 8 MB | 8 GB ⚠️ |
| ip_rpm | 600 | 48 KB | 48 MB |
| model_rpm | 0(M1 不限) | 0 | 0 |
| model_tpm | 0(M1 不限) | 0 | 0 |

**TPM 8 GB 的隐患**:每个 1 token cost 都 ZADD 一个成员的话,100k limit × 80 字节 = 8 MB/user。如果 1000 个用户同时跑满,8 GB 物理内存只在 Redis 上。

**M1 缓解措施**:

1. **粗粒度成员**:在 `ConsumeTPM` 时,若 `cost > 100`,合并写为单成员(score 仍是 now_ms,member 包含 cost 数字,ZCARD 时按"成员数 ≠ 计数"语义算):

```lua
-- 替代方案 A:用 ZINCRBY 单成员累加(失去精确滑动窗口语义,但内存常数)
-- M1 不采用,保留方案 B 简单粗暴
```

实际 M1 采纳方案 B:**保持 ZADD cost 个成员**,但 `ConsumeTPM` 在 Go 端检测 `cost > 1000` 时分拆批次(Lua 脚本 unpack 限制单批 ZADD 不超过 8000 args)。

**M1 监控**:Prometheus(由 M3 引入 — M1 仅本地日志)定期采样 `redis-cli memory usage ratelimit:user:*`,>500MB 单 key 报警。

**M2 优化**:改 ZADD 为 ZINCRBY 单成员模型,牺牲毫秒级窗口精度换内存常数。

> 决策:M1 阶段先用 80 字节 × cost 模型,默认 TPM 100k × 1000 用户 = 8GB 是 worst case;真实业务 token 平均请求 5-20k tokens,稳态 200-500 MB,可接受。

```go
package middleware

import (
    "context"
    "net/http"
    "strconv"
    "time"

    "github.com/gin-gonic/gin"
    "go.uber.org/zap"

    "github.com/proapi/proapi/internal/ratelimit"
    "github.com/proapi/proapi/internal/setting"
    "github.com/proapi/proapi/pkg/apierr"
)

const (
    ctxKeyTotalTokens = "proapi:total_tokens" // relay 在 c.Next() 期间写入
    ctxKeyClientModel = "proapi:client_model" // ModelAllowlist 中间件写入
    ctxKeyUserID      = "proapi:user_id"
    ctxKeyTokenID     = "proapi:token_id"
    ctxKeyGroupID     = "proapi:group_id"
    ctxKeyGroupRatio  = "proapi:group_ratio"
    ctxKeyTokenRPM    = "proapi:token_rpm"   // token.RPMLimit 字段
    ctxKeyTokenTPM    = "proapi:token_tpm"
)

// RateLimit 构造代理 API 的限流中间件。
//
// 依赖:
//   - limiter:Redis 滑动窗口实现
//   - planner:阈值合成(订阅了 setting 失效)
//   - sett:用于读 ratelimit.enabled 全局开关
//
// 中间件顺序见总纲 §6.1,本中间件位于 ModelAllowlist 之后。
func RateLimit(limiter ratelimit.Limiter, planner *ratelimit.Planner, sett setting.Store, log *zap.Logger) gin.HandlerFunc {
    return func(c *gin.Context) {
        // 1. 全局开关
        if !sett.GetBool(c.Request.Context(), "ratelimit.enabled", true) {
            c.Next()
            return
        }

        // 2. 拼装 PlanInput
        in := ratelimit.PlanInput{
            UserID:           getInt64(c, ctxKeyUserID),
            TokenID:          getInt64(c, ctxKeyTokenID),
            GroupID:          getInt64(c, ctxKeyGroupID),
            IP:               clientIP(c),
            Model:            getString(c, ctxKeyClientModel),
            TokenRPMOverride: getInt(c, ctxKeyTokenRPM),
            TokenTPMOverride: getInt(c, ctxKeyTokenTPM),
            GroupRatio:       getFloat(c, ctxKeyGroupRatio),
        }

        now := time.Now()
        ctx := c.Request.Context()

        // 3. RPM gating
        rpmChecks := planner.PlanRPM(ctx, in, now)
        decision := limiter.AllowMulti(ctx, rpmChecks)
        if !decision.Allowed {
            writeRateLimitHeaders(c, decision, true)
            SetErr(c, apierr.New(codeForDimension(decision.Dimension), messageForDimension(decision.Dimension)))
            return
        }
        // 通过时也写"最紧张维度"的剩余配额头(可观测性)
        writeRateLimitHeaders(c, decision, false)

        // 4. 计算并暂存 TPM Checks(用于 c.Next 后)
        tpmChecks := planner.PlanTPM(ctx, in, now)
        c.Set("proapi:tpm_checks", tpmChecks)

        // 5. 让 handler 跑
        c.Next()

        // 6. 事后扣 TPM(handler 应已经在 ctx 写入 total_tokens)
        total := getInt(c, ctxKeyTotalTokens)
        if total <= 0 || len(tpmChecks) == 0 {
            return
        }
        // 复制一份并填 cost
        filled := ratelimit.FillTPMCost(tpmChecks, total)
        if err := limiter.ConsumeTPM(ctx, filled); err != nil {
            log.Warn("ratelimit: tpm consume returned error",
                zap.Error(err),
                zap.Int64("user_id", in.UserID),
                zap.Int("total_tokens", total),
            )
        }
    }
}

func writeRateLimitHeaders(c *gin.Context, d ratelimit.Decision, denied bool) {
    if denied {
        // 仅输出被拒维度的 Limit / Remaining / Reset / Retry-After
        suffix := d.Dimension.HeaderSuffix()
        c.Header("X-RateLimit-Limit-"+suffix, strconv.Itoa(d.Limit))
        c.Header("X-RateLimit-Remaining-"+suffix, "0")
        c.Header("X-RateLimit-Reset", strconv.FormatInt(d.Reset.Unix(), 10))
        retryAfter := int(time.Until(d.Reset).Seconds())
        if retryAfter < 1 {
            retryAfter = 1
        }
        c.Header("Retry-After", strconv.Itoa(retryAfter))
        return
    }
    // 通过时只写最紧张维度的提示头(避免 7+ 个头污染响应)
    suffix := d.Dimension.HeaderSuffix()
    c.Header("X-RateLimit-Limit-"+suffix, strconv.Itoa(d.Limit))
    c.Header("X-RateLimit-Remaining-"+suffix, strconv.Itoa(d.Remaining))
    c.Header("X-RateLimit-Reset", strconv.FormatInt(d.Reset.Unix(), 10))
}

func codeForDimension(d ratelimit.Dimension) apierr.Code {
    switch d {
    case ratelimit.DimUserRPM, ratelimit.DimUserTPM:
        return apierr.CodeRateLimitUser
    case ratelimit.DimTokenRPM, ratelimit.DimTokenTPM:
        return apierr.CodeRateLimitToken
    case ratelimit.DimIPRPM:
        return apierr.CodeRateLimitIP
    case ratelimit.DimModelRPM, ratelimit.DimModelTPM:
        return apierr.CodeRateLimitGlobal // M1 用 global 代指 model 维度;M2 加 CodeRateLimitModel
    default:
        return apierr.CodeRateLimitGlobal
    }
}

func messageForDimension(d ratelimit.Dimension) string {
    switch d {
    case ratelimit.DimUserRPM, ratelimit.DimUserTPM:
        return "请求过于频繁,请稍后再试(用户维度)"
    case ratelimit.DimTokenRPM, ratelimit.DimTokenTPM:
        return "令牌请求过于频繁,请稍后再试"
    case ratelimit.DimIPRPM:
        return "IP 请求过于频繁,请稍后再试"
    case ratelimit.DimModelRPM, ratelimit.DimModelTPM:
        return "模型请求过于频繁,请稍后再试"
    }
    return "请求过于频繁"
}
```

```go
        }
        if err := l.Reset(c.Request.Context(), key); err != nil {
            middleware.SetErr(c, apierr.New(apierr.CodeCache, err.Error()))
            return
        }
        actor := middleware.ActorID(c)
        _ = audi.Log(c.Request.Context(), audit.Entry{
            ActorID:    &actor,
            Action:     "ratelimit.reset",
            TargetType: "ratelimit_key",
            After:      []byte(`{"key":"` + key + `"}`),
            IP:         c.ClientIP(),
        })
        c.JSON(http.StatusOK, gin.H{"ok": true, "key": key})
    }
}
```

路由(由 M1-12 系统设置 spec 同 group 注册;本 spec 仅提供 handler 函数):

```go
admin := r.Group("/api/admin")
admin.Use(middleware.SessionAuth(app.AuthSvc), middleware.RoleGate(3)) // 仅超级管理员
```

### 5.5 典型故障与排查 playbook

| 现象 | 可能原因 | 排查命令 |
|---|---|---|
| 所有 `/v1/*` 都 429 且 `Retry-After` 一致 | `ratelimit.user_default_rpm` 被改成极小 | `SELECT * FROM system_settings WHERE key LIKE 'ratelimit.%'` |
| 单个用户怎么都不限流 | `token.rpm_limit / tpm_limit` 设了大值,优先级高于 default | `SELECT name, rpm_limit, tpm_limit FROM api_tokens WHERE user_id=N` |
| Redis 重启后第一次请求慢 1-2ms | LuaScript fallback EVAL(自带 LOAD) | 看 app log `lua script reloaded` |
| 限流计数比预期少很多 | nonce 冲突导致 ZADD 失败 — 用旧脚本时可能;新脚本不会 | 看 `redis-cli ZRANGE ratelimit:user:N:rpm 0 -1 WITHSCORES`,如有不连续可疑 |
| VIP 用户被频繁限流 | group_ratio 没传(`GroupRatio=0`),Planner 用默认 1.0 | 看 TokenAuth 是否填了 `ctxKeyGroupRatio` |
| 限流"窗口期"奇怪(明明等够 60s 仍 429) | 系统时钟漂移 vs Redis 时钟 / now_ms 入参错 | `redis-cli TIME` 对比 app 时钟;`ZADD` 是否传了未来时间 |
| IP 限流误伤同 CIDR 内多用户 | `/24` 太粗,公司出口 IP 共用 | 给 `ratelimit.ip_rpm` 调大 / 给企业用户加白名单(M2) |
| Pub/Sub 消息丢导致阈值未生效 | Redis 短暂断连 | 等 30s 本地 cache TTL 自然失效;或重启 app |

### 9.3 边界用例

| 用例 | 期望 |
|---|---|
| `cost = 0`(model RPM 维度 token 是 0) | 跳过 redis;Per 中标 Allowed=true |
| `cost > limit`(单次大请求,如 token=200000 但 limit=100000) | gating 模式直接拒(返回 429);counting 模式照写 |
| `Reset` 时刻刚好在调用瞬间 | Retry-After ≥ 1 秒(向上取整防 0) |
| nil ctx 传给 Limiter | 用 `context.Background()` 兜底(防 NPE) |
| Redis 集群 MOVED 错误 | go-redis 自动 follow;脚本经 LuaScript 处理 |
| 同一窗口内 limit 被改小(setting 改了) | 当前 ZCARD 已经超过新 limit → 下一次请求立刻被拒(语义可接受) |
| user_id=0(未登录 — 理论上不会到 RateLimit) | Planner 跳过 user_rpm/tpm(返回 0 个 user 维度 Check) |
| 极长 model 名(64+ 字符) | 写入 ratelimit:model:{name}:rpm,Redis 接受任意长度 key,M1 不截断 |

## 12. 验收

完成 M1-07 时应能:

- `go test ./internal/ratelimit/... ./internal/server/middleware/ratelimit_test.go ./internal/server/handler/admin/ratelimit_handler_test.go` 全通过
- `go test -tags=integration ./internal/ratelimit/...` 在 docker-compose 起的 Redis 上全过(含高并发用例)
- `make build && ./bin/proapi` 启动正常,启动日志含 `lua scripts loaded: ratelimit_sliding_window`
- 手动 e2e:
  - 给某用户建一个 token(用 M1-03 endpoint),调 `POST /v1/chat/completions` 61 次(假设 user_rpm=60),第 61 次返回 429 + `X-RateLimit-Limit-User-RPM: 60` + `Retry-After`
  - 等 60s 后再调可成功
  - 在 token 上设 `rpm_limit=10`(M1-03 admin endpoint),token_rpm 立即生效为 10(本地 cache 30s 内 / Pub/Sub < 1s)
  - 设 `ratelimit.enabled=false`,再调 100 次都通过(无 X-RateLimit-* 响应头)
  - `curl -X POST http://.../api/admin/ratelimit/keys/ratelimit%3Auser%3A42%3Arpm/reset` 后,该用户立即恢复 60 RPM 配额
  - `curl http://.../api/admin/ratelimit/keys/ratelimit%3Auser%3A42%3Arpm/stats` 返回 `{count:0, oldest_at:null, key:"ratelimit:user:42:rpm"}`
- 高并发烟雾:`hey -n 1000 -c 100 -H "Authorization: Bearer pa-xxx"` `/v1/chat/completions`(用 mock relay)
  - 200 计数 = `user_rpm`(60 或全局阈值);429 计数 = 1000 - 200
  - Redis `ratelimit:user:N:rpm` ZCARD ≤ user_rpm + 误差 ≤ 5
- Redis 服务停掉:接口仍 200(fail-open),日志中有 warn `ratelimit script failed, fail-open`
- Redis 重启 + SCRIPT FLUSH:接口仍 200,且新 EVALSHA 在第一次自动 fallback EVAL 后稳定 SHA
- 覆盖率:`go test -cover ./internal/ratelimit/...` ≥ 80%
