# 号池管理(Account Pool)设计稿

> 在现有「一个 channel = 一个 API key」的基础上,引入 **账号池层**:一个 channel 可挂载 N 个 Codex 类账号(Claude Code OAuth / Codex CLI OAuth / 直连 API Key),relay 链路在 channel 选定后从该 channel 的账号池中再挑一个具体账号下手。该模块负责:批量入池 / 凭证加密存储 / token 自动刷新 / 上游限额嗅探 / 账号级熔断 / 账号级监控 / 完整审计。

# 第 1 节 / 目标与边界

## 1.1 项目目标

为 proapi 增加**号池层(Account Pool)**,使一个 channel 不再被一个 API key 绑死,可以挂载 N 个上游账号并按策略调度。同时提供:

- **批量入池**:支持粘贴(7+ 种 JSON / token 字符串格式自动识别)、文件上传、单条 API Key、OAuth 直连。
- **凭证管理**:OAuth `access_token` / `refresh_token` 全生命周期自动刷新(过期前 5 分钟主动刷)。
- **限额感知**:5h 滚动窗口 + 周窗口的余量、重置时间从上游响应头嗅探采集;入池时主动 probe 一次初始化。
- **故障自愈**:429 短熔断到 reset_at,自动恢复;401 触发刷新,失败下线;5xx 连续 N 次进入冷却。
- **完整监控**:总览 KPI + 列表多维筛选 + 详情时间线 + Prometheus 指标 + 告警。

## 1.2 范围

| 维度 | 决策 |
|---|---|
| Provider 范围 | M1 主路径 = **Anthropic**(Claude Code OAuth);双 schema 同步支持 **OpenAI**(Codex CLI OAuth) |
| 与 channel 关系 | **一对多**:`accounts.channel_id` 外键,每个账号只归属一个 channel |
| 入池方式 | OAuth 直连(M2) / Token-JSON(M1) / API Key(M1) / 批量导入(M1,含 cpa = CLI Proxy API 导出) |
| 凭证存储 | `accounts.credentials` 字段 AES-256-GCM 加密,密钥来自 `PROAPI_MASTER_KEY` |
| 额度采集 | 上游响应头嗅探(常态) + 入池 probe(初始化) + 手动测试按钮(管理员) |
| 限流响应 | 短熔断到 `reset_at`,后台 worker 每 30 秒扫表恢复 |
| Token 刷新 | 后台 worker 60 秒 tick + 过期前 300 秒主动刷,Redis SET NX 锁多实例去重 |
| 调度策略 | 默认 `top_k` 余量优先 + jitter,可选 `round_robin` / `weighted` / `max_remaining`,channel 维度可配 |
| 监控字段 | 身份(provider/tier/email) + 可用性(status/cooldown_until) + 额度(5h/week) + 用量(last_used/last_success) + 凭证健康(token 过期 / refresh 状态) |
| 用户前台 | 不开放(号池属于运营资产) |
| 模块边界 | `internal/account/`,与 `internal/channel/` 平级,被 `relay/` 在 channel 选定后调用 |

## 1.3 关键决策摘要

```
账号是 channel 下的「资源池」,channel 是「业务策略层」(决定走哪个上游、什么倍率、什么限流)
account 是「调用资源层」(具体调用谁的 token,处理刷新与限额)
relay 链路:request → channel selector → account selector → adapter
```

| 决策点 | 选择 | 理由 |
|---|---|---|
| 号池放哪 | 独立模块 `internal/account/` | 边界清晰,可独立测试,oauth/importer/probe 不污染 channel |
| 数据模型 | 主表 `accounts` + 事件表 `account_events` + `channels` 加 3 字段 | 主路径简单(外键),共享场景靠 tag,不引 join 表 |
| 凭证类型 | `provider` × `tier` 双轴 + `cred_type` 三态 | 同一表表达 OAuth/API Key/粘贴 token 三种形态 |
| 额度来源 | 上游响应头嗅探 + 入池 probe + 手动测试 | 不靠用户填,不消耗主链路 |
| 失败熔断 | 短熔断到 `cooldown_until`(精度到秒)+ 后台 worker 恢复 | 与现有 channel breaker 状态机一致,代码模式复用 |
| Token 刷新 | 后台 worker + Redis 分布式锁 | 多实例下保证同一账号同一时刻只刷一次 |
| 调度策略 | strategy 接口,默认 top_k 余量优先 | 偏好余量充足账号,jitter 防雪崩 |
| Importer | 启发式自动识别 + 用户可覆盖 | 9 种格式同一框架,扩展只加 file |
| OAuth | M1 stub + refresh 实现,直连授权放 M2 | 90% 用户已有 token,先验主路径 |

## 1.4 不在范围(明示边界)

- ❌ 用户前台查询号池(账号是运营资产,只管理员看)
- ❌ 跨 provider 自动迁移(Anthropic 账号失效自动启用 OpenAI 备份)
- ❌ 按账号维度计费(账号是资源,计费仍在 channel 维度)
- ❌ 账号"健康分"(沿用 channel 健康分即可,M3 范围)
- ❌ 自动注册账号 / 自动养号(合规与法律风险,本项目永不做)
- ❌ 二级共享(多对多 join 表,M3 视需求再评估)

## 1.5 兼容性

- 现有 channels(`pool_enabled = 0`,默认)行为不变,继续走 `channels.credentials` 单 key 路径。
- 启用号池只需对单个 channel 改 `pool_enabled = 1`,逐 channel 灰度。
- relay 链路在 channel 选定后做一次分支判断,主路径几乎无 overhead。

## 3.1 Go 接口定义(`internal/account/iface.go`)

```go
// Account 是 accounts 表的领域对象。
type Account struct {
    ID                   int64
    ChannelID            int64
    Name                 string
    Provider             string  // anthropic | openai
    Tier                 string  // free|plus|pro|pro_max|team|enterprise|api|unknown
    CredType             string  // oauth|apikey|token_pasted
    Email                string
    ExternalAccountID    string
    Status               Status
    Priority             int16
    Weight               int
    CooldownUntil        *time.Time
    Quota5h              QuotaWindow
    QuotaWeek            QuotaWindow
    AccessTokenExpiresAt *time.Time
    RefreshTokenValid    int8
    // ... 见 2.1 表完整字段
    Cred                 AccountCred  // 运行时字段,不持久化,从加密字段解出
}

type QuotaWindow struct {
    Total     *int64
    Remaining *int64
    ResetAt   *time.Time
    SyncedAt  *time.Time
}

type Status int8
const (
    StatusActive   Status = 0
    StatusCooldown Status = 1
    StatusExpired  Status = 2
    StatusDisabled Status = 3
    StatusInvalid  Status = 4
)

// Selector 从 channel 的账号池中挑一个。
type Selector interface {
    Select(ctx context.Context, channel *channel.Channel, hint SelectHint) (*Account, error)
    ReportSuccess(accountID int64, latency time.Duration)
    ReportFailure(accountID int64, err error, upstreamHeaders http.Header)
}

type SelectHint struct {
    Excluded []int64       // 本次请求已失败的 account id
    UserID   int64
    TokenID  int64

}

// Repo 数据访问层。
type Repo interface {
    Create(ctx context.Context, a *Account) error
    Update(ctx context.Context, a *Account) error
    Get(ctx context.Context, id int64) (*Account, error)
    ListByChannel(ctx context.Context, channelID int64) ([]*Account, error)
    ListForRefresher(ctx context.Context, before time.Time, limit int) ([]*Account, error)

type QuotaTracker interface {

}

    Run(ctx context.Context) error                            // 启动后台循环
```

## 3.2 调度算法(默认 strategy = top_k)

```go
func (s *topKSelector) Select(ctx, channel, hint) (*Account, error) {
    // 1. 取候选池(Redis 优先,miss 回 DB)
    pool := s.repo.poolFor(channel)           // accounts.channel_id = ch.id
    if len(pool) == 0 { return nil, ErrNoAccount }

    // 2. 过滤:status==active,排除 hint.Excluded
    cands := filter(pool, func(a *Account) bool {
        return a.Status == StatusActive &&
               !contains(hint.Excluded, a.ID) &&
               (a.Tier == "" || tierSupportsModel(a.Tier, hint.Model))
    })
    if len(cands) == 0 { return nil, ErrNoAccount }

    // 3. 按余量百分比降序(余量未知按 100% 算,给新账号机会)
    sort.Slice(cands, func(i, j int) bool {
        return remPct(cands[i]) > remPct(cands[j])
    })

    // 4. 取 top K(channel.AccountTopK,默认 3)
    k := min(channel.AccountTopK, len(cands))
    topK := cands[:k]

    // 5. 组内按 priority 高 → weight 加权随机
    return weightedRandom(topK), nil
}

func remPct(a *Account) float64 {
    if a.Quota5h.Total == nil || a.Quota5h.Remaining == nil {
        return 1.0  // 未知视为满额
    }
    return float64(*a.Quota5h.Remaining) / float64(*a.Quota5h.Total)
}
```

其它 strategy(`round_robin` / `weighted` / `max_remaining`)各 ~20 行实现,共用 `Selector` 接口,通过 `strategyRegistry` 按 channel 配置切换。

## 3.3 失败处理与短熔断

```go
func (s *selector) ReportFailure(accountID int64, err error, headers http.Header) {
    code := classify(err)
    switch code {
    case ErrRateLimited:                       // 429
        reset := parseResetAt(headers)         // x-ratelimit-reset / anthropic-ratelimit-reset
        if reset.IsZero() {
            reset = time.Now().Add(5 * time.Minute)
        }
        s.repo.markCooldown(accountID, reset)
        s.appendEvent(accountID, "cooldown_entered",
            map[string]any{"until": reset, "err": err.Error()})

    case ErrTokenExpired, ErrTokenRevoked:    // 401
        ok := s.refresher.RefreshOne(ctx, accountID)
        if !ok {
            s.repo.markExpired(accountID)
            s.appendEvent(accountID, "refresh_failed", nil)
        }

    case ErrInvalidCredential:                 // 403 / 凭证作废
        s.repo.markInvalid(accountID)

    default:                                    // 临时错误(网络 / 5xx)
        s.repo.incConsecFail(accountID)
        if consec >= 5 {
            s.repo.markCooldown(accountID, time.Now().Add(60*time.Second))
        }
    }
}
```

**恢复**:后台 worker 每 30 秒扫 `status=cooldown AND cooldown_until <= NOW()`,批量改回 active,广播 Redis Pub/Sub 失效缓存。

## 3.4 Token 刷新 worker

```go
// 启动时 go refresher.Run(ctx)
func (r *refresher) Run(ctx context.Context) error {
    tick := time.NewTicker(60 * time.Second)
    for {
        select {
        case <-ctx.Done(): return nil
        case <-tick.C:
            // 找出 5 分钟内将过期的 OAuth 账号
            list, _ := r.repo.ListForRefresher(ctx, time.Now().Add(5*time.Minute), 100)
            for _, a := range list {
                go r.refreshWithLock(ctx, a)  // Redis SET NX 抢锁,多实例只刷一次
            }
        }
    }
}

func (r *refresher) refreshWithLock(ctx context.Context, a *Account) {
    lockKey := fmt.Sprintf("account:lock:refresh:%d", a.ID)
    if !r.redis.SetNX(lockKey, "1", 30*time.Second) { return }
    defer r.redis.Del(lockKey)

    newCred, err := r.providerOAuth[a.Provider].ExchangeRefreshToken(ctx, a.Cred.RefreshToken)
    if err != nil {
        r.repo.markRefreshFailed(a.ID, err)
        r.appendEvent(a.ID, "refresh_failed", map[string]any{"err": err.Error()})
        return
    }
    r.repo.updateCred(a.ID, newCred)
    r.appendEvent(a.ID, "token_refreshed", nil)
}
```

provider 各自实现 refresh endpoint(`oauth/anthropic.go` / `oauth/openai.go`)。

## 3.5 额度嗅探(常态采集)

在 adapter 调用点(`relay/chat.go`)挂钩:


provider 各自实现 header 解析:

- `quota/anthropic.go` — 解析 `anthropic-ratelimit-requests-*` / `anthropic-ratelimit-tokens-*` / `x-claude-*`
- `quota/openai.go` — 解析 `x-codex-*` / `x-ratelimit-*`

## 3.6 入池 probe

账号入库后立即触发(同步等待 ≤ 3 秒,超时不阻塞):

```go
func (p *probe) Run(ctx context.Context, a *Account) error {
    // 不消耗 token 的轻量调用:
    //   Anthropic 用 /v1/messages?dry_run=true 或 count_tokens
    //   OpenAI 用 /v1/models 列表
    headers, err := p.providerProbe[a.Provider].Probe(ctx, a.Cred)
    if err != nil { return err }
    snap := p.quotaTracker.ExtractFromResponse(a.Provider, headers)
    p.repo.updateQuota(a.ID, snap)
    p.appendEvent(a.ID, "probed", snap)
    return nil
}
```

## 3.7 relay 链路接入点

```go
// internal/relay/chat.go
func RelayChat(ctx context.Context, req IRRequest) (*IRResponse, error) {
    ch, err := channelSelector.Select(ctx, req.Model, hint)
    if err != nil { return nil, err }

    var cred channel.Credential
    var accountID int64
    if ch.PoolEnabled == 1 {
        acc, err := accountSelector.Select(ctx, ch, accountHint)
        if err != nil { return nil, err }
        cred = acc.Cred.ToChannelCred()
        accountID = acc.ID
    } else {
        cred = ch.Cred
    }

    resp, err := adapter.Chat(ctx, req, cred)

    if accountID > 0 {
        if err != nil {
            accountSelector.ReportFailure(accountID, err, resp.Headers)
        } else {
            accountSelector.ReportSuccess(accountID, resp.Latency)
            go quotaTracker.UpdateAccount(ctx, accountID, snap)
        }
    }
    return resp, err
}
```

# 第 4 节 / Importer(粘贴 + 文件导入)

## 4.1 支持的格式与识别策略

`Importer.Detect()` 用启发式优先级匹配,识别失败再让用户在 UI 手选:

| 格式 ID | 识别特征 | 输出账号数 |
|---|---|---|
| `oauth_session` | 顶层有 `tokens.access_token` + `tokens.refresh_token` | 1 |
| `claude_authjson` | 顶层是 `{"claudeAiOauth": {...}}` 或单文件含 `access_token`/`refresh_token`/`expires_at`/`scopes` | 1 |
| `codex_authjson` | 顶层有 `OPENAI_API_KEY` 或 `tokens.id_token` 且 `tokens.refresh_token` 是 `rt_*` | 1 |
| `sub2api_export` | 顶层是数组,每项含 `email` + `tokens` 或 `accessToken` | N |
| `cliproxy_export` | 顶层 `accounts: [...]` 或 `proxies: [...]`,内含 `provider` + `credentials` 字段(CLI Proxy API 项目导出) | N |
| `auths_json_batch` | `~/.claude/auths.json` 多账号,顶层是 `{email1: {tokens:...}, email2: {tokens:...}}` map | N |
| `raw_access_token` | 纯字符串,以 `sk-ant-oat01-` / `eyJ` 开头(JWT) | 1 |
| `raw_refresh_token` | 纯字符串,以 `sk-ant-ort01-` / `rt_` 开头 → 联网换 access_token | 1 |
| `raw_apikey` | 纯字符串,以 `sk-ant-api03-` / `sk-` 开头 | 1 |

仅 `refresh_token` 时,Importer 内部调 `OAuthFlow.ExchangeRefreshToken()` 换出完整凭据后再入库;失败 → 报错并计入 `errors`。

## 4.2 文件 / 批量上传

后台路由 `POST /api/admin/accounts/import`,multipart:

- 字段 `file`(可选):接受 `.json` / `.txt`,≤ 2 MB
- 字段 `text`(可选):粘贴的字符串
- 字段 `channel_id`(必填):导入到哪个 channel
- 字段 `format`(可选):用户在 UI 上覆盖自动识别结果
- 字段 `dry_run`(可选,bool):仅解析不入库,用于「预览」按钮

返回:

```json
{
  "code": 0,
  "data": {
    "total": 12,
    "imported": 10,
    "skipped": 2,
    "errors": [
      {"index": 3, "reason": "refresh_token expired"},
      {"index": 7, "reason": "duplicate, account_id=ac_xxx exists"}
    ],
    "account_ids": [101, 102]
  }
}
```

入库后:批量触发 probe(并发上限 8),probe 结果异步写回,前端轮询 `GET /api/admin/accounts?ids=101,102,...` 看进度(M2 可改为 SSE)。

## 4.3 去重策略

入库前算 `dedup_key`(顺序回退):

1. `external_account_id`(优先,上游侧的 stable id)
2. `email`
3. `sha256(access_token)`(无前两者时)

DB 命中(同 `channel_id` 内)→ 默认**跳过 + 计入 skipped**;UI 上提供「覆盖更新」选项 → 走 update 而非 insert。

## 4.4 OAuth 直连(M2,接口先留)

```go
type OAuthFlow interface {
    Start(ctx, provider, channelID) (authURL string, state string, err error)
    Callback(ctx, state, code string) (*Account, error)
}
```

流程:

```
1. 后台 UI 点「OAuth 授权」→ POST /api/admin/accounts/oauth/start
2. 后端生成 state + PKCE verifier,Redis 缓存 state→verifier 10 分钟
3. 返回 authURL,前端 window.open
4. 上游回调 /api/admin/accounts/oauth/callback?state=...&code=...
5. 后端用 verifier 换 token → 入库 → 关闭窗口
6. 前端轮询或 WS 通知刷新列表
```

M1 在 UI 上把按钮置灰,tooltip 写「M2 上线」;后端 `OAuthFlow.Start/Callback` 留 stub 返回 `501 Not Implemented`,只有 `ExchangeRefreshToken` 完整实现(给 Importer 用)。

## 7.6 关键风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| A1 | 上游 OAuth refresh endpoint 不稳定 / 频繁返回 invalid_grant | 账号大面积下线 | refresh 失败不立即下线,前 3 次进 cooldown 重试,第 4 次才 mark expired |
| A2 | 上游响应头额度字段变更 | quota 显示失真 | 解析器 fallback:取不到字段则保留旧值,不覆盖为 0;事件日志记录"quota_extract_partial" |
| A3 | 批量导入大量账号挤兑 probe worker | probe 延迟过长 | probe 并发上限 8,超额排队;UI 显示进度 |
| A4 | 多实例下同账号 refresh 重复 | 上游限制刷新频率,可能黑该账号 | Redis SET NX 锁 + 单实例内 channel 缓存 + 后端层去重 |
| A5 | 凭证泄露(数据库被脱库 / 备份外泄) | 上游账号被盗用 | AES-256-GCM 加密 + 密钥从 ENV / KMS 读;peek 强制 audit;DBA 也无法解 |
| A6 | 用户错误粘贴包含旧 token,覆盖了正在用的活账号 | 在线服务短暂中断 | 默认"跳过重复",覆盖需 UI 显式勾选;覆盖时写 audit_log |
