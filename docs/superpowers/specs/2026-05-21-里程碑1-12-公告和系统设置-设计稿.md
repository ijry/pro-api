# 里程碑 M1-12 公告与系统设置

## 1. 目标与范围

### 1.1 一句话

**两个低复杂度的 admin 后台维护型功能** — 公告发布(含用户侧未读)+ 系统设置统一编辑入口(含敏感字段透明加密)。

### 1.2 范围

放在同一份 spec 的理由:两块都是"配置/通知"性质,handler 都很薄,代码量都不大;且共享 audit、apierr、setting.Store、Application 容器等基础设施;前端最终也都落在"系统管理"那一栏 tab。

属于本 spec 的(必须实现):

#### A. 公告(notices)

1. **migration**:`000018_create_notices.{up,down}.sql`(MySQL + PG),schema 见 [总纲 §2.17](./2026-05-21-里程碑1-总体设计纲要.md#217--notices)
2. **领域服务** `internal/notice/`:CRUD、publish/unpublish、用户已读、未读数
3. **已读机制**:Redis SET `notice:read:{user_id}` 存已读 notice_id 集合,**无 TTL**(永久)
4. **publish 流程**:create 时 `status=0`(草稿),单独的 publish endpoint 才改 `status=1`;unpublish 改为 `status=2`(已下架)
5. **管理员 handler**:7 个路由,见 §5.1
6. **用户 handler**:4 个路由,见 §5.2
7. **公开 handler**:1 个路由,见 §5.3
8. **登录联动 helper**:`notice.Service.UnreadCountForUser(ctx, userID) int`,供 [M1-02](./2026-05-21-里程碑1-02-用户与鉴权-设计稿.md) 在登录响应中 include `unread_count`(本 spec 暴露接口,M1-02 调用)

#### B. 系统设置(system_settings)

1. **migration**:`system_settings` 表由 M1-01 建好(`000019_*`),本 spec **不重建**
2. **分组常量**:本 spec 在 `internal/setting/groups.go` 定义"key prefix → 分组名"映射,后端按 prefix 分组返回,前端按分组渲染 tab
3. **敏感字段加密**:本 spec 在 `internal/setting/sensitive.go` 定义敏感 key 清单与判定函数,PATCH 接收明文时调 `application.Crypto.Encrypt` 包装后写库;GET 时形如 `ENC(v1,...)` 的 value 一律脱敏为字符串 `"<encrypted>"`
4. **管理员 handler**:4 个路由,见 §5.4(列表 / 单查 / 修改 / SMTP 测试)
5. **SMTP 测试**:本 spec 仅校验字段格式,**实际发送由 [M1-02 用户与鉴权](./2026-05-21-里程碑1-02-用户与鉴权-设计稿.md) 的 Mailer 接口完成**(跨 spec 引用);M1-02 接口未就绪前返回 `{"ok": true, "stubbed": true}`

### 1.3 不属于本 spec(明确边界)

- 公告与系统设置的前端 UI([M1-09 后台前端](./2026-05-21-里程碑1-09-后台前端-设计稿.md))
- 用户端公告订阅推送 / WebSocket(M2/M3)
- SMTP 实际发送(依赖 M1-02 Mailer 接口实现)
- 公告 Markdown 富文本编辑器(前端的事)
- system_settings 读取时的**透明解密**(本 spec **不提供**;业务模块各自调 `crypto.Decrypt`,详见 §11 建议)
- 公告的定时发布(`publish_at` 字段存了,但 cron 调度任务**推到 M2**)
- 公告的"reach 用户数 / 阅读率"统计(M3)

### 2.3 Redis 已读集合

```
key   : notice:read:{user_id}     (Redis SET)
member: notice_id (int64 string)
TTL   : 永不过期(无 EXPIRE)
```

设计理由:
- 用户量 ×公告量 = O(N×M),N、M 都不大(单租户预计 N<100k,M<1k),Redis SET 完全扛得住
- 不存 DB:已读行为查询频次低,且业务上"未读"只看用户端 — 无需历史回溯
- 不加 TTL:用户未读状态是长期事实,即使过期公告也应保留"已读"标记,避免重新弹出
- 公告硬删时,本 spec **不主动清理** Redis 残留 member(对端 Get notice 时已不存在,自然过滤掉)

> 决策:已读机制走纯 Redis,容忍 Redis 数据丢失(最坏情况:用户被重新弹一次未读公告,可接受)。M3 若要做"已读率统计",再加一张 `notice_reads` 表。

## 3. 接口契约

### 3.1 notice.Service

```go
// internal/notice/service.go
package notice

import (
    "context"
    "time"
)

type Service interface {
    // ===== 管理员 =====

    // Create 创建公告(status=Draft)。createdBy 即操作者 user id。
    Create(ctx context.Context, in CreateInput, createdBy int64) (*Notice, error)

    // List 后台分页列表;filter.Status<0 表示不筛。
    List(ctx context.Context, filter ListFilter) ([]*Notice, int64, error)

    // Get 拿一条(不区分 status)。
    Get(ctx context.Context, id int64) (*Notice, error)

    // Update 更新 title/content/level/target/pinned/publish_at/expires_at;
    // 不允许通过 Update 改 status(用 Publish/Unpublish)。
    Update(ctx context.Context, id int64, patch UpdatePatch, actor int64) (*Notice, error)

    // Delete 硬删(M1 不做软删,公告量小)。
    Delete(ctx context.Context, id int64, actor int64) error

    // Publish 把 status 置 1;若 publish_at 为 NULL,补当前时间。
    Publish(ctx context.Context, id int64, actor int64) (*Notice, error)

    // Unpublish 把 status 置 2(已下架)。
    Unpublish(ctx context.Context, id int64, actor int64) (*Notice, error)

    // ===== 用户 =====

    // ListForUser 用户侧列表:status=Published, 未过期, target ∈ {all,user},
    // 含 isRead 字段;按 pinned DESC, publish_at DESC 排序。
    ListForUser(ctx context.Context, userID int64, page, size int) ([]*UserNotice, int64, error)

    // GetForUser 单条获取;无权限或不可见返 nil, apierr.CodeNotFound。
    GetForUser(ctx context.Context, userID int64, id int64) (*UserNotice, error)

    // MarkRead 把 (userID, noticeID) 加入已读集合;幂等。
    MarkRead(ctx context.Context, userID, noticeID int64) error

    // UnreadCountForUser 返回用户未读公告数(target ∈ {all,user}, status=Published, 未过期)。
    // 失败返 0 不阻塞登录。
    UnreadCountForUser(ctx context.Context, userID int64) int

    // ===== 公开 =====

    // ListPublic target=all 且 status=Published 且未过期。
    ListPublic(ctx context.Context, page, size int) ([]*Notice, int64, error)
}

type CreateInput struct {
    Title     string
    Content   string
    Level     string
    Target    string
    Pinned    bool
    PublishAt *time.Time
    ExpiresAt *time.Time
}

type UpdatePatch struct {
    Title     *string
    Content   *string
    Level     *string
    Target    *string
    Pinned    *bool
    PublishAt *time.Time   // nil pointer = 不改;若想清空,客户端传 expires_at:0 由 handler 转 NULL — 见 §5
    ExpiresAt *time.Time
    // 客户端用 "publish_at": null 表示清空 → handler 解析为 sentinel (见 §5.1 PATCH 协议)
    PublishAtNull bool
    ExpiresAtNull bool
}

type ListFilter struct {
    Status int8  // -1 = 不筛;0/1/2 = 草稿/已发布/已下架
    Page   int
    Size   int
}

// UserNotice 是用户视角的公告;比 Notice 多 IsRead。
type UserNotice struct {
    Notice
    IsRead bool `json:"is_read"`
}
```

    UnreadCount(ctx context.Context, userID int64, visibleIDs []int64) (int, error)

type reader struct {
    rdb *redis.Client

### 3.5 setting sensitive

```go
// internal/setting/sensitive.go
package setting

import (
    "regexp"
    "strings"
)

// SensitiveKeys 是显式列出的敏感配置项白名单。
//
// 这里只列那些以 _secret/_password/_key 结尾不容易被 §3.5.2 兜底匹配到的"业务命名"项。
var SensitiveKeys = map[string]struct{}{
    "auth.github_oauth.client_secret": {},
    "auth.smtp.password":              {},
    "payment.stripe.secret_key":       {},  // M1 不使用,留作 M2;但加密策略需提前一致
    "payment.stripe.webhook_secret":   {},
}

// sensitiveSuffixRE 用正则兜底所有以 _secret / _password / _key 结尾的 key。
//   注意:有些 key 含 "secret" 在中间(如 "secret_path")不是敏感的,本规则只匹配后缀。
var sensitiveSuffixRE = regexp.MustCompile(`(?:^|\.)([a-z0-9_]+_(secret|password|key))$`)

// IsSensitive 判断一个 key 是否敏感。
func IsSensitive(key string) bool {
    if _, ok := SensitiveKeys[key]; ok {
        return true
    }
    return sensitiveSuffixRE.MatchString(key)
}

// 占位字符串:GET 时敏感字段(若 value 是 ENC(...))替换为该值。
const EncryptedPlaceholder = "<encrypted>"

// IsEncryptedValue 判断 raw JSON string value 是否是 ENC(v1,...) 形态。
//   只识别 JSON 字符串形式;非字符串 value 不当作 ENC。
func IsEncryptedValue(raw []byte) bool {
    s := strings.TrimSpace(string(raw))
    return strings.HasPrefix(s, `"ENC(`) && strings.HasSuffix(s, `)"`)
}

// IsPlaceholderValue 判断 PATCH body 中是否为占位值(若是,handler 不更新该 key)。
func IsPlaceholderValue(raw []byte) bool {
    s := strings.TrimSpace(string(raw))
    return s == `"`+EncryptedPlaceholder+`"`
}
```

## 4. 关键算法

### 4.1 未读数计算

**输入**:`userID`
**输出**:整数 `unread`

```
1. visibleIDs = repo.VisibleIDsForUser(targets={all,user}, now=Clock.Now())
   - SQL: SELECT id FROM notices WHERE status=1
              AND (publish_at IS NULL OR publish_at<=?)
              AND (expires_at IS NULL OR expires_at>?)
              AND target IN ('all','user')
2. 若 len(visibleIDs)==0  → 返回 0
3. unread = reader.UnreadCount(userID, visibleIDs)
   - 用 SMISMEMBER notice:read:{userID} 批量判断,反集即未读
   - 大集合分批,每批 ≤ 500
4. 失败任何一步 → 记 warn 日志,返回 0(不影响登录)
```

> 性能:可见公告数预期 < 100,即使千用户并发查询也只是几次 SMISMEMBER,完全可接受。无需缓存 visibleIDs(读路径加缓存反而增加失效复杂度;改 publish 时要清,M1 不值)。

### 4.2 ListForUser 批量标 isRead

```
1. notices, total = repo.ListVisibleForUser(targets, now, page, size)
2. readSet = reader.ReadSet(userID)            // 单次 SMEMBERS
3. for each n in notices: n.IsRead = readSet[n.ID] != nil
4. 排序 by pinned DESC, publish_at DESC  → 已在 repo SQL ORDER BY
```

排序细节:`ORDER BY pinned DESC, COALESCE(publish_at, created_at) DESC, id DESC`。

### 4.3 Publish 流转

```
Publish(id, actor):
  tx.Begin()
    n = repo.GetByID(id)
    if n == nil          → return apierr.CodeNotFound
    if n.Status == 1     → return n, nil   (幂等;不报错)
    now = Clock.Now()
    fields = { status: 1, updated_at: now }
    if n.PublishAt == nil { fields.publish_at = now }
    repo.Update(id, fields)
  tx.Commit()
  audit.Log(action="notice.publish", target_type="notice", target_id=id,
            before={status:n.Status}, after={status:1}, actor=actor)
  return repo.GetByID(id), nil
```

Unpublish 类似,`status: 2`,审计 action `notice.unpublish`。

### 4.4 系统设置 PATCH 加密路径

```
PATCH /api/admin/settings/{key}  body: { "value": <any JSON> }

handler 流程:
  1. 校验 key 存在(必须是已知 key —— 通过 Setting.Get 看;不存在拒绝)
  2. raw = body.value (json.RawMessage)
  3. 若 setting.IsPlaceholderValue(raw)        → 不更新,返回 ok (用户没改动密文字段)
  4. 若 setting.IsSensitive(key):
       - 解析 raw 必须是 JSON string(非字符串 → CodeInvalidParam)
       - plaintext = unquote(raw)
       - ct = crypto.Encrypt([]byte(plaintext))  // 返回形如 "ENC(v1,nonce,ct)"
       - raw = json.Marshal(ct)                  // 重新打包为 JSON string
  5. Setting.Put(ctx, key, raw, actor)
  6. audit.Log("setting.update", target_id=hash(key), before=<脱敏 raw>, after=<脱敏 raw>, actor)
```

> 注:audit 的 before/after 也走脱敏(IsEncryptedValue 替换为 `"<encrypted>"`),否则 audit 表本身泄密。

### 4.5 系统设置 GET 列表的脱敏与分组

```
GET /api/admin/settings  →  { groups: [ { name, items: [ {key, value, description, is_sensitive} ] } ] }

handler 流程:
  1. rows = setting.ListAll(ctx)   // 该方法 M1-01 已实现 Store.Get 单 key;此处需要全表
                                    // 若未实现 → 本 spec 在 internal/setting/store.go
                                    // 加一个 ListAll(ctx) ([]Setting, error);仅 admin 调用
  2. for each row:
       if IsEncryptedValue(row.Value) || IsSensitive(row.Key):
         out.Value = `"<encrypted>"`
       else:
         out.Value = row.Value
       out.IsSensitive = IsSensitive(row.Key)
       group = GroupOf(row.Key)
       buckets[group] = append(buckets[group], out)
  3. 按 AllGroups() 顺序输出
```

> §11 会建议给 Store 加 `ListAll`(M1-01 未提供);本 spec 默认 M1-01 已加;若未加,本 spec 内部用 `repo` 直接查 system_settings 表(注入 `*gorm.DB`)。

## 7. 错误码补充

无新增错误码。复用 M1-01 已扩展的:

| Code | 场景 |
|---|---|
| `CodeNotFound` | 公告 id 不存在 / 设置 key 不存在 / 公告对用户不可见 |
| `CodeForbidden` | 用户访问 admin 路由 |
| `CodeMissingParam` | body 缺 title / value 等 |
| `CodeInvalidParam` | level/target 不在枚举 / expires_at < now / 敏感 key 值非字符串 / PATCH notice 含 status 字段 |
| `CodeInternal` | DB / Redis 异常 |

公告未发布或已下架对用户来说**返 404 而不是 403**,避免泄露公告存在性。

### 11.3 给 M1-01 的反向建议(不阻塞本 spec)

本 spec 实施过程中,会让"业务模块自己 Decrypt"以下场景重复出现:

- M1-02 读 `auth.github_oauth.client_secret`、`auth.smtp.password` 时需要 `crypto.Decrypt`
- M1-11 读 `payment.stripe.webhook_secret` 时(M2)需要 `crypto.Decrypt`

**建议**:M1-01 在 `internal/setting/store.go` 后续小版本加一个 helper:

```go
// GetSecret 读取 key,若 value 是 ENC(...) 自动解密为明文 string;
// 若 value 不是字符串或 ENC 形态,返回 ErrNotEncrypted。
// 该方法依赖 crypto.AESGCM,New 时通过 Config.Crypto 注入(M1-01 当前 Config 未含 Crypto)。
func (s *store) GetSecret(ctx context.Context, key string) (string, error)
```

为不阻塞本 spec,**当前先各业务模块自己** `crypto.Decrypt`;`GetSecret` 视为 M1-01 后续 P2 改动。

### 11.4 修改 Application 容器
