# 里程碑 M1-06 计费

## 1. 目标与范围

### 1.1 一句话

**用 Redis Lua 原子三段式(Reserve → Commit → Refund)实现一次代理调用的 quota 扣费,配上钱包余额、定价规则、过期回收三件套**,对内通过 `billing.Biller` / `pricing.Pricing` / `wallet.Store` 接口暴露,对外提供"我的钱包"和"管理定价规则"两组 HTTP 入口。

请求生命周期内,本 spec 负责回答四个问题:

1. **能不能扣?** — `Reserve` 调 `reserve.lua`,根据估算成本检查 Redis 中的 `wallet:user:{id}.balance`,够则锁定;不够即返回 `CodeBalanceInsufficient`
2. **实际扣多少?** — `Commit` 调 `commit.lua`,把"占位 reserved"转成"已消费 consumed",自动退还差额
3. **失败怎么退?** — `Refund` 调 `refund.lua`,整笔回滚到 balance
4. **崩溃漏扣怎么办?** — `reconcile` cron 每 30s 扫 `quota_reservations.status=pending AND expires_at<NOW()`,对每条调 `refund.lua` 兜底并落 `status=expired`

定价模块独立成包(总纲 §3.1 决策):`pricing.Compute / RatioFor / EstimateMax / DefaultMaxOut` 四个方法。匹配顺序定稿:`group_model → model → group → global → model_catalogs default`(总纲 §2.12),同优先级 `id DESC` 最新者胜。

### 1.2 范围

属于本 spec 的(12 件事):

1. **migrations**:`000004_create_wallets`、`000011_create_ledger_entries`、`000012_create_quota_reservations`、`000013_create_pricing_rules`(MySQL + PG 各四份)
2. **`internal/wallet/`**:GORM model + `Store` 接口(`GetOrCreate / Balance / Credit / Snapshot`)+ Redis hash 同步
3. **`internal/pricing/`**:`Pricing` 接口完整实现 — 规则匹配缓存 + `Compute / RatioFor / EstimateMax / DefaultMaxOut`
4. **`internal/billing/`**:`Biller` 接口 — 三阶段 + 异步 ledger worker + reconcile cron + 优雅关停 final drain
5. **Lua 脚本三段**:`internal/billing/lua/{reserve,commit,refund}.lua` — 总纲 §5.1 已定稿,本 spec 用 [M1-01 §3.1 cache.LuaScript](./2026-05-21-里程碑1-01-基础设施增量-设计稿.md#31-cacheluascripts) 加载
6. **`UsageIncrementer` 接口**:在 `internal/billing` 包内定义,wire 时把 [M1-03 token.Store](./2026-05-21-里程碑1-03-API令牌-设计稿.md#31-tokenstore) 注入
7. **HTTP handler(用户侧)**:`GET /api/user/wallet`、`GET /api/user/wallet/ledger`、`GET /api/user/usage`
8. **HTTP handler(管理员侧)**:`GET/POST/PATCH/DELETE /api/admin/pricing/rules`
9. **`wallet.Credit` handler**:暴露给 [M1-02 用户与鉴权](./2026-05-21-里程碑1-02-用户与鉴权-设计稿.md) 的 `POST /api/admin/users/{id}/quota` 入口调用(本 spec 提供 service 方法,不写该路由)
10. **错误码**:复用 M1-01 已有 `CodeBalanceInsufficient / CodeReservationNotFound / CodeReservationCommitted`(本 spec 不新增)
11. **审计事件**:`wallet.credit / pricing_rule.create / pricing_rule.update / pricing_rule.delete / reservation.expired / ledger.write_failed`
12. **可观测指标**(prom counter,埋点桩位):`billing_reserve_total{result=ok|insufficient|error}`、`billing_commit_total`、`billing_refund_total`、`billing_ledger_write_failures_total`、`billing_reservation_expired_total`

### 1.3 排除项(明确边界)

- ❌ **在线支付**(Stripe / 支付宝 / 微信)— 全部 M2;本 spec `Credit` 只服务"管理员加额度"和"手动充值审批通过后"(M1-11)和"兑换码兑换"(M1-11)三个入口
- ❌ **部门钱包 / 部门预算** — `owner_type` 字段保留 `dept` 占位,M1 实现仅认 `user`;M3 加部门预算扣减链路
- ❌ **健康分定价 / 渠道动态溢价** — M3
- ❌ **限流维度限额** — RPM/TPM 在 [M1-07 限流](./2026-05-21-里程碑1-总体设计纲要.md#46-ratelimiter);本 spec 不参与
- ❌ **请求/消费日志写入** — 在 [M1-08 日志与统计](./2026-05-21-里程碑1-总体设计纲要.md);本 spec 仅在 commit 后调 `log.Store.Write`(由 relay 编排,不在 billing 内部)
- ❌ **流式 tokenize 与上游 usage 对齐细节** — 在 [M1-04 适配器层](./2026-05-21-里程碑1-总体设计纲要.md) + [M1-05 渠道调度](./2026-05-21-里程碑1-总体设计纲要.md);本 spec 只提供 `Pricing.EstimateMax` 与 `Pricing.Compute`
- ❌ **`/api/admin/users/{id}/quota` 路由 handler 本身** — 由 [M1-02 用户与鉴权](./2026-05-21-里程碑1-02-用户与鉴权-设计稿.md) 承担;本 spec 仅暴露 `Wallet.Credit` 与 `wallet.Service.AdminCredit` 包级方法

## 3. 接口契约

### 3.1 Wallet(总纲 §4.10)

签名总纲已定。本 spec 完整化:

```go
// internal/wallet/store.go
package wallet

import (
    "context"
    "encoding/json"
    "time"

    "github.com/proapi/proapi/internal/audit"
    "github.com/proapi/proapi/internal/util/clock"
    "github.com/proapi/proapi/internal/util/idgen"
    "github.com/redis/go-redis/v9"
    "go.uber.org/zap"
    "gorm.io/gorm"
)

const (
    OwnerTypeUser = "user"
    OwnerTypeDept = "dept" // M3,M1 不允许使用
)

type Store interface {
    // GetOrCreate 取一个 wallet;不存在则插入 quota_balance=0 行,自动初始化 Redis hash。
    //   - 错误:apierr.CodeDatabase
    //   - 并发安全:UNIQUE (owner_type, owner_id) + ON DUPLICATE KEY / ON CONFLICT 兜底
    GetOrCreate(ctx context.Context, ownerType string, ownerID int64) (*Wallet, error)

    // Balance 取实时余额。
    //   - 优先 Redis hash 字段 balance
    //   - miss 时回源 DB 并回填 Redis(TTL = 永久,由 Pub/Sub 维护一致)
    //   - 错误:apierr.CodeCache / CodeDatabase
    Balance(ctx context.Context, walletID int64) (int64, error)

    // Credit 给钱包加额度(管理员加额度 / 兑换码 / 手动充值审批通过)。
    //   - DB 事务:UPDATE wallets SET balance += ?, total_recharged += ?, version += 1 + INSERT ledger_entries
    //   - 成功后 Redis HINCRBY balance += amount 同步
    //   - 失败:DB 错误回滚,Redis 不动
    //   - 审计:action="wallet.credit"
    //   - amount 必须 > 0;<= 0 返回 CodeInvalidParam
    Credit(ctx context.Context, walletID int64, amount int64, refType string, refID *int64, desc string, actor int64) error

    // Snapshot 从 DB 全量读取(用于 ledger 页 / 钱包详情)。
    //   - 不读 Redis,DB 是真源
    Snapshot(ctx context.Context, walletID int64) (*Wallet, error)

    // ByOwner 按 owner 取 wallet(等价于 GetOrCreate 但不创建)。
    //   - 不存在返回 nil, apierr.CodeNotFound
    ByOwner(ctx context.Context, ownerType string, ownerID int64) (*Wallet, error)

    // Close 关停内部资源(本 spec wallet 包暂无后台 goroutine,占位以保持模式一致)。
    Close() error
}

type Config struct {
    DB    *gorm.DB
    Cache *redis.Client
    Log   *zap.Logger
    Clock clock.Clock
    IDGen *idgen.Generator
    Audit audit.Logger
}

func New(cfg Config) (Store, error)
```

Redis 钱包 key 定稿:

```
wallet:user:{user_id}              hash{balance, reserved, consumed}
                                   永久 TTL,由 GetOrCreate 初始化、Credit 同步、Lua 维护
```

> 决策:wallet hash **不设 TTL**。理由 — Lua 路径要求 hash 永远存在,TTL 过期会导致 `reserve.lua` 见到 balance="0" 误报余额不足。失效路径只有"管理员清账"(M2),M1 没有删除入口。

```go
// internal/billing/biller.go
package billing

import (
    "context"
    "time"
)

type Biller interface {
    // Reserve 预扣 quota。
    //   - 余额不足返回 apierr.CodeBalanceInsufficient
    //   - estCost <= 0 返回 apierr.CodeInvalidParam
    //   - 成功:Redis Lua 扣减 + DB INSERT quota_reservations(status=pending)
    //   - DB INSERT 失败 → 立即调 refund.lua 回滚 Redis + 记 error_log + 返回 CodeDatabase
    //   - reservation id 用 UUID v4(全集群无依赖)
    Reserve(ctx context.Context, in ReserveInput) (reservationID string, err error)

    // Commit 用实际成本提交。
    //   - actualCost <= reserved:Lua 把差额退回 balance
    //   - actualCost > reserved:返回 apierr.CodeInternal(理论不可达;estCost 应为上限)
    //   - rid 不存在 / 状态非 pending:CodeReservationNotFound
    //   - rid 已 committed:CodeReservationCommitted
    //   - 成功:Lua 改 Redis + 异步队列推 ledger event + 异步调 UsageIncrementer
    //   - 同步返回不等异步 worker
    Commit(ctx context.Context, reservationID string, actualCost int64) error

    // Refund 完整退还(请求失败 / 上游 401 / 客户端取消)。
    //   - rid 不存在:CodeReservationNotFound
    //   - 已 committed:CodeReservationCommitted
    //   - 已 refunded / expired:幂等返回 nil
    //   - 成功:Lua 改 Redis + DB UPDATE status=refunded + 异步推一条 refund ledger event
    Refund(ctx context.Context, reservationID string) error

    // BindRequestID 在 reservation 行上挂请求 id(由 relay 在调上游前调)。
    //   - 不影响计费,仅供 ledger 关联日志使用
    //   - 失败仅日志,不返回 error
    BindRequestID(ctx context.Context, reservationID string, requestID int64)

    // Close 关停内部 goroutine。
    //   - 关 ledger worker channel,等 worker drain 完
    //   - 关 reconcile cron
    //   - 阻塞至所有未写入 ledger 全部成功写入(最多重试 3 次,失败计入 metric)
    Close() error
}

    TokenID   int64
    EstCost   int64
    RequestID *int64        // 可选,reserve 时可填 0,Commit 前由 relay 调 BindRequestID 填入
    TTL       time.Duration // 可选,0 = 用 setting.billing.reserve_ttl_seconds
}
```

### 4.1 三段式 Lua(总纲 §5.1 已定稿,本节复述加载路径)

```go
// internal/billing/lua_loader.go
package billing

import (
    _ "embed"

    "github.com/proapi/proapi/internal/cache"

//go:embed lua/reserve.lua
var luaReserveSrc string

//go:embed lua/commit.lua
var luaCommitSrc string

//go:embed lua/refund.lua
var luaRefundSrc string

type luaScripts struct {
    reserve *cache.LuaScript
    commit  *cache.LuaScript
    refund  *cache.LuaScript
}

func loadLua(ctx context.Context, rdb *redis.Client) (*luaScripts, error) {
    r, err := cache.LoadScript(ctx, rdb, "billing.reserve", luaReserveSrc)
    if err != nil { return nil, fmt.Errorf("load reserve: %w", err) }
    c, err := cache.LoadScript(ctx, rdb, "billing.commit", luaCommitSrc)

    return &luaScripts{reserve: r, commit: c, refund: f}, nil
```

### 4.2 Reserve 完整路径

```go
// internal/billing/reserve.go
package billing

import (
    "context"
    "fmt"

    "github.com/google/uuid"
    "github.com/proapi/proapi/pkg/apierr"
)

func (b *biller) Reserve(ctx context.Context, in ReserveInput) (string, error) {
    if in.EstCost <= 0 {
        return "", apierr.New(apierr.CodeInvalidParam, "est_cost must be > 0")
    }
    if in.UserID == 0 {
        return "", apierr.New(apierr.CodeInvalidParam, "user_id required")
    }

    // 1. 取钱包(GetOrCreate 保证存在 + Redis hash 初始化)
    w, err := b.wallet.GetOrCreate(ctx, wallet.OwnerTypeUser, in.UserID)
    if err != nil {
        b.metrics.reserveErrors.Inc()
        return "", apierr.Wrap(err)
    }

    // 2. 生成 reservation id(UUID v4)
    rid := uuid.NewString()

    // 3. 决定 TTL
    ttl := in.TTL
    if ttl == 0 {
        ttl = time.Duration(b.setting.GetInt(ctx, "billing.reserve_ttl_seconds", 600)) * time.Second
    }

    // 4. Lua reserve
    walletKey := fmt.Sprintf("wallet:user:%d", in.UserID)
    rsvKey := fmt.Sprintf("reservation:%s", rid)
    res, err := b.lua.reserve.RunInts(ctx,
        []string{walletKey, rsvKey},
        in.EstCost, int(ttl.Seconds()),
    )
    if err != nil {
        b.metrics.reserveErrors.Inc()
        return "", apierr.New(apierr.CodeCache, "reserve lua: "+err.Error())
    }
    // res = [ok, balance_after]
    if res[0] == 0 {
        b.metrics.reserveInsufficient.Inc()
        return "", apierr.New(apierr.CodeBalanceInsufficient,
            fmt.Sprintf("insufficient balance: need %d, have %d", in.EstCost, res[1]))
    }

    // 5. DB INSERT quota_reservations
    now := b.clock.Now().UTC()
    expiresAt := now.Add(ttl)
    rsv := &Reservation{
        ID:            rid,
        WalletID:      w.ID,
        UserID:        in.UserID,
        TokenID:       in.TokenID,
        RequestID:     in.RequestID,
        ReservedQuota: in.EstCost,
        Status:        StatusPending,
        CreatedAt:     now,
        ExpiresAt:     expiresAt,
    }
    if err := b.db.WithContext(ctx).Create(rsv).Error; err != nil {
        // DB 失败 → 立即调 refund.lua 回滚 Redis(关键:避免 Redis 锁定但 DB 无记录的脏数据)
        if rerr := b.refundLua(ctx, in.UserID, rid); rerr != nil {
            b.log.Error("billing: reserve DB failed AND refund failed (LEAK)",
                zap.Error(err), zap.NamedError("refund_err", rerr),
                zap.String("rid", rid), zap.Int64("user_id", in.UserID),
                zap.Int64("est_cost", in.EstCost))
            // 计入泄漏指标,运维介入
            b.metrics.reserveLeaks.Inc()
        }
        b.metrics.reserveErrors.Inc()
        return "", apierr.New(apierr.CodeDatabase, "reserve insert: "+err.Error())
    }

    b.metrics.reserveOK.Inc()
    return rid, nil
}
```

**关键决策清单**(本算法):

- **顺序**:先 Lua 成功,后 DB INSERT。理由:Lua 是原子操作,失败时无副作用;DB 失败需要补偿但概率小
- **DB 失败的补偿**:调 `refund.lua` 同步回滚,失败则记 error_log + metric `billing_reserve_leaks_total`(运维介入,需要 reconcile cron 兜底 — 但本场景 reservation 行不存在,cron 扫不到,所以 leak 永久存在;接受这个 trade-off 以避免更复杂的两阶段提交)
- **reservation id 用 UUID v4**:全集群无依赖,reservation 数量虽大但 lifecycle 短(10 分钟内 expired),不挤压 Snowflake 段
- **`in.RequestID` 可为 nil**:relay 先 reserve 后才写 request_logs(请求日志在收到响应后才落),所以 reserve 时 request_id 还未知;由 `BindRequestID` 在请求结束前补上

### 4.3 Commit 完整路径

```go
// internal/billing/commit.go
package billing

import (
    "context"
    "fmt"

    "github.com/proapi/proapi/pkg/apierr"
)

func (b *biller) Commit(ctx context.Context, rid string, actualCost int64) error {
    if actualCost < 0 {
        return apierr.New(apierr.CodeInvalidParam, "actual_cost must be >= 0")
    }

    // 1. 先取 reservation(用于路由 wallet key + 状态校验 + token_id 等元信息)
    var rsv Reservation
    if err := b.db.WithContext(ctx).Where("id = ?", rid).First(&rsv).Error; err != nil {
        if errors.Is(err, gorm.ErrRecordNotFound) {
            return apierr.New(apierr.CodeReservationNotFound, "reservation not found: "+rid)
        }
        return apierr.New(apierr.CodeDatabase, err.Error())
    }
    switch rsv.Status {
    case StatusCommitted:
        return apierr.New(apierr.CodeReservationCommitted, "already committed: "+rid)
    case StatusRefunded, StatusExpired:
        return apierr.New(apierr.CodeReservationNotFound,
            fmt.Sprintf("reservation %s is %s, cannot commit",
                rid, statusName(rsv.Status)))
    }
    if actualCost > rsv.ReservedQuota {
        b.log.Error("billing: actual > reserved (BUG in EstimateMax)",
            zap.String("rid", rid),
            zap.Int64("reserved", rsv.ReservedQuota),
            zap.Int64("actual", actualCost))
        return apierr.New(apierr.CodeInternal,
            fmt.Sprintf("actual %d > reserved %d", actualCost, rsv.ReservedQuota))
    }

    // 2. Lua commit
    walletKey := fmt.Sprintf("wallet:user:%d", rsv.UserID)
    rsvKey := fmt.Sprintf("reservation:%s", rid)
    res, err := b.lua.commit.RunInts(ctx, []string{walletKey, rsvKey}, actualCost)
    if err != nil {
        b.metrics.commitErrors.Inc()
        return apierr.New(apierr.CodeCache, "commit lua: "+err.Error())
    }
    // res = [ok, refund]
    if res[0] == -1 {
        // Redis 已不存在(可能 TTL 过期或 reconcile 已扫):仍允许 DB 提交,但记 warning
        b.log.Warn("billing: commit redis miss, DB-only path",
            zap.String("rid", rid))
        // 不返回错误 — DB 已落 reservation,继续标记 committed 即可
    } else if res[0] == -2 {
        // 不应发生(代码已在第 1 步拦截 actualCost > reserved)
        return apierr.New(apierr.CodeInternal, "commit lua: actual > reserved")
    }

    // 3. DB UPDATE quota_reservations
    now := b.clock.Now().UTC()
    if err := b.db.WithContext(ctx).Model(&Reservation{}).
        Where("id = ? AND status = ?", rid, StatusPending).
        Updates(map[string]any{
            "status":           StatusCommitted,
            "committed_quota":  actualCost,
            "committed_at":     &now,
        }).Error; err != nil {
        b.log.Error("billing: commit DB update failed (Redis already debited)",
            zap.Error(err), zap.String("rid", rid))
        // 不回滚 Lua — 那会导致重复扣 / 错位;接受短暂不一致由 reconcile 修
        b.metrics.commitDBErrors.Inc()
        return apierr.New(apierr.CodeDatabase, "commit update: "+err.Error())
    }

    // 4. 异步推 ledger event(channel 满会阻塞 → 接受延迟换数据一致性)
    b.ledgerCh <- wallet.LedgerEvent{
        WalletID:    rsv.WalletID,
        UserID:      rsv.UserID,
        Direction:   "debit",
        AmountQuota: actualCost,
        RefType:     "usage",
        RefID:       rsv.RequestID,
        Description: fmt.Sprintf("usage commit rid=%s", rid),
        OccurredAt:  now,
    }

    // 5. 异步通知 token 用量(M1-03 IncrementUsage 内部已经 batch)
    if b.usage != nil && rsv.TokenID > 0 {
        b.usage.IncrementUsage(rsv.TokenID, actualCost)
    }

    b.metrics.commitOK.Inc()
    return nil
}
```

**关键决策清单**(本算法):

- **第 1 步 SELECT reservation**:必须先取出 user_id 才知道走哪个 wallet hash;同时校验状态防止幂等问题
- **Lua res[0]==-1 的处理**:Redis miss 但 DB 还有 → 仍 commit DB,只记 warning。理由:Redis TTL 过期时 wallet hash 的 `reserved` 字段没回退,但 reconcile cron 会扫到 expired reservation 自动 refund(此时 Lua 会让 `reserved -= reserved`,把"已逻辑离开"的额度从 reserved 计数器中清掉)。这条 commit 不影响一致性
- **第 3 步 UPDATE 加 `WHERE status = pending`**:保证幂等;并发 commit 同一 rid 只有一个 UPDATE 命中 0 行
- **`ledgerCh <- event` 阻塞而非丢弃**:cap=1024 满了就 block;优先数据一致而非接口延迟。压力大时 commit 会变慢,运维通过 metric 知道
- **不阻塞响应**:`b.usage.IncrementUsage` 已经是 token 包内部 batch 异步,本调用本身就是非阻塞;ledger event 推送是 send 到 buffered channel,正常情况 < 1µs
- **DB UPDATE 失败不回滚 Lua**:已扣的余额不应该退回(因为本次请求确实消耗成功,response 已经发回客户端);接受 reservation 表 status 仍为 pending 的不一致,reconcile cron 30s 内会触发 refund 路径 — 但 refund 会反向扣 reserved,导致钱包账面错乱。**修正**:DB UPDATE 失败时,把 reservation 的"事实已扣"状态再写一条直接 ledger 事件(`debit, ref_type=usage`),让 ledger 与 wallet 表的累计字段最终一致;reservation 行的 pending → expired 转换会被 reconcile 触发的 refund.lua 处理(Redis 已无 reservation key,refund.lua 返回 -1,不动 wallet hash;DB UPDATE expired 成功)。这条路径最终一致性可达成

### 4.4 Refund 完整路径

```go
// internal/billing/refund.go
package billing

func (b *biller) Refund(ctx context.Context, rid string) error {
    var rsv Reservation
    if err := b.db.WithContext(ctx).Where("id = ?", rid).First(&rsv).Error; err != nil {
        if errors.Is(err, gorm.ErrRecordNotFound) {
            return apierr.New(apierr.CodeReservationNotFound, rid)
        }
        return apierr.New(apierr.CodeDatabase, err.Error())
    }
    switch rsv.Status {
    case StatusCommitted:
        return apierr.New(apierr.CodeReservationCommitted, rid)
    case StatusRefunded, StatusExpired:
        return nil // 幂等
    }

    walletKey := fmt.Sprintf("wallet:user:%d", rsv.UserID)
    rsvKey := fmt.Sprintf("reservation:%s", rid)
    res, err := b.lua.refund.RunInts(ctx, []string{walletKey, rsvKey})
    if err != nil {
        b.metrics.refundErrors.Inc()
        return apierr.New(apierr.CodeCache, err.Error())
    }
    // res = [ok, refunded]
    // ok=-1(Redis miss)在 reconcile 路径常见;不视为错误

    now := b.clock.Now().UTC()
    if err := b.db.WithContext(ctx).Model(&Reservation{}).
        Where("id = ? AND status = ?", rid, StatusPending).
        Updates(map[string]any{
            "status":       StatusRefunded,
            "committed_at": &now,
        }).Error; err != nil {
        return apierr.New(apierr.CodeDatabase, err.Error())
    }

    // 异步推 refund ledger event(可选;refund 通常用于失败请求,无 ledger 影响平衡)
    // 决策:仍写一条 credit ledger,direction=credit,ref_type=refund,便于审计追溯
    b.ledgerCh <- wallet.LedgerEvent{
        WalletID:    rsv.WalletID,
        UserID:      rsv.UserID,
        Direction:   "credit",
        AmountQuota: rsv.ReservedQuota,
        RefType:     "refund",
        RefID:       refID(rsv.ID), // 用 reservation id 转 int64 hash;实际改用 *int64 = nil(因 reservation id 是 UUID 而非 int64)
        Description: fmt.Sprintf("refund rid=%s", rid),
        OccurredAt:  now,
    }
    b.metrics.refundOK.Inc()
    return nil
}
```

> **决策**:refund ledger 的 `ref_id` 字段不能存 UUID(int64 列存不下)— 写 nil,在 `description` 字段保留 `rid=...` 供审计;或在 schema 增 `ref_uuid VARCHAR(36)` 列。本 spec 采用前者(`description` 含 rid),避免修改 ledger schema。

### 4.6 异步 ledger worker

```go
// internal/billing/ledger.go
package billing

import (
    "context"
    "time"

    "github.com/proapi/proapi/internal/wallet"
)

func (b *biller) runLedgerWorker() {
    defer close(b.ledgerWorkerDone)

    batch := make([]wallet.LedgerEvent, 0, b.ledgerBatchSize)
    ticker := b.clock.NewTicker(b.ledgerFlushEvery)
    defer ticker.Stop()

    flush := func() {
        if len(batch) == 0 { return }
        // 按 wallet_id 分组(一个 batch 可能涉及多个钱包)
        groups := groupByWallet(batch)
        for _, g := range groups {
            if err := b.applyLedgerWithRetry(context.Background(), g); err != nil {
                b.metrics.ledgerFailures.Add(float64(len(g)))
                b.audit.Log(context.Background(), audit.Entry{
                    Action:     "ledger.write_failed",
                    TargetType: "wallet",
                    TargetID:   &g[0].WalletID,
                    After:      mustJSON(map[string]any{
                        "events":     len(g),
                        "last_error": err.Error(),
                    }),
                })
                b.log.Error("billing: ledger flush failed permanently",
                    zap.Error(err), zap.Int("count", len(g)))
            }
        }
        batch = batch[:0]
    }

    for {
        select {
        case ev, ok := <-b.ledgerCh:
            if !ok {
                flush() // 关停 final drain
                return
            }
            batch = append(batch, ev)
            if len(batch) >= b.ledgerBatchSize {
                flush()
            }
        case <-ticker.C():
            flush()
        }
    }
}

// applyLedgerWithRetry 调用 WalletWriter,失败重试 3 次,指数退避。
func (b *biller) applyLedgerWithRetry(ctx context.Context, events []wallet.LedgerEvent) error {
    var lastErr error
    backoff := 100 * time.Millisecond
    for attempt := 0; attempt < 3; attempt++ {
        if attempt > 0 {
            b.clock.Sleep(backoff)
            backoff *= 2
        }
        if err := b.wallet.ApplyLedgerBatch(ctx, events); err == nil {
            return nil
        } else {
            lastErr = err
            b.log.Warn("billing: ledger apply failed, retrying",
                zap.Error(err), zap.Int("attempt", attempt+1))
        }
    }
    return lastErr
}
```

`wallet.Store.ApplyLedgerBatch` 实现细节(在 wallet 包):

```go
// internal/wallet/credit.go (节选)

// ApplyLedgerBatch 单事务写入一批 ledger + 同步钱包累计字段。
//   - events 必须同 wallet_id;调用方负责分组
//   - 事务内:
//       SELECT wallet WHERE id = ? FOR UPDATE  -- 取最新 balance
//       FOR each event: INSERT ledger(balance_after = current ± amount)
//                       current ± amount
//       UPDATE wallets SET quota_balance = current, quota_total_consumed += sum_debit,
//                          quota_total_recharged += sum_credit(usage 除外), version += 1
//   - Redis hash 不需要在此同步(Lua 已经更新 balance 字段)
func (s *store) ApplyLedgerBatch(ctx context.Context, events []LedgerEvent) error {
    if len(events) == 0 { return nil }
    walletID := events[0].WalletID
    return s.db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
        var w Wallet
        if err := tx.Clauses(clause.Locking{Strength: "UPDATE"}).
            Where("id = ?", walletID).First(&w).Error; err != nil {
            return err
        }
        cur := w.QuotaBalance
        var sumDebit, sumCredit int64
        rows := make([]LedgerEntry, 0, len(events))
        for _, ev := range events {
            if ev.Direction == "debit" {
                cur -= ev.AmountQuota
                sumDebit += ev.AmountQuota
            } else {
                cur += ev.AmountQuota
                sumCredit += ev.AmountQuota
            }
            rows = append(rows, LedgerEntry{
                ID:           s.idgen.Generate(),
                WalletID:     ev.WalletID,
                Direction:    ev.Direction,
                AmountQuota:  ev.AmountQuota,
                Currency:     w.Currency,
                RefType:      ev.RefType,
                RefID:        ev.RefID,
                BalanceAfter: cur,
                Description:  ev.Description,
                CreatedAt:    ev.OccurredAt,
            })
        }
        if err := tx.CreateInBatches(&rows, 100).Error; err != nil {
            return err
        }
        // 更新 wallet 累计字段
        updates := map[string]any{
            "quota_balance":         cur,
            "quota_total_consumed":  gorm.Expr("quota_total_consumed + ?", sumDebit),
            "version":               gorm.Expr("version + 1"),
            "updated_at":            s.clock.Now().UTC(),
        }
        // 注意:credit 路径(refund 也是 credit)不增 recharged
        // recharged 只由 Credit() 显式调用时累加
        if err := tx.Model(&Wallet{}).Where("id = ?", walletID).Updates(updates).Error; err != nil {
            return err
        }
        return nil
    })
}
```

> 决策:`quota_total_recharged` 只由 `Wallet.Credit()` 显式增加;ledger worker 不维护它(refund 不算"充值",虽然 direction=credit)。

```go
// internal/billing/reconcile.go
package billing

import (
    "context"
    "time"

func (b *biller) runReconciler() {
    defer close(b.reconcileDone)

    interval := time.Duration(
        b.setting.GetInt(context.Background(), "billing.reconcile_interval_seconds", 30),
    ) * time.Second
    ticker := b.clock.NewTicker(interval)
    defer ticker.Stop()

    for {
        select {
        case <-ticker.C():
            if n, err := b.reconcileOnce(context.Background()); err != nil {
                b.log.Warn("billing: reconcile failed", zap.Error(err))
            } else if n > 0 {
                b.log.Info("billing: reconciled expired reservations", zap.Int("count", n))
            }
        case <-b.reconcileStop:
            return
        }
    }
}

// reconcileOnce 扫一批过期 reservation,挨条 refund.lua + UPDATE status=expired。
func (b *biller) reconcileOnce(ctx context.Context) (int, error) {
    var rows []Reservation
    if err := b.db.WithContext(ctx).
        Where("status = ? AND expires_at < ?", StatusPending, b.clock.Now().UTC()).
        Order("expires_at ASC").
        Limit(100).
        Find(&rows).Error; err != nil {
        return 0, err
    }
    for _, r := range rows {
        if err := b.expireOne(ctx, &r); err != nil {
            b.log.Warn("billing: expire reservation failed",
                zap.Error(err), zap.String("rid", r.ID))
            continue
        }
        b.metrics.expired.Inc()
    }
    return len(rows), nil
}

func (b *biller) expireOne(ctx context.Context, r *Reservation) error {
    walletKey := fmt.Sprintf("wallet:user:%d", r.UserID)
    rsvKey := fmt.Sprintf("reservation:%s", r.ID)
    // refund.lua 幂等:Redis miss 时返回 -1,不影响 DB UPDATE
    _, err := b.lua.refund.RunInts(ctx, []string{walletKey, rsvKey})
    if err != nil {
        return err
    }
    now := b.clock.Now().UTC()
    if err := b.db.WithContext(ctx).Model(&Reservation{}).
        Where("id = ? AND status = ?", r.ID, StatusPending).
        Updates(map[string]any{
            "status":       StatusExpired,
            "committed_at": &now,
        }).Error; err != nil {
        return err
    }

    // 推 credit ledger event(把过期的 reserved 还回 balance)
    b.ledgerCh <- wallet.LedgerEvent{
        WalletID:    r.WalletID,
        UserID:      r.UserID,
        Direction:   "credit",
        AmountQuota: r.ReservedQuota,
        RefType:     "refund",
        RefID:       nil,
        Description: fmt.Sprintf("reservation expired rid=%s", r.ID),
        OccurredAt:  now,
    }
    b.audit.Log(ctx, audit.Entry{
        Action:     "reservation.expired",
        TargetType: "quota_reservation",
        // target_id 是 int64,reservation 是 UUID;此处填 user_id 作为替代,在 description 含 rid
        TargetID:   &r.UserID,
        After: mustJSON(map[string]any{
            "rid":     r.ID,
            "amount":  r.ReservedQuota,
            "expired_at": now,
        }),
    })
    return nil
}
```

> **决策**:reconcile 单次最多扫 100 条,频率 30s。如果系统压力大有大量 expired,需要多个 tick 才能消化 — 接受这个 trade-off,避免单次扫描卡死 DB。M2 可增加 worker 并发度。

### 4.8 Pricing 匹配算法

```go
// internal/pricing/match.go
package pricing

import (
    "strings"

    "github.com/proapi/proapi/internal/channel"
)

// matchRule 按"最精确者胜 + priority 数字小者胜 + 同 priority id desc"顺序找规则。
//
// 顺序:
//   group_model(group_id, model 都匹配) → model(只 model) → group(只 group_id) → global(空)
//
// 每个层级内按 (priority ASC, id DESC) 排;层级间按上面顺序。
func (p *pricing) matchRule(model string, groupID int64) *Rule {
    rules := p.cache.All() // 本地缓存的所有 enabled rule
    // 1. group_model
    if r := pickBest(rules, func(r *Rule) bool {
        return r.Scope == ScopeGroupModel &&
            r.GroupID != nil && *r.GroupID == groupID &&
            r.Model != nil && modelMatch(*r.Model, model)
    }); r != nil { return r }
    // 2. model
    if r := pickBest(rules, func(r *Rule) bool {
        return r.Scope == ScopeModel &&
            r.Model != nil && modelMatch(*r.Model, model)
    }); r != nil { return r }
    // 3. group
    if r := pickBest(rules, func(r *Rule) bool {
        return r.Scope == ScopeGroup &&
            r.GroupID != nil && *r.GroupID == groupID
    }); r != nil { return r }
    // 4. global
    return pickBest(rules, func(r *Rule) bool {
        return r.Scope == ScopeGlobal
    })
}

// pickBest 按 priority ASC, id DESC 选第一个匹配。
func pickBest(rs []*Rule, pred func(*Rule) bool) *Rule {
    var best *Rule
    for _, r := range rs {
        if !pred(r) { continue }
        if best == nil { best = r; continue }
        if r.Priority < best.Priority ||
            (r.Priority == best.Priority && r.ID > best.ID) {
            best = r
        }
    }
    return best
}

// modelMatch 支持末尾 "*" 通配(与 token 模型白名单同语义,M1-03 §4)。
func modelMatch(pattern, model string) bool {
    if strings.HasSuffix(pattern, "*") {
        return strings.HasPrefix(model, strings.TrimSuffix(pattern, "*"))
    }
    return pattern == model
}
```

`pricing.cache` 数据结构:`sync.Map[ruleID]*Rule` + 启动时一次性 SELECT 全量 + Pub/Sub `proapi:pricing:invalidate` 失效后重载。规则数量预期 < 1k,内存里全量持有,O(N) 扫描可接受。

### 4.9 Compute 与 RatioFor

```go
// internal/pricing/compute.go
package pricing

import (
    "context"

    "github.com/proapi/proapi/internal/channel"
    "github.com/proapi/proapi/internal/group"
)

func (p *pricing) RatioFor(ctx context.Context, model string, groupID int64, ch *channel.Channel) Ratios {
    // 1. 默认:模型字典
    catalog := p.lookupCatalog(model)
    in := catalog.DefaultInputRatio
    out := catalog.DefaultOutputRatio
    cached := catalog.DefaultCachedRatio
    reasoning := catalog.DefaultReasoningRatio
    if cached == 0 { cached = in }       // NULL → 按 input 同价
    if reasoning == 0 { reasoning = out } // NULL → 按 output 同价

    // 2. 渠道 ModelOverride
    if ch != nil {
        if mo, ok := ch.ModelOverrides[model]; ok {
            if mo.InputRatio != nil { in = *mo.InputRatio }
            if mo.OutputRatio != nil { out = *mo.OutputRatio }
            if mo.CachedRatio != nil { cached = *mo.CachedRatio }
            if mo.ReasoningRatio != nil { reasoning = *mo.ReasoningRatio }
        }
    }

    // 3. pricing_rules 匹配(从最不精确到最精确,后者覆盖前者)
    if r := p.matchRule(model, groupID); r != nil {
        if r.InputRatio != nil { in = *r.InputRatio }
        if r.OutputRatio != nil { out = *r.OutputRatio }
        if r.CachedRatio != nil { cached = *r.CachedRatio }
        if r.ReasoningRatio != nil { reasoning = *r.ReasoningRatio }
    }

    // 4. 分组倍率
    gr := p.groupRatio(groupID)

    return Ratios{
        Input:     in,
        Output:    out,
        Cached:    cached,
        Reasoning: reasoning,
        Group:     gr,
    }
}

func (p *pricing) Compute(ctx context.Context, in ComputeInput) ComputeResult {
    rt := p.RatioFor(ctx, in.Model, in.GroupID, in.Channel)
    // 公式:quota = (in*r_in + out*r_out + cached*r_cached + reasoning*r_reasoning) * group_ratio
    rawIn := float64(in.InputTokens) * rt.Input
    rawOut := float64(in.OutputTokens) * rt.Output
    rawCached := float64(in.CachedTokens) * rt.Cached
    rawReasoning := float64(in.ReasoningTokens) * rt.Reasoning
    sum := (rawIn + rawOut + rawCached + rawReasoning) * rt.Group
    // 向上取整为 quota 整数(不丢精度);最小 1(只要有 token 就至少扣 1)
    quota := int64(math.Ceil(sum))
    if quota == 0 && (in.InputTokens+in.OutputTokens) > 0 {
        quota = 1
    }
    return ComputeResult{Quota: quota, Ratios: rt}
}

func (p *pricing) EstimateMax(ctx context.Context, model string, in EstimateInput) int64 {
    rt := p.RatioFor(ctx, model, 0, nil) // 估算时 group 与 channel 未知;用默认
    if in.BillingGroupRatio > 0 {
        rt.Group = in.BillingGroupRatio
    }
    maxOut := in.MaxOutTokens
    if maxOut <= 0 {
        maxOut = p.DefaultMaxOut(ctx, model)
    }
    raw := float64(in.InputTokens)*rt.Input + float64(maxOut)*rt.Output
    return int64(math.Ceil(raw * rt.Group))
}

func (p *pricing) DefaultMaxOut(ctx context.Context, model string) int {
    catalog := p.lookupCatalog(model)
    if catalog.MaxInputTokens > 0 {
        // 启发式:max_out 上限 = 0.5 * max_input,封顶 4096
        v := catalog.MaxInputTokens / 2
        if v > 4096 { v = 4096 }
        return v
    }
    return 4096
}
```

**Channel 为 nil 时**:`RatioFor` 跳过 ModelOverride 步骤,直接用 model_catalogs default + rule 覆盖。这就是 `Reserve` 预扣时的场景(尚未选渠道)。`Commit` 时已经选好渠道,会再 `Compute` 一次取精确值。

```go
// internal/pricing/service.go
package pricing

func (s *service) Create(ctx context.Context, in CreateInput, actor int64) (*Rule, error) {
    if err := validateInput(&in); err != nil {
        return nil, err
    }
    r := &Rule{
        ID:             s.idgen.Generate(),
        Scope:          in.Scope,
        GroupID:        in.GroupID,
        Model:          in.Model,
        InputRatio:     in.InputRatio,
        OutputRatio:    in.OutputRatio,
        CachedRatio:    in.CachedRatio,
        ReasoningRatio: in.ReasoningRatio,
        Priority:       in.Priority,
        Status:         in.Status,
        CreatedAt:      s.clock.Now().UTC(),
        UpdatedAt:      s.clock.Now().UTC(),
    }
    if err := s.db.WithContext(ctx).Create(r).Error; err != nil {

    }
    s.cache.Refresh(ctx)
    s.publishInvalidate(ctx)
    s.audit.Log(ctx, audit.Entry{
        Action:     "pricing_rule.create",
        ActorID:    &actor,
        TargetType: "pricing_rule",
        TargetID:   &r.ID,
        After:      mustJSON(r),
    })
    return r, nil

func validateInput(in *CreateInput) error {
    // scope 合法
    switch in.Scope {
    case ScopeGlobal:
        if in.GroupID != nil || in.Model != nil {
            return apierr.New(apierr.CodeInvalidParam, "global scope must not set group_id/model")
        }
    case ScopeGroup:
        if in.GroupID == nil || in.Model != nil {
            return apierr.New(apierr.CodeInvalidParam, "group scope requires group_id and forbids model")
        }
    case ScopeModel:
        if in.Model == nil || in.GroupID != nil {
            return apierr.New(apierr.CodeInvalidParam, "model scope requires model and forbids group_id")
        }
    case ScopeGroupModel:
        if in.GroupID == nil || in.Model == nil {
            return apierr.New(apierr.CodeInvalidParam, "group_model scope requires both group_id and model")
        }
    default:
        return apierr.New(apierr.CodeInvalidParam, "unknown scope: "+in.Scope)
    }
    // 至少一个 ratio 非 nil
    if in.InputRatio == nil && in.OutputRatio == nil &&
        in.CachedRatio == nil && in.ReasoningRatio == nil {
        return apierr.New(apierr.CodeInvalidParam, "at least one ratio must be set")
    }
    // ratio 非负
    for _, r := range []*float64{in.InputRatio, in.OutputRatio, in.CachedRatio, in.ReasoningRatio} {
        if r != nil && *r < 0 {
            return apierr.New(apierr.CodeInvalidParam, "ratio must be >= 0")
        }
    }
    return nil
}
```

```json

  "group_id": 2,
```

#### `PATCH /api/admin/pricing/rules/{id}`

```json
{
  "input_ratio": 0.6,
  "output_ratio": null,
  "clear_output": true,
  "priority": 90,
  "status": 1
```

#### `DELETE /api/admin/pricing/rules/{id}`

物理删除。响应 200 `{"status":"deleted"}`。审计 `action="pricing_rule.delete"`。

> 决策:M1 不做软删 — pricing_rules 数据量小、操作频率低,硬删 + audit 已经足够。

## 7. 错误码

本 spec **不新增**错误码,复用 [M1-01 §7](./2026-05-21-里程碑1-01-基础设施增量-设计稿.md#7-错误码补充) 已写入的:

| Code | 中文消息 | HTTP | 使用场景 |
|---|---|---|---|
| `CodeBalanceInsufficient` | 余额不足,请充值 | 402 | Reserve 时 wallet hash balance < est_cost |
| `CodeReservationNotFound` | 预扣记录不存在或已过期 | 410 | Commit/Refund 时 rid 不存在或状态非 pending |
| `CodeReservationCommitted` | 预扣记录已提交,不可重复操作 | 409 | Commit 重复 / Refund 已 committed |
| `CodeInvalidParam` | 参数格式错误 | 400 | est_cost <= 0 / scope 不合法 / ratio 负值 |
| `CodeNotFound` | 资源不存在 | 404 | 钱包按 owner 不存在 / 规则 id 不存在 |
| `CodeForbidden` | 权限不足 | 403 | 普通用户访问 `/api/admin/*` |
| `CodeDatabase` | 数据库错误 | 500 | DB 操作失败 wrap |
| `CodeCache` | 缓存错误 | 500 | Lua / Redis 命令失败 wrap |
| `CodeInternal` | 内部错误,请稍后重试 | 500 | actualCost > reserved 等不应发生场景 |

i18n 消息已在 M1-01 §7 注入。

> 决策:`CodeBalanceInsufficient` 在代理 API 链(`/v1/*`,M1-01 ErrorResponse "openai")下的 OpenAI type 是 `insufficient_quota`(M1-01 §4.4 映射表已包含)。本 spec 用户侧 `GET /api/user/wallet` 链不触发这个码(只在 Reserve 路径触发)。

## 11. 关键决策

本节集中说明 11 个核心 trade-off,便于后续 review 与回追。

### 11.1 Reserve 失败时的 DB 写入顺序

**决策**:**先 Lua 成功 → 再 INSERT quota_reservations**;DB 失败时立即调 `refund.lua` 回滚 Redis,失败兜底为 error_log + metric。

**替代方案与权衡**:
- (A) DB INSERT 先,Lua 后:DB 写后才知道额度够不够,可能多 round-trip + 还要 DELETE
- (B) Lua + DB 在事务边界内同步:Lua 与 DB 是两个独立系统,无两阶段提交协议,做不到原子
- (C) 当前方案:Lua 后 DB,失败补偿:99.99% 路径只一个 round-trip;失败补偿率极低(DB 故障时本身就异常)

**剩余风险**:Redis 已扣但 DB 未写 + refund.lua 也失败 → 数据"漏在 Redis 余额减少但 DB 无 reservation 记录"。无法被 reconcile 修(reconcile 扫 DB 找不到这条)。运维介入路径:监控 `billing_reserve_leaks_total` 报警 + 手动从日志找出 user/amount,对账人工 Credit 补偿。

### 11.2 Commit DB UPDATE 失败时不回滚 Lua

**决策**:Lua 已扣,DB UPDATE 失败 → 不调 refund.lua;接受短暂不一致,reconcile 会在 30s 内把 reservation 状态推到 expired,并触发一次"无 Redis 影响的"DB-only refund 路径。

**理由**:
- 该请求已经返回客户端(commit 是请求生命周期最后一步),客户端认为消费已完成 — 退回额度等于"白送"
- 反向调 refund.lua 会让 wallet balance 多还一次,在 reconcile 时又会再调一次 refund.lua(由 expireOne 触发),要么造成重复退还,要么造成账面对不齐
- 接受"DB reservation 行处于 pending 一段时间"这个短暂状态,reconcile + ledger worker 最终一致

**剩余风险**:在 commit DB 失败到 reconcile 触发之间,如果用户查 `GET /api/user/wallet`,看到的 balance 是"已扣的版本"(因为 wallet 表是 ApplyLedgerBatch 更新的,只要 ledger event 入队就会被持久化)— 实际是一致的;`quota_reservations.status=pending` 不暴露给前端。

### 11.3 ledger channel 满则阻塞而非丢弃

**决策**:`ledgerCh` cap = 1024;send 阻塞而非 select-default-drop。

**理由**:ledger 是账本,丢一条等于丢一笔账。优先数据一致而非接口延迟。

**代价**:大压力下 commit 路径 RT 变长,影响响应延迟尾部分布。可观测性兜底:`billing_ledger_queue_depth` gauge(本 spec 不必实现,M1-08 监控加)。M2 可以加旁路落盘(WAL)+ 重放,但 M1 不做。

### 11.4 ledger 写入 worker batch 失败的处理

**决策**:重试 3 次(100ms / 200ms / 400ms 指数退避);仍失败 → metric `billing_ledger_write_failures_total += batch_size` + audit `ledger.write_failed`;**事件不放回队列**,直接丢弃(进入"运维修复"的人工对账路径)。

**理由**:
- 持续失败说明 DB 不可达,堆积重试会让 channel 满 → 阻塞 commit → 雪崩
- 失败的 ledger 事件即使重放也不可信(顺序已乱,balance_after 串错)
- 人工对账路径:从 audit + log 里抽取 wallet_id 列表,定期对比 `SELECT SUM(amount_quota) GROUP BY wallet_id` 与 wallet 表累计字段,差值入账

### 11.5 reconcile cron 频率与单次扫描数量

**决策**:30s 一次,单次 100 条上限。两者都从 setting 读取,运行时可调。

**理由**:
- 30s 是 reserve_ttl_seconds(600s)的 5%,足以"在 TTL 后 2-3 个 tick 内回收"
- 100 条避免单次 SQL 扫描压力大;实际场景 expired 数量主要来自客户端取消(浏览器关闭 / 网络断开),日常 < 10 条/30s

**剩余风险**:burst 场景(峰值故障导致 1k+ pending)需要 5-10 个 tick 才能消化,期间用户感觉"余额没回来"。M2 可以加并行 worker 加速。

### 11.6 reservation id 用 UUID v4 而非 Snowflake

**决策**:UUID v4,`CHAR(36)`。

**理由**:
- 全集群无依赖 — 即使 idgen 故障 reservation 也能签发
- reservation lifecycle 极短(< 10 分钟过期);UUID 字符串长一些不构成索引开销
- 接口签名 `Reserve(...) (string, error)` 返回 string,自然 fit UUID
- Snowflake 是业务表共享段,reservation 高频签发会挤压其他业务 id 段

**代价**:
- ref_id 字段是 BIGINT 存不下 UUID — 通过 description 字段保留 rid 文本作 audit 替代(§4.4)
- DB 索引性能上 CHAR(36) 比 BIGINT 略差但可接受(reservation 高频 query 都按 id PK 走主键索引,O(log N) 不受字符串长度影响)

### 11.7 pricing 匹配顺序与优先级

**决策**:
- 顺序(由精到粗):`group_model → model → group → global → catalog default`
- 每层内:`priority ASC → id DESC`(priority 数字小者胜,同 priority 取最新)
- 通配:仅末尾 `*`(与 M1-03 §4 token 模型白名单同语义)

**理由**:
- "精确优先"符合用户认知:为 `gpt-4o + vip 分组` 单独定的规则一定胜过"所有 gpt-* 模型"的规则
- 数字小优先,是定价规则常见约定(类比路由器优先级)
- 末尾通配避开正则 / glob 复杂度,与 token 白名单一致

### 11.8 Compute 渠道 nil 容错

**决策**:`Compute` 接受 `Channel == nil`(在 Reserve 估算路径),此时跳过 `ModelOverrides`,直接用 model_catalogs default + pricing_rules。

**理由**:Reserve 是在选渠道**之前**调用的 — 这时还不知道用哪个 channel,但需要预估 max cost。允许 nil 让接口对调用方更宽容。Commit 时已经选好 channel,会再 `Compute` 一次取精确值。

**结果**:Reserve 估算值可能与最终 Commit 值有差异(±20% 量级,取决于 channel overrides),靠 `commit.lua` 自动退回差额来对齐。

### 11.9 流式 usage 优先 vs 本地 tokenize fallback

**决策**:Commit 路径优先用上游 `usage` 字段(`ir.Usage`),没有则用本地 `tokenize.Registry` 计算 input + 累计 delta 计算 output。

**理由**:
- 各上游 tokenizer 与本地 tiktoken 存在 ±5% 偏差,以上游为准最准确
- 本地兜底保证"流式 chunk 没有 usage 时也能计费"(M1-04 spec 对各 adapter 是否提供 usage 有清单)

**实现位置**:本 spec **不**在 billing 内 tokenize;由 relay 模块在 commit 前调用 `pricing.Compute(ComputeInput{InputTokens, OutputTokens, ...})`,relay 自己决定如何填充 token 数(本地 tokenize 或上游 usage)。本 spec 只接受最终的 4 个 token 数。

### 11.10 wallet Redis hash 不设 TTL

**决策**:`wallet:user:{id}` hash 永久驻留(无 EXPIRE)。

**理由**:
- Lua 路径强依赖 hash 存在 — TTL 过期会导致 `reserve.lua` 见到 balance="0",误报余额不足
- wallet 数量与活跃用户数同阶(< 100w),每个 hash ~100 bytes,总 RAM < 100MB,远低于风险阈值
- 失效路径只有"管理员清账"(M2),M1 无此入口

**代价**:Redis 重启后所有 wallet hash 丢失。`GetOrCreate` 路径会回源 DB 重建,但**重建窗口**:
- 用户首次请求时,`GetOrCreate` 路径走完,hash 重建,balance 与 DB 一致
- 在重建之前,`reserve.lua` 会见到 hash 不存在 → `HGET` 返回 nil → tonumber(nil or '0') = 0 → 误判余额不足
- 缓解:`GetOrCreate` 在创建钱包后立即 `HSET wallet:user:{id} balance ... reserved 0 consumed ...`;每次 `Balance` 路径回源 DB 后也同样 HSET

### 11.11 Reserve 不写日志(请求日志由 relay/log 模块负责)

**决策**:本 spec 三个方法都**不**调 `log.Store.Write`(避免循环依赖);request_logs 由 [M1-08 日志](./2026-05-21-里程碑1-总体设计纲要.md) 在 relay 编排时统一写。

**理由**:
- ledger 是"账"(append-only 流水);request_logs 是"日志"(查询用)。两者用途不同
- billing 关注 wallet/quota,不应该知道 request 元数据(model / channel / status_code 等)
- relay 模块拿到 reservation_id + token_id + 各种元数据后,统一 Write log,顺便引用 reservation_id 写入(`request_logs.token_id`)

**relay 路径示意**:
```
relay.Chat(ctx, req):
    rid := biller.Reserve(ctx, ...)
    ch := selector.Select(...)
    biller.BindRequestID(ctx, rid, requestID)  // requestID 由 idgen 在 relay 入口生成
    resp := adapter.Chat(ctx, req, ch.Cred)
    cost := pricing.Compute(ctx, ComputeInput{...})
    biller.Commit(ctx, rid, cost.Quota)
    log.Store.Write(ctx, log.Event{TokenID, RequestID: requestID, TotalQuota: cost.Quota, ...})
```
