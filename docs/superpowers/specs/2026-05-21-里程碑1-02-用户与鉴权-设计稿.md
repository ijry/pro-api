# 里程碑 M1-02 用户与鉴权(基础)

## 1. 目标与范围

### 1.1 一句话

把"谁是用户、用户怎么登入、登入后怎么识别身份"这条最基础的链路打通 — 包括 **users / user_groups / oauth_bindings / sessions 四张表**、注册/登录/登出/邮箱验证码/GitHub OAuth、Session Store(Redis primary + DB mirror)、SessionAuth 与 CSRF 两个中间件,以及全套 `/api/auth/* + /api/user/* + /api/admin/users/*` handler。

### 1.2 范围

属于本 spec 的(13 件事):

1. **migration**:`000002_alter_users_m1`(M0 users 基础上加 `email_verified_at`)、`000003_create_user_groups`、`000014_create_sessions`、`000015_create_oauth_bindings`
2. **`internal/user/`**:users repository + service(CRUD / 注册 / 密码 hash / 邮箱验证状态)
3. **`internal/group/`**:user_groups CRUD + 按 id 取分组倍率
4. **`internal/auth/session/`**:`SessionStore`(Redis primary + DB mirror、Pub/Sub 强制下线、Sliding TTL)
5. **`internal/auth/verifycode/`**:6 位数字邮箱验证码(Redis 存储,TTL 5min)
6. **`internal/auth/oauth/github/`**:GitHub OAuth state + 回调 + 自动建账号 + 绑定
7. **`internal/auth/password/`**:bcrypt cost=10 hash 与校验
8. **`internal/auth/service.go`**:auth.Service 顶层(注册、登录、登出、密码登录、邮箱码登录、密码忘记/重置)
9. **`internal/notify/email/`**:`Mailer` 接口 + Stub 实现(M1 把验证码打到 log + audit;SMTP 留 M2)
10. **中间件**:`SessionAuth`、`CSRF`、`RoleGate(minRole)`(M1-02 引入,所有后续 spec 共用)
11. **HTTP handler**:`/api/auth/*` + `/api/user/*`(本人个人信息) + `/api/admin/users/*`(后台用户管理)与 `/api/admin/auth/*`(后台登录)
12. **wire**:`app.WireAuth(app)` 装配 user / group / auth.Service / SessionStore / Mailer 等到 application
13. **审计**:对 `user.register / user.update / user.reset_password / user.status_change / session.force_logout / user.role_change / oauth.bind / oauth.unbind` 等关键操作记 audit

### 1.3 排除项(明确不做)

- 后台 / 用户前端 UI(分别在 M1-09 / M1-10 spec)
- API 令牌(M1-03)
- 部门(M3)、邀请(M2)
- Google / 微信 / 飞书 / 钉钉 / Discord OAuth(M2)
- SSO(M3)
- SMTP 真实发件、邮件模板系统(M2)
- 双因素认证 / 短信验证码 / 图形验证码(M2/M3)
- 用户头像上传(M2;`avatar` 字段先存 URL 字符串,PATCH profile 接受 URL)
- 部门预算 / 部门管理员(M3)

## 2. 数据模型

字段定义全部沿用 [总纲 §2.1](./2026-05-21-里程碑1-总体设计纲要.md#21--users)([§2.2](./2026-05-21-里程碑1-总体设计纲要.md#22--user_groups) / [§2.13](./2026-05-21-里程碑1-总体设计纲要.md#213--sessions冗余镜像) / [§2.14](./2026-05-21-里程碑1-总体设计纲要.md#214--oauth_bindings)),本节只给 **migration 落地 SQL + GORM 模型**。

### 2.1 users ALTER

M0 已建最小 `users` 表(`id / username / email / password_hash / display_name / avatar / role / status / group_id / last_login_at / last_login_ip / created_at / updated_at / deleted_at`),M1 通过 ALTER 增加 `email_verified_at`。

`migrations/mysql/000002_alter_users_m1.up.sql`:

```sql
ALTER TABLE users
  ADD COLUMN email_verified_at DATETIME(3) NULL AFTER status;

-- 额外索引补齐(M0 可能没建)
CREATE INDEX IF NOT EXISTS idx_users_group_status ON users (group_id, status);
```

down:

```sql
ALTER TABLE users DROP COLUMN email_verified_at;
DROP INDEX idx_users_group_status ON users;
```

`migrations/postgres/000002_alter_users_m1.up.sql`:

```sql
ALTER TABLE users ADD COLUMN IF NOT EXISTS email_verified_at TIMESTAMPTZ;
CREATE INDEX IF NOT EXISTS idx_users_group_status ON users (group_id, status);
```

down:

```sql
DROP INDEX IF EXISTS idx_users_group_status;
ALTER TABLE users DROP COLUMN IF EXISTS email_verified_at;
```

> 决策:**保留** M0 已建好的 `primary_dept_id` / `invited_by` 字段(M3/M2 才用)以避免 PG 上 DROP COLUMN 的事务约束。

### 2.2 user_groups

`migrations/mysql/000003_create_user_groups.up.sql`:

```sql
CREATE TABLE IF NOT EXISTS user_groups (
    id            BIGINT       NOT NULL,
    name          VARCHAR(64)  NOT NULL,
    display_name  VARCHAR(64)  NOT NULL DEFAULT '',
    ratio         DECIMAL(10,4) NOT NULL DEFAULT 1.0000,
    priority      SMALLINT     NOT NULL DEFAULT 0,
    status        TINYINT      NOT NULL DEFAULT 0,
    created_at    DATETIME(3)  NOT NULL,
    updated_at    DATETIME(3)  NOT NULL,

```

PG 等价(`SMALLINT` / `TIMESTAMPTZ` / `DECIMAL(10,4)`)。`down` 都是 `DROP TABLE IF EXISTS user_groups;`。

种子数据由 M1-01 spec 的 `000022_seed_initial.up.sql` 写入(已含 `default / vip / svip` 三条)。

## 3. 接口契约

### 3.1 user.Service

```go
// internal/user/service.go
package user

import (
    "context"
    "time"
)

// CreateInput 描述一个新建用户。GroupID 缺省时 service 自动填 "default" 分组。
type CreateInput struct {
    Username     string
    Email        *string
    PasswordHash *string  // 已 hash;OAuth 注册时可为 nil
    DisplayName  *string
    Role         int8
    Status       int8
    GroupID      *int64
}

type UpdateInput struct {
    DisplayName *string
    Avatar      *string
    Role        *int8
    Status      *int8
    GroupID     *int64
}

type ListFilter struct {
    Keyword string  // 模糊匹配 username / email / display_name
    Role    *int8
    Status  *int8
    GroupID *int64
    Page    int     // 1-based
    Size    int     // 默认 20,上限 100
    OrderBy string  // "created_at_desc" / "last_login_desc";默认 created_at_desc
}

type Service interface {
    // 注册:写 users 表(role=user, status=按 email_verification_required 决定 active 或 pending)
    Create(ctx context.Context, in CreateInput) (*User, error)
    // 主键查询;不存在返回 (nil, nil)
    GetByID(ctx context.Context, id int64) (*User, error)
    GetByUsername(ctx context.Context, name string) (*User, error)
    GetByEmail(ctx context.Context, email string) (*User, error)
    // 后台列表;返回 items + total
    List(ctx context.Context, f ListFilter) ([]*User, int64, error)
    // PATCH:仅更新非 nil 字段;Role 变更需调用方校验 actor 权限
    Update(ctx context.Context, id int64, in UpdateInput) (*User, error)
    // 改密:覆盖 password_hash,清空所有 sessions(交由 caller 同步 SessionStore.RevokeAllForUser)
    UpdatePasswordHash(ctx context.Context, id int64, hash string) error
    // 邮箱验证完成:set email_verified_at + status active(若原本是 pending)
    MarkEmailVerified(ctx context.Context, id int64) error
    // 记 last_login_at / last_login_ip(失败仅日志,不阻塞登录)
    TouchLogin(ctx context.Context, id int64, ip string) error
    // 软删:写 deleted_at;同时 service 会同步禁用 status=1(避免误恢复后仍能登录)
    Delete(ctx context.Context, id int64) error
}
```

### 3.3 SessionStore

实现 [总纲 §4.8](./2026-05-21-里程碑1-总体设计纲要.md#48-sessionstore) 接口:

```go
// internal/auth/session/store.go
package session

import (
    "context"
    "time"
)

type Session struct {
    ID        string
    UserID    int64
    Role      int8
    IP        string
    UserAgent string
    CreatedAt time.Time
    LastSeen  time.Time
    ExpiresAt time.Time
}

type Store interface {
    Create(ctx context.Context, userID int64, role int8, ip, ua string) (*Session, error)
    Get(ctx context.Context, id string) (*Session, error)  // miss 返回 (nil, nil)
    Touch(ctx context.Context, id string) error             // 更新 LastSeen + 滑动延期
    Revoke(ctx context.Context, id string) error
    RevokeAllForUser(ctx context.Context, userID int64) error
    Close() error
}

// Config — 构造参数
type Config struct {
    TTL     time.Duration       // 默认 30 天,从 setting "session.ttl_days" 读
    Sliding bool                // 默认 true
    MirrorBatchSize  int        // DB mirror 异步同步 last_seen 的 batch 大小,默认 100
    MirrorBatchEvery time.Duration  // 默认 30s
}
```

### 3.4 verifycode.Store

```go
// internal/auth/verifycode/store.go
package verifycode

import (
    "context"
    "time"
)

type Purpose string

const (
    PurposeRegister      Purpose = "register"
    PurposeLogin         Purpose = "login"
    PurposePasswordReset Purpose = "password_reset"
    PurposeBindEmail     Purpose = "bind_email"
)

type Store interface {
    // Generate 生成 6 位数字码,写入 Redis(TTL 5min,可由 setting 覆盖),返回 code 明文。
    // 同一 (purpose, email) 重复 Generate 直接覆盖旧码并重置 TTL(避免穷举)。
    // Generate 有 IP+email 双维度的发送频率限制(60s 内同 email 最多发 1 次)。
    Generate(ctx context.Context, purpose Purpose, email, ip string) (code string, err error)
    // Verify 校验并消费(成功后立刻删除 key,防重放)。
    // 错误:CodeCaptchaInvalid(过期或不匹配)。
    Verify(ctx context.Context, purpose Purpose, email, code string) error
}
```

Redis key 命名(本 spec 定稿):

```
verify_code:{purpose}:{email}            string  value=6 位数字  TTL=300s
verify_code:throttle:{purpose}:{email}   string  value=1         TTL=60s   (节流键)
```

```go
    Lang     string  // 用于错误消息和邮件
}

type RegisterResult struct {
    UserID            int64
    EmailVerifyRequired bool   // 取决于 setting auth.email_verification_required
    Session           *session.Session  // 验证不要求时直接登录,否则为 nil
}

type LoginInput struct {
    Identity string  // username 或 email
    Password string
    IP       string
    UA       string
}

type EmailCodeLoginInput struct {
    Email string
    Code  string
    IP    string
    UA    string
}

type Service interface {
    Register(ctx context.Context, in RegisterInput) (*RegisterResult, error)
    Login(ctx context.Context, in LoginInput) (*session.Session, *User, error)
    EmailCodeLogin(ctx context.Context, in EmailCodeLoginInput) (*session.Session, *User, error)
    Logout(ctx context.Context, sessionID string) error
    // SendEmailCode:调 verifycode.Generate + 调 Mailer.Send(M1 stub)

    // 忘记密码:发一封"重置链接"邮件(M1 stub:发一个 6 位 reset_token 写到 audit)

    // 重置密码:校验 code + 改 hash + RevokeAllForUser
    ResetPassword(ctx context.Context, email, code, newPlain string) error
    // 修改密码(已登录):校验旧密码 + 改 hash + RevokeAllForUser (除当前 session)
    ChangePassword(ctx context.Context, userID int64, currentSessionID, oldPlain, newPlain string) error
    // GitHub OAuth:start 返回跳转 URL;callback 完成登录/绑定/建账号

    GithubOAuthCallback(ctx context.Context, code, state, ip, ua string) (*session.Session, *User, error)
```

## 4. 关键算法

### 4.1 注册流程

```
Input(username, email, password, ip, ua)
  ↓
1. setting.Get("auth.allow_register") == true                     | else CodeForbidden
2. password.CheckStrength(password, min_length, require_mixed)    | else CodeInvalidParam
3. user.GetByEmail(email)  exists → CodeEmailRegistered
4. user.GetByUsername(name) exists → CodeUsernameTaken
5. hash = password.Hash(password)
6. emailVerifyRequired = setting.Get("auth.email_verification_required")
7. status = emailVerifyRequired ? StatusPendingEmailVerify : StatusActive
8. groupDefault = group.Default()
9. u = user.Create({username, email, hash, role=0, status, group_id=default.id})
10. audit.Log({action:"user.register", target:u.id, after:{username,email}})
11. if emailVerifyRequired:
       verifycode.Generate(PurposeRegister, email, ip)
       mailer.Send({to:email, subject:"验证码", body:"您的验证码是 NNNNNN", tag:"verify_register"})
       return RegisterResult{UserID:u.id, EmailVerifyRequired:true, Session:nil}
   else:
       sess = session.Create(u.id, u.role, ip, ua)
       user.TouchLogin(u.id, ip)
       return RegisterResult{..., Session:sess}
```

错误码:`CodeForbidden`(注册关闭)、`CodeInvalidParam`(密码强度)、`CodeEmailRegistered`、`CodeUsernameTaken`、`CodeDatabase`、`CodeInternal`。

### 4.2 邮箱验证完成(VerifyEmail)

注册时若 `email_verification_required=true`,前端调 `POST /api/auth/email/login` 用验证码登录会自动同时完成 verify。专门的 `POST /api/auth/email/verify`(本 spec 不单独提供,等 M2 加重发等场景)合并到 `EmailCodeLogin` 内部:

```
EmailCodeLogin(email, code, ip, ua):
  1. user.GetByEmail(email)              not exist → CodeWrongPassword(避免泄露 email 存在性)
  2. if status == StatusDisabled         → CodeForbidden
  3. verifycode.Verify(PurposeLogin OR PurposeRegister, email, code)
       (M1 一码两用:同时尝试 register 和 login purpose,任一命中即可;
        简化方案 — Generate 时用 PurposeRegister,Verify 时 service 内部按 user.status 选择 purpose)
  4. if user.EmailVerifiedAt == nil:
       user.MarkEmailVerified(u.id)      (内部同时把 status 从 pending 改 active)
       audit.Log({action:"user.email_verified", target:u.id})
  5. sess = session.Create(u.id, u.role, ip, ua)
  6. user.TouchLogin(u.id, ip)
  7. return sess, u
```

### 4.3 密码登录

```
Login(identity, password, ip, ua):
  1. lookup user by email if strings.Contains(identity, "@"), else by username
  2. user == nil → CodeWrongPassword
  3. user.PasswordHash == nil → CodeWrongPassword (OAuth-only 账号未设密码)
  4. password.Verify(user.PasswordHash, password) failed → CodeWrongPassword
  5. if user.Status == StatusDisabled → CodeForbidden
  6. if user.Status == StatusPendingEmailVerify → CodeEmailNotVerified
  7. sess = session.Create(...)
  8. user.TouchLogin(u.id, ip)
  9. audit.Log({action:"user.login", target:u.id, after:{method:"password", ip}})
  10. return sess, user
```

注意:第 2 / 4 步都返回 `CodeWrongPassword`(同一错误消息),防止用枚举 email 是否注册。

### 4.4 GitHub OAuth 流程

#### 4.4.1 start(未登录场景)

```
GithubOAuthStart(ip, ua, bindUserID=0):
  1. cfg = setting.github_oauth 不存在 → CodeForbidden("GitHub 登录未启用")
  2. payload = json.Marshal({"bind_user_id": bindUserID, "ip": ip, "ua": ua, "issued_at": now})
  3. state = stateStore.Issue("github", payload)
  4. redirectURL = cfg.RedirectURL OR "https://"+host+"/api/auth/oauth/github/callback"
  5. url = ghProvider.BuildAuthURL(state, redirectURL)
  6. return url
```

#### 4.4.2 callback(无 bind)

```
GithubOAuthCallback(code, state, ip, ua):
  1. payload, err = stateStore.Consume("github", state)
       err → CodeCaptchaInvalid("state 无效或过期")
  2. info, accessToken = ghProvider.Exchange(code, redirectURL)
       err → CodeInternal / CodeUpstreamError
  3. binding = oauthRepo.FindBy(provider="github", uid=info.ID)
  4. if binding exists:
       user = userSvc.GetByID(binding.UserID)
       if user == nil OR status == disabled → CodeForbidden
       (走"已绑定登录"路径)
  5. else if info.Email != "" && existsUser by email:
       user = ...
       oauthRepo.Create({user_id, provider:"github", uid, email, profile})  (自动绑定)
       audit.Log({action:"oauth.bind", actor:user.id, target:user.id, after:{provider:"github"}})
  6. else:
       (自动建账号)
       username = pickUsername(info.Login OR "gh_"+info.ID)  -- 冲突时附 "_2" 等后缀
       email = info.Email if verified
       u = userSvc.Create({username, email, password_hash:nil, role:0, status:StatusActive, group_id:default})
       oauthRepo.Create({user_id:u.id, ...})
       audit.Log({action:"user.register", actor:nil, target:u.id, after:{method:"github"}})
  7. sess = session.Create(user.id, user.role, ip, ua)
  8. userSvc.TouchLogin(user.id, ip)
  9. audit.Log({action:"user.login", target:user.id, after:{method:"github"}})
 10. return sess, user
```

> 决策:**OAuth 自动建账号默认 status=Active**,不再走 email 验证(GitHub 的邮箱已是 verified)。

#### 4.4.3 BindGithub(已登录绑定)

```
BindGithub(userID, code, state):
  1. payload = stateStore.Consume("github", state)
       校验 payload.bind_user_id == userID,否则 CodeForbidden
  2. info = ghProvider.Exchange(code, redirectURL)
  3. existing = oauthRepo.FindBy("github", info.ID)
       if existing != nil && existing.UserID != userID → CodeForbidden("此 GitHub 已绑定其他账号")
  4. oauthRepo.Upsert({user_id:userID, provider:"github", uid:info.ID, email, profile})
  5. audit.Log({action:"oauth.bind", actor:userID, target:userID, after:{provider:"github", uid}})
```

#### 4.4.4 UnbindGithub

```
UnbindGithub(userID):
  1. user = userSvc.GetByID(userID)
  2. if user.PasswordHash == nil → CodeForbidden("解绑前请先设置密码,以免无法登录")
  3. oauthRepo.DeleteBy(userID, "github")
  4. audit.Log({action:"oauth.unbind", actor:userID, target:userID, after:{provider:"github"}})
```

### 4.5 SessionStore 实现细节

#### 4.5.1 Redis 数据结构

```
session:{id}                Hash {user_id, role, ip, ua, created_at, last_seen, expires_at}
                            TTL = expires_at - now
session:user:{uid}          Set 成员 = session.id (用于 RevokeAllForUser)
                            TTL = max session.expires_at
session:revoke:notify       Pub/Sub channel,广播 "revoked:{session_id}"
```

#### 4.5.2 Create

```
Create(userID, role, ip, ua):
  1. id = "sess_" + base64url(rand(32))
  2. now = clock.Now()
  3. expires = now + cfg.TTL
  4. HSET session:{id} ...
  5. EXPIRE session:{id} cfg.TTL
  6. SADD session:user:{uid} {id}
  7. EXPIRE session:user:{uid} cfg.TTL  (overrides only if larger;实际上每次 add 都 PEXPIRE 一次)
  8. DB insert sessions(id, user_id, ip, ua, created_at, last_seen_at, expires_at)
       (失败仅 log,不阻塞 — Redis 是 primary)
  9. return Session{...}
```

#### 4.5.3 Get

```
Get(id):
  1. HGETALL session:{id}
  2. empty → return (nil, nil)
  3. now > expires_at → DEL + return (nil, nil)
  4. revoked → 同上(我们用 Redis EXPIRE 间接实现 revoked;Revoke 时直接 DEL key)
  5. return Session{...}
```

#### 4.5.4 Touch(Sliding)

```
Touch(id):
  if !cfg.Sliding: return nil  (仅更新 last_seen 不延期)

  1. HSET session:{id} last_seen now
  2. PEXPIRE session:{id} cfg.TTL  (滑动延期)
  3. HSET session:{id} expires_at (now + cfg.TTL)
  4. 入队 mirror update(异步 batch 写 DB)
```

DB mirror batch:`internal/auth/session/mirror.go` 启动一个 goroutine,每 30s 或 100 条更新 `UPDATE sessions SET last_seen_at=?, expires_at=? WHERE id=?`(in batch transaction)。

#### 4.5.5 Revoke

```
Revoke(id):
  1. HGET session:{id} user_id  (拿到 uid)
  2. DEL session:{id}
  3. SREM session:user:{uid} {id}
  4. UPDATE sessions SET revoked_at = now WHERE id = ?  (DB mirror)
  5. PUBLISH proapi:session:revoke "{id}"
```

订阅者(本进程或集群其他实例)收到后清掉任何本地 cache(M1 暂无 session 本地缓存,Pub/Sub 主要给"强制下线"提供未来扩展点)。

#### 4.5.6 RevokeAllForUser(强制下线)

```
RevokeAllForUser(uid):
  1. ids = SMEMBERS session:user:{uid}
  2. for id in ids: Revoke(id)
  3. UPDATE sessions SET revoked_at = now WHERE user_id = ? AND revoked_at IS NULL
  4. audit.Log({action:"session.force_logout", target:uid})
```

调用场景:管理员重置用户密码、用户主动改密、用户被禁用、解绑唯一 OAuth 等。

#### 4.5.7 启动回放

`session.New()` 启动时:

```
1. 查 DB:SELECT * FROM sessions WHERE expires_at > NOW() AND revoked_at IS NULL LIMIT 10000
2. 对每条:HSET 到 Redis(如果 Redis 已有则跳过,只补缺失)
   (避免冷启动后用户已发的 session 全部失效)
```

只在 `cfg.RestoreOnStart=true` 时执行;默认 true。

#### 4.5.8 过期清理 cron

`internal/auth/session/cleanup.go` 每 5 分钟跑:

```sql
DELETE FROM sessions
WHERE expires_at < NOW() - INTERVAL 7 DAY
   OR (revoked_at IS NOT NULL AND revoked_at < NOW() - INTERVAL 7 DAY);
LIMIT 1000;
```

保留 7 天用于审计追溯。

### 4.6 验证码生成与节流

```
Generate(purpose, email, ip):
  1. throttleKey = "verify_code:throttle:"+purpose+":"+email
     EXISTS throttleKey → CodeRateLimitUser("发送过于频繁,请稍后再试")
  2. code = randDigits(6)
  3. SETEX verify_code:{purpose}:{email} 300 code
  4. SETEX throttleKey 60 "1"
  5. (M1 不写 audit;Mailer.Send 在 caller 端做)
  6. return code
```

```
Verify(purpose, email, code):
  1. key = "verify_code:"+purpose+":"+email
  2. v = GET key
  3. v == "" → CodeCaptchaInvalid
  4. crypto.SubtleCompare(v, code) failed → CodeCaptchaInvalid
       (constant-time;math/crypto/subtle)
  5. DEL key  (单次有效)
  6. return nil
```

### 4.7 CSRF 双 Cookie 法

```
中间件 SessionAuth 在写 Cookie proapi_session 时,同步写 proapi_csrf:
   Cookie proapi_session  HttpOnly=true, SameSite=Lax, Path=/, Secure=prod
   Cookie proapi_csrf     HttpOnly=false(让 Vue 端 document.cookie 读)
                          SameSite=Lax, Path=/, Secure=prod
   proapi_csrf 的值 = HMAC_SHA256(masterKey, session_id) 取 16 字节 hex

CSRF 中间件:
   仅对 unsafe method(POST/PUT/PATCH/DELETE)校验
   读取请求头 X-CSRF-Token
   读取 Cookie proapi_csrf
   constant-time 比较;不一致返回 CodeForbidden
   GET / HEAD / OPTIONS 跳过

例外:
   /api/auth/oauth/github/callback 是 GET,自动跳过
   /api/admin/auth/login + /api/auth/login 等"获取登录态"的入口:仍校验 CSRF?
     决策:**不校验**(此时还没有 session,但有 SameSite=Lax 保护)。
     具体实现:CSRF 中间件读 cookie proapi_csrf;没有则跳过校验(同时不允许写 unsafe path)。
     更稳妥:对 /api/auth/* 入口路由跳过 CSRF 中间件(白名单)。
```

CSRF 中间件路由白名单:

```
/api/auth/register
/api/auth/login
/api/auth/email/send_code
/api/auth/email/login
/api/auth/password/forgot
/api/auth/password/reset
/api/auth/oauth/github/start
/api/auth/oauth/github/callback
/api/admin/auth/login
```

其余 unsafe method 必须有 CSRF。

### 4.8 SessionAuth 中间件

```go
func SessionAuth(store session.Store, clock clock.Clock) gin.HandlerFunc {
    return func(c *gin.Context) {
        sid := readSessionID(c)  // Cookie proapi_session 优先,fallback Header X-Session-Token
        if sid == "" {
            middleware.SetErr(c, apierr.New(apierr.CodeNotLoggedIn, "请先登录"))
            return
        }
        sess, err := store.Get(c.Request.Context(), sid)
        if err != nil { middleware.SetErr(c, apierr.Wrap(apierr.CodeInternal, err)); return }
        if sess == nil {
            middleware.SetErr(c, apierr.New(apierr.CodeSessionExpired, "会话已过期"))
            return
        }
        // 滑动延期(异步,fire-and-forget)
        go func(id string) {
            _ = store.Touch(context.Background(), id)
        }(sid)
        // 注入 ctx
        c.Set(ctxKeyUserID, sess.UserID)
        c.Set(ctxKeyRole, sess.Role)
        c.Set(ctxKeySessionID, sess.ID)
        c.Next()
    }
}
```

context key 常量(`internal/server/middleware/ctx_keys.go`):

```go

    ctxKeyRole      = "proapi:role"

)
```


## 6. 前后台联动

> 前端 UI 由 M1-09(admin)/ M1-10(user)spec 详细设计;本节只约定 **handler 与前端的交互契约**,不涉及具体页面。

### 6.1 登录态与 Cookie

- 前端首次访问任何 `/api/*` 前不需要任何额外操作。**首次 unsafe 请求若没有 `proapi_csrf` cookie,后端拒绝**(CSRF 中间件)— 因此前端启动时**必须先调一次 `GET /api/user/profile` 或 `GET /api/admin/auth/me`**(都会触发 SessionAuth 检查,若未登录返回 `CodeNotLoggedIn`,但**仍会种 csrf cookie**?— 不会,csrf 是 SessionAuth 创建 session 时种的)。

- 完整方案:
  - `POST /api/auth/login` 成功响应时同时种 `proapi_session` + `proapi_csrf`(后者非 HttpOnly,前端 JS 可读)
  - 之后前端在所有 unsafe 请求带 header `X-CSRF-Token: <proapi_csrf 的值>`
  - axios 拦截器统一注入(M1-10 spec 详细)

### 6.2 错误响应格式

所有 `/api/*` 错误统一:

```json
{
  "code": 20007,
  "message": "邮箱未验证,请先验证邮箱",
  "details": null
}
```

`code` 对照 `pkg/apierr/codes.go`。前端按 `code` 走分支(如 `CodeNotLoggedIn=20001 → 跳登录页`,`CodeSessionExpired=20002 → 提示重登`,`CodeEmailNotVerified=20007 → 弹"已发送验证码"`)。

### 6.3 OAuth 回跳

- `GET /api/auth/oauth/github/start?redirect=/console` → 302 到 GitHub
- GitHub 回跳 → `GET /api/auth/oauth/github/callback?code=...&state=...`
- 后端处理:
  - 成功:`Set-Cookie: proapi_session=...` + `302 Location: <state.payload.redirect or "/">`
  - 失败:`302 Location: /login?oauth_error=<code>&oauth_message=<urlencoded message>`

前端 `/login` 页面读 query 判断是否要显示错误 toast。

### 6.4 多端 / 强制下线提示

- 管理员调 `PATCH /api/admin/users/:id` 将 `status` 改为 disabled,触发 `RevokeAllForUser`
- 该用户的浏览器下次任意请求被 SessionAuth 拦截 → `CodeSessionExpired` → 前端跳 `/login?reason=session_expired`

未来扩展(M2/M3):Pub/Sub `proapi:session:revoke` 可以再被一个 WebSocket 网关订阅,实时通知前端"被强制下线",但 M1 暂不实现 WS。

### 6.5 SSR / Web 端 / 服务端调用

- 后台 / 前台 Vue 全部 SPA + CSR,无 SSR cookie 处理压力
- 后端不对 SPA 路径做 fallback(那是部署层 nginx 的事)
- 调用方语言无差别,只要带 cookie 即可

## 12. 验收

完成 M1-02 时应能:

- `make test` 全过(本 spec 所有单测 + 集成测;`//go:build integration` 用 `make test-integration`)
- `make build` 成功
- `./bin/proapi` 启动后日志含:
  - `session store restored N sessions from DB`
  - `auth service ready`(以及 GitHub OAuth 配置缺失时的 `github oauth disabled`)
- 端到端 smoke(可手动):
  1. `curl -X POST /api/auth/register -d '{...}'` → 200,返回 user / session / email_verify_required
  2. `curl -X POST /api/auth/email/send_code` → 200(看 log 拿到验证码)
  3. `curl -X POST /api/auth/email/login` → 200,Set-Cookie
  4. `curl -b cookie /api/user/profile` → 200
  5. `curl -X PATCH -b cookie -H 'X-CSRF-Token: ...' /api/user/profile -d '{"display_name":"X"}'` → 200
  6. `curl -b admincookie /api/admin/users?page=1` → 200,看到刚注册的用户
  7. `curl -X PATCH -b admincookie -H 'X-CSRF-Token: ...' /api/admin/users/123 -d '{"status":1}'` → 200
  8. 同一个普通用户 cookie 再调 `/api/user/profile` → 401 `CodeSessionExpired`(强制下线生效)
- 数据库可观察:`sessions`、`oauth_bindings` 表有正确数据,`audit_logs` 有 `user.register / user.login / user.update / session.force_logout` 记录
- 跨实例:启 2 个进程 + 同一 Redis/DB,在 A 进程注册 + 登录,B 进程查 `/api/user/profile` 同 cookie → 200(Session 跨实例)
- 在 A 进程吊销该用户所有 session,B 进程下次请求 → 401(Pub/Sub 不强求,Redis DEL 已足够)
