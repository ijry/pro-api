# 里程碑 M1-11 手动充值与兑换码

## 1. 目标与范围

### 1.1 一句话

把 **"没有第三方支付通道也能给用户加额度"** 这条最朴素的钱进出路径打通 — 用户在前台填一张"我已经线下转账了"的申请单,管理员审批通过后按"当时汇率"换算成 quota 写入钱包;同时支持管理员**批量**生成兑换码、用户**一次性**兑换码加额度。两类入账都通过 [总纲 §4.10 `wallet.Store.Credit`](./2026-05-21-里程碑1-总体设计纲要.md#410-wallet) 落库,与日后 Stripe / 支付宝 / 微信(M2)走同一计入口径,**不直接改钱包余额**。

### 1.2 范围

属于本 spec 的(12 件事):

1. **migration**:`000016_create_manual_recharges.{up,down}.sql`、`000017_create_redeem_codes.{up,down}.sql`
2. **`internal/payment/manual/`**:`Service` 顶层(`Apply / Approve / Reject / Cancel / List / Get`)+ repository
3. **`internal/payment/redeem/`**:`Service` 顶层(`BatchCreate / Redeem / Disable / List / Get / Export`)+ repository
4. **`internal/payment/`**:`payment.Service` 聚合(对外只暴露这一个对象,内嵌 manual + redeem 两个子服务,便于 handler / wire)
5. **HTTP handler — 用户侧**:`POST /api/user/payment/manual`、`GET /api/user/payment/manual`、`POST /api/user/payment/manual/{id}/cancel`、`POST /api/user/payment/redeem`
6. **HTTP handler — 管理员侧**:`/api/admin/payments/manual_recharges/*` 列表/详情/审批/驳回;`/api/admin/payments/redeem_codes/*` 列表/批量生成/禁用/导出
7. **wire**:`app.WirePayment(app)` 装配 `payment.Service` 到 application 容器
8. **审计**:对 `recharge.apply / .approve / .reject / .cancel`、`redeem.batch_create / .use / .disable / .export` 八个动作记 audit
9. **配置消费**:从 [总纲 §7.2](./2026-05-21-里程碑1-总体设计纲要.md#72--运行时配置system_settings-表) 的 `manual_recharge.* / redeem.* / pricing.base_quota_per_dollar` 等 key 读运行时参数
10. **错误码使用**:复用 [总纲 §8](./2026-05-21-里程碑1-总体设计纲要.md#8--错误码扩展m1-新增) 已有的 `CodeRedeemInvalid / CodeOrderNotFound / CodeInvalidParam / CodeForbidden / CodeBalanceInsufficient` 等,**本 spec 不新增错误码**;仅在 details 中细分 redeem 的四种失败语义
11. **测试**:repository + service + handler 三层单元测试,以及一份 docker `redeem.BatchCreate` 并发冲突回归
12. **后台/前台联动**:在用户中心新增"申请充值 / 兑换码"两个入口,在管理后台新增"充值审批 / 兑换码管理"两个页面(本 spec 给路由 + 字段契约,具体 UI 见 [M1-09 后台前端](./2026-05-21-里程碑1-09-后台前端-设计稿.md) 和 [M1-10 用户前台](./2026-05-21-里程碑1-10-用户前台-设计稿.md))

### 1.3 排除项(明确不做)

- ❌ Stripe / 支付宝 / 微信支付订单(M2)
- ❌ 邀请返佣(M2)
- ❌ 部门预算 / 部门钱包(M3)
- ❌ 充值发票 / 开票工作流(M2)
- ❌ 退款流程(M1 未实现负数手动充值入口;`wallet.Store.Credit` 本身支持负数,但本 spec 的 admin UI 不暴露;若线下退款需 DBA 直写 ledger,等到 M2 引入"退款" ref_type)
- ❌ "锁码后再兑换"二步流程(本 spec 一步完成:hash 查找 + 状态机切换 + Credit,DB 事务托底)
- ❌ 通过 admin 后台直接修改 wallet 余额([M1-02 §5.3.8](./2026-05-21-里程碑1-02-用户与鉴权-设计稿.md) 已声明该入口由 M1-06 接管,与本 spec 解耦)
- ❌ 兑换码自动生成预览(管理员只能整批生成,不允许"一码一密"指定)
- ❌ 中文 / 特殊字符兑换码(只用 A-Z + 0-9 去歧义集)

### 2.3 GORM 模型

`internal/payment/manual/model.go`:

```go
package manual

import "time"

// Status 枚举
const (
    StatusPending  int8 = 0
    StatusApproved int8 = 1
    StatusRejected int8 = 2
    StatusCanceled int8 = 3
)

// Recharge 是手动充值单。一笔申请一行,append 流转。
type Recharge struct {
    ID            int64      `gorm:"primaryKey;column:id"`
    UserID        int64      `gorm:"column:user_id;index"`
    AmountMoney   int64      `gorm:"column:amount_money"`           // 厘
    Currency      string     `gorm:"column:currency;size:8"`        // 'CNY'
    AmountQuota   int64      `gorm:"column:amount_quota"`           // 审批通过时填
    Status        int8       `gorm:"column:status"`
    ApplicantNote string     `gorm:"column:applicant_note;size:512"`
    ReviewerID    *int64     `gorm:"column:reviewer_id"`
    ReviewNote    string     `gorm:"column:review_note;size:512"`
    ReviewedAt    *time.Time `gorm:"column:reviewed_at"`
    CreatedAt     time.Time  `gorm:"column:created_at"`
    UpdatedAt     time.Time  `gorm:"column:updated_at"`
}

func (Recharge) TableName() string { return "manual_recharges" }

// StatusName 是日志 / audit 用的可读名。
func StatusName(s int8) string {
    switch s {
    case StatusPending:
        return "pending"
    case StatusApproved:
        return "approved"
    case StatusRejected:
        return "rejected"
    case StatusCanceled:
        return "canceled"
    default:
        return "unknown"
    }
}
```

### 2.4 索引读路径回顾

| 查询场景 | 用索引 |
|---|---|
| 用户列我的充值 | `idx_manual_recharges_user_status (user_id, status)` |
| 管理员按状态分页 | `idx_manual_recharges_status_created (status, created_at)` |
| 兑换码兑换查 hash | `uk_redeem_codes_hash` |
| 管理员按批次列码 | `idx_redeem_codes_batch` |
| 系统扫"已过期未使用"做后台标记(本 spec 不实现 cron,仅留索引)| `idx_redeem_codes_status_expires (status, expires_at)` |

> 决策:**不实现"过期自动转 disabled"** 后台 job;兑换时校验 `expires_at < now` 即返回失败,过期码物理保留。日后若要做"过期清理",加 cron 即可,索引已就位。

## 3. 接口契约

### 3.1 manual.Service

```go
// internal/payment/manual/service.go
package manual

import (
    "context"
    "time"

    "github.com/proapi/proapi/internal/audit"
    "github.com/proapi/proapi/internal/setting"
    "github.com/proapi/proapi/internal/util/clock"
    "github.com/proapi/proapi/internal/util/idgen"
    "github.com/proapi/proapi/internal/wallet"
    "github.com/proapi/proapi/pkg/apierr"
    "go.uber.org/zap"
    "gorm.io/gorm"
)

type Service interface {
    // Apply 由用户调用。
    //   amountMoney 单位 厘(1 元 = 10000 厘);上层 handler 负责把 yuan → 厘 的换算
    //   note 为申请人留言(转账凭证 URL / 单号),size ≤ 512
    Apply(ctx context.Context, userID int64, amountMoney int64, note string) (*Recharge, error)

    // Approve 由管理员调用。
    //   计算 amount_quota = floor(amount_yuan / exchange_rate * base_quota_per_dollar)
    //   调 wallet.Credit(ref_type="manual", ref_id=recharge.id)
    //   状态从 pending → approved;非 pending 拒绝
    Approve(ctx context.Context, id, reviewerID int64, note string) (*Recharge, error)

    // Reject 由管理员调用。非 pending 拒绝。不调钱包。
    Reject(ctx context.Context, id, reviewerID int64, note string) (*Recharge, error)

    // Cancel 由用户本人调用。只能取消自己 pending 的单。
    //   userID 与 recharge.UserID 不一致 → CodeForbidden
    //   非 pending → CodeInvalidParam("not_pending")
    Cancel(ctx context.Context, id, userID int64) (*Recharge, error)

    // List 通用列表。filter 区分用户/管理员两种范围(见 ListFilter)。
    List(ctx context.Context, f ListFilter) ([]*Recharge, int64, error)

    // Get 单条详情。userID = 0 表示 admin(不做 owner 校验)。
    Get(ctx context.Context, id int64, userID int64) (*Recharge, error)
}

type ListFilter struct {
    UserID   int64   // 0 = 不限(admin)
    Status   *int8   // nil = 不限
    BatchNo  string  // 暂未使用,预留
    Page     int     // 1-based
    PageSize int     // 默认 20,最大 100
}

// Config 由 wire 装配传入。
type Config struct {
    DB      *gorm.DB
    Setting setting.Store
    Wallet  wallet.Store
    Audit   audit.Logger
    IDGen   *idgen.Generator
    Clock   clock.Clock
    Log     *zap.Logger
}

func New(cfg Config) Service { return &service{cfg: cfg, repo: NewRepository(cfg.DB)} }
```

### 3.2 redeem.Service

```go
// internal/payment/redeem/service.go
package redeem

import (
    "context"
    "io"
    "time"

    "github.com/proapi/proapi/internal/audit"
    "github.com/proapi/proapi/internal/setting"
    "github.com/proapi/proapi/internal/util/clock"
    "github.com/proapi/proapi/internal/util/idgen"
    "github.com/proapi/proapi/internal/wallet"
    "go.uber.org/zap"
    "gorm.io/gorm"
)

type Service interface {
    // BatchCreate 由管理员调用。
    //   count: 1..1000;超出返回 CodeInvalidParam("count_out_of_range")
    //   amountQuota: > 0
    //   expiresAt: nil 用 setting.redeem.default_expires_days 计算;0 时间值=永不过期
    //   batchNo: 可空,空则后端按 "B" + yyyymmddHHMMSS + 4位随机 自动生成,展示给管理员
    //
    // 返回 (plaintexts, batchNoUsed, codeIDs, err)。
    //   plaintexts 与 codeIDs 顺序一致,长度等于 count。
    //   plaintexts 仅此一次返回;后续无法恢复。
    BatchCreate(ctx context.Context, actorID int64, count int, amountQuota int64, expiresAt *time.Time, batchNo string) (plaintexts []string, batchNoUsed string, codeIDs []int64, err error)

    // Redeem 由用户调用。
    //   plaintext 可带分隔符 / 空白 / 大小写任意,内部 normalize 后查 hash。
    //   失败语义全部用 CodeRedeemInvalid + details.reason 区分:
    //     "not_found" / "used" / "disabled" / "expired"
    //   成功:状态 unused → used,调 wallet.Credit(ref_type="redeem", ref_id=code.id),返回 RedeemResult。
    Redeem(ctx context.Context, userID int64, plaintext string) (*RedeemResult, error)

    // Disable 由管理员调用。
    //   只允许 unused → disabled;已 used / disabled 跳过(返回的 disabledCount 反映实际生效条数)
    Disable(ctx context.Context, actorID int64, ids []int64, reason string) (disabledCount int, err error)

    // List 管理员列表。filter:batchNo + status 可空。
    List(ctx context.Context, f ListFilter) ([]*Code, int64, error)

    // Get 单条详情(管理员)。
    Get(ctx context.Context, id int64) (*Code, error)

    // Export CSV 流写到 w。包含 id / code_prefix / amount_quota / batch_no / status / used_by / used_at / expires_at / created_at;
    // **不包含明文**(明文已不可恢复)。filter 同 List,但不分页。
    Export(ctx context.Context, w io.Writer, f ListFilter) error
}

// RedeemResult 是 Redeem 成功后的返回。
type RedeemResult struct {
    CodeID       int64
    AmountQuota  int64
    BalanceAfter int64
    UsedAt       time.Time
}

type ListFilter struct {
    BatchNo  string
    Status   *int8
    Page     int
    PageSize int
}

type Config struct {
    DB      *gorm.DB
    Setting setting.Store
    Wallet  wallet.Store
    Audit   audit.Logger
    IDGen   *idgen.Generator
    Clock   clock.Clock
    Log     *zap.Logger
}

func New(cfg Config) Service { return &service{cfg: cfg, repo: NewRepository(cfg.DB)} }
```

### 3.4 wire 装配

`internal/app/wire.go` 新增(由本 spec 在 M1-06 落地后再启用,但**接口与文件名本 spec 定稿**):

```go
// WirePayment 装配 manual + redeem 服务。
// 必须在 WireWallet (M1-06) 之后调用。
func (a *Application) WirePayment() error {
    if a.WalletStore == nil {
        return fmt.Errorf("payment wire: wallet store required")
    }
    walletStore, ok := a.WalletStore.(wallet.Store)
    if !ok {
        return fmt.Errorf("payment wire: WalletStore type mismatch")
    }

    manualSvc := manual.New(manual.Config{
        DB:      a.DB,
        Setting: a.Setting,
        Wallet:  walletStore,
        Audit:   a.Audit,
        IDGen:   a.IDGen,
        Clock:   a.Clock,
        Log:     a.Log.Named("payment.manual"),
    })
    redeemSvc := redeem.New(redeem.Config{
        DB:      a.DB,
        Setting: a.Setting,
        Wallet:  walletStore,
        Audit:   a.Audit,
        IDGen:   a.IDGen,
        Clock:   a.Clock,
        Log:     a.Log.Named("payment.redeem"),
    })
    a.PaymentSvc = payment.New(manualSvc, redeemSvc)
    return nil
}
```

### 3.5 与 wallet.Store 的契约

复用 [总纲 §4.10](./2026-05-21-里程碑1-总体设计纲要.md#410-wallet) 的 `Credit` 签名:

```go
Credit(ctx context.Context, walletID int64, amount int64, refType string, refID int64, desc string) error
```

| 入账场景 | `refType` | `refID` | `desc` |
|---|---|---|---|
| 手动充值审批通过 | `"manual"` | `manual_recharges.id` | `"manual recharge approved by admin {reviewerID}"` |
| 兑换码兑换 | `"redeem"` | `redeem_codes.id` | `"redeem code {prefix}"` |

`amount` 严格为正(非零正整数);本 spec 不会调用负数 Credit。`Credit` 内部应在事务里同时写 `wallets`(balance += amount, total_recharged += amount, version++) 与 `ledger_entries`,M1-06 实现。

> **顺序约定**:本 spec 在 `Approve` / `Redeem` 中**先**写 manual_recharges / redeem_codes 的状态(用 DB 事务包住"读 pending → 写 approved / used"),状态写完后**再**调 `wallet.Credit`。状态写失败 → 直接回滚事务,Credit 不会被调;状态写成功但 Credit 失败 → 回滚状态(详见 §4.5)。

## 4. 关键算法

### 4.1 兑换码字符集 / 长度 / 展示

```go
// internal/payment/redeem/codegen.go
package redeem

import (
    "crypto/rand"
    "crypto/sha256"
    "encoding/hex"
    "math/big"
    "strings"
)

// codeAlphabet 是 A-Z + 0-9 共 36 字符,排除歧义集 {'0','O','I','L','1'} 后剩 31 字符。
//
// 排除原因:
//   '0' 与 'O' / 'D' / 'Q' 易混
//   'I' 与 '1' / 'L' / '|' 易混
//
// 31 字符 ^ 16 位 ≈ 2.4 × 10^23 种排列,生日碰撞 1k 条远在安全范围。
const codeAlphabet = "23456789ABCDEFGHJKMNPQRSTUVWXYZ"

const codeLen = 16

// generatePlaintext 用 crypto/rand 生成 16 位明文(无分隔)。
func generatePlaintext() (string, error) {
    n := big.NewInt(int64(len(codeAlphabet)))
    b := make([]byte, codeLen)
    for i := range b {
        r, err := rand.Int(rand.Reader, n)
        if err != nil {
            return "", err
        }
        b[i] = codeAlphabet[r.Int64()]
    }
    return string(b), nil
}

// hashCode 对已 normalize 的明文做 sha256,返回 64 字符 hex(小写)。
func hashCode(plain string) string {
    sum := sha256.Sum256([]byte(plain))
    return hex.EncodeToString(sum[:])
}

// prefix 取明文前 4 位作为展示前缀(无分隔)。
func prefix(plain string) string {
    if len(plain) < 4 {
        return plain
    }
    return plain[:4]
}

// format 把无分隔的 16 位明文转 XXXX-XXXX-XXXX-XXXX,返回给管理员展示用。
func format(plain string) string {
    if len(plain) != codeLen {
        return plain
    }
    return plain[0:4] + "-" + plain[4:8] + "-" + plain[8:12] + "-" + plain[12:16]
}

// normalize 把用户输入(可能带分隔 / 空白 / 小写)转无分隔大写 16 位明文。
//   去掉所有 '-' / ' ' / '\t' / '\r' / '\n';转大写;长度必须等于 codeLen;
//   含非字母表字符 → 返回 false。
//
// 不做"歧义字符自动纠正"(例如 'O' → '0') — 这样用户最坏只是"码错了",
// 不会出现"我以为兑了 A 单结果兑了 B 单"的认知偏差。
func normalize(input string) (string, bool) {
    cleaned := strings.Map(func(r rune) rune {
        if r == '-' || r == ' ' || r == '\t' || r == '\r' || r == '\n' {
            return -1
        }
        if r >= 'a' && r <= 'z' {
            return r - 32
        }
        return r
    }, input)
    if len(cleaned) != codeLen {
        return "", false
    }
    for _, r := range cleaned {
        if !strings.ContainsRune(codeAlphabet, r) {
            return "", false
        }
    }
    return cleaned, true
}
```

> 单元测试要点:同一明文 hash 稳定;不同明文 hash 不冲突;normalize 处理空白 / 大小写 / 半角全角(只半角,我们不接全角)。

### 4.2 兑换码批量生成事务

```go
// internal/payment/redeem/service.go (节选)

func (s *service) BatchCreate(
    ctx context.Context, actorID int64, count int, amountQuota int64,
    expiresAt *time.Time, batchNo string,
) (plaintexts []string, batchNoUsed string, codeIDs []int64, err error) {

    // 1. 参数校验
    if count < 1 || count > 1000 {
        return nil, "", nil, apierr.New(apierr.CodeInvalidParam, "count must be 1..1000").
            WithDetails(map[string]any{"count": count})
    }
    if amountQuota <= 0 {
        return nil, "", nil, apierr.New(apierr.CodeInvalidParam, "amount_quota must be > 0")
    }

    // 2. 默认 expiresAt
    if expiresAt == nil {
        days := s.cfg.Setting.GetInt(ctx, "redeem.default_expires_days", 365)
        if days > 0 {
            t := s.cfg.Clock.Now().UTC().AddDate(0, 0, days)
            expiresAt = &t
        } // days == 0 表示永不过期,保持 nil
    }

    // 3. 默认 batchNo
    if batchNo == "" {
        batchNo = autoBatchNo(s.cfg.Clock.Now())
    }
    batchNoUsed = batchNo

    // 4. 生成 count 条明文 + hash + prefix,并准备 Code 记录
    plaintexts = make([]string, 0, count)
    codes := make([]*Code, 0, count)
    seenHashes := make(map[string]struct{}, count)  // 同批次内去重(理论上不会撞)
    for i := 0; i < count; i++ {
        var plain string
        var attempt int
        for {
            attempt++
            if attempt > 5 {
                return nil, "", nil, apierr.New(apierr.CodeInternal, "redeem codegen retries exhausted")
            }
            p, gerr := generatePlaintext()
            if gerr != nil {
                return nil, "", nil, apierr.Wrap(apierr.CodeInternal, gerr)
            }
            h := hashCode(p)
            if _, dup := seenHashes[h]; dup {
                continue
            }
            seenHashes[h] = struct{}{}
            plain = p
            break
        }
        h := hashCode(plain)
        now := s.cfg.Clock.Now().UTC()
        codes = append(codes, &Code{
            ID:          s.cfg.IDGen.Generate(),
            CodeHash:    h,
            CodePrefix:  prefix(plain),
            AmountQuota: amountQuota,
            BatchNo:     batchNo,
            Status:      StatusUnused,
            ExpiresAt:   expiresAt,
            CreatedBy:   actorID,
            CreatedAt:   now,
        })
        plaintexts = append(plaintexts, plain)
    }

    // 5. DB 事务批量 INSERT(单批 CreateInBatches);冲突重试一次
    err = s.cfg.DB.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
        // GORM CreateInBatches 默认 batch 100,够用
        return tx.CreateInBatches(codes, 100).Error
    })
    if err != nil {
        if isUniqueConstraintErr(err) {
            // 极小概率:与历史码 hash 冲突;整批重试(整批回滚后重新生成)
            return s.BatchCreate(ctx, actorID, count, amountQuota, expiresAt, batchNo)
        }
        return nil, "", nil, apierr.Wrap(apierr.CodeDatabase, err)
    }

    codeIDs = make([]int64, len(codes))
    for i, c := range codes {
        codeIDs[i] = c.ID
    }

    // 6. 审计:不记明文,只记 batch 元数据
    _ = s.cfg.Audit.Log(ctx, audit.Entry{
        ActorID:    ptrInt64(actorID),
        Action:     "redeem.batch_create",
        TargetType: "redeem_batch",
        After: audit.JSON(map[string]any{
            "batch_no":     batchNo,
            "count":        count,
            "amount_quota": amountQuota,
            "expires_at":   expiresAt,
        }),
    })
    return plaintexts, batchNoUsed, codeIDs, nil
}

// autoBatchNo 生成 "B" + yyyymmddHHMMSS + 4 位随机数 字符串。
func autoBatchNo(t time.Time) string {
    return "B" + t.UTC().Format("20060102150405") +
        fmt.Sprintf("%04d", mathrand.Intn(10000))
}
```

设计要点:

1. **明文 / hash 全部在内存中算完后一次性写 DB**,避免逐条 INSERT + commit 的延迟堆叠
2. **同批次内 hash 去重**:理论上 16 位 × 31 字符的明文空间足够大,但内存 set 兜底
3. **跨批次冲突回退**:`uk_redeem_codes_hash` 唯一索引兜底;命中 unique 错误时**整批回滚**,函数尾递归重生(无限层用最少;实践中冲突概率 ≈ 0)
4. **明文绝对不入库 / 不进 audit**:审计只记 batch_no / count / amount_quota / expires_at;明文丢失就是丢失,只能新生一批
5. **CreateInBatches batch=100**:GORM 默认值,平衡 SQL 长度与连接占用

`isUniqueConstraintErr`(放 `internal/orm/error.go` 共用):

```go
package orm

import "strings"

func IsUniqueConstraintErr(err error) bool {
    if err == nil {
        return false
    }
    msg := err.Error()
    // MySQL: "Error 1062: Duplicate entry"
    // PG:    "ERROR: duplicate key value violates unique constraint"
    return strings.Contains(msg, "Duplicate entry") ||
        strings.Contains(msg, "duplicate key value") ||
        strings.Contains(msg, "UNIQUE constraint failed")  // sqlite (tests)
}
```

### 4.3 兑换码兑换流程

```go
// internal/payment/redeem/service.go (节选)

func (s *service) Redeem(ctx context.Context, userID int64, plaintext string) (*RedeemResult, error) {
    // 1. normalize
    plain, ok := normalize(plaintext)
    if !ok {
        return nil, apierr.New(apierr.CodeRedeemInvalid, "兑换码格式无效").
            WithDetails(map[string]any{"reason": "format"})
    }
    h := hashCode(plain)

    // 2. DB 事务:SELECT FOR UPDATE → 校验 → UPDATE → Credit
    var (
        result *RedeemResult
        codeID int64
        amount int64
    )
    err := s.cfg.DB.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
        var c Code
        err := tx.Clauses(clause.Locking{Strength: "UPDATE"}).
            Where("code_hash = ?", h).
            First(&c).Error
        if errors.Is(err, gorm.ErrRecordNotFound) {
            return apierr.New(apierr.CodeRedeemInvalid, "兑换码不存在").
                WithDetails(map[string]any{"reason": "not_found"})
        }
        if err != nil {
            return apierr.Wrap(apierr.CodeDatabase, err)
        }

        switch c.Status {
        case StatusUsed:
            return apierr.New(apierr.CodeRedeemInvalid, "兑换码已被使用").
                WithDetails(map[string]any{"reason": "used"})
        case StatusDisabled:
            return apierr.New(apierr.CodeRedeemInvalid, "兑换码已被禁用").
                WithDetails(map[string]any{"reason": "disabled"})
        }
        now := s.cfg.Clock.Now().UTC()
        if c.ExpiresAt != nil && !c.ExpiresAt.IsZero() && now.After(*c.ExpiresAt) {
            return apierr.New(apierr.CodeRedeemInvalid, "兑换码已过期").
                WithDetails(map[string]any{"reason": "expired"})
        }

        // 3. UPDATE 状态
        upd := tx.Model(&Code{}).
            Where("id = ? AND status = ?", c.ID, StatusUnused).
            Updates(map[string]any{
                "status":  StatusUsed,
                "used_by": userID,
                "used_at": now,
            })
        if upd.Error != nil {
            return apierr.Wrap(apierr.CodeDatabase, upd.Error)
        }
        if upd.RowsAffected != 1 {
            // 并发:另一个事务已经把它兑了(理论上 SELECT FOR UPDATE 已经隔离,但兜底)
            return apierr.New(apierr.CodeRedeemInvalid, "兑换码已被使用").
                WithDetails(map[string]any{"reason": "used"})
        }
        codeID = c.ID
        amount = c.AmountQuota

        // 4. Credit(同事务外做更安全 — 不,wallet.Credit 内部已保证原子;
        //    本事务此处只为锁定 redeem_codes 行,Credit 自管事务)
        //    决策:Credit 放事务**外**,见 §4.5 错误回滚说明。
        result = &RedeemResult{
            CodeID:      c.ID,
            AmountQuota: c.AmountQuota,
            UsedAt:      now,
        }
        return nil
    })
    if err != nil {
        return nil, err
    }

    // 5. wallet.Credit(单独事务)
    w, err := s.cfg.Wallet.GetOrCreate(ctx, "user", userID)
    if err != nil {
        // 状态已变 used 但钱包出错:rollback redeem 状态(见 §4.5)
        s.rollbackRedeem(ctx, codeID)
        return nil, apierr.Wrap(apierr.CodeInternal, err)
    }
    if err := s.cfg.Wallet.Credit(ctx, w.ID, amount, "redeem", codeID, fmt.Sprintf("redeem code %s", "")); err != nil {
        s.rollbackRedeem(ctx, codeID)
        return nil, apierr.Wrap(apierr.CodeInternal, err)
    }
    bal, _ := s.cfg.Wallet.Balance(ctx, w.ID)
    result.BalanceAfter = bal

    // 6. 审计
    _ = s.cfg.Audit.Log(ctx, audit.Entry{
        ActorID:    ptrInt64(userID),
        Action:     "redeem.use",
        TargetType: "redeem_code",
        TargetID:   ptrInt64(codeID),
        After: audit.JSON(map[string]any{
            "amount_quota":  amount,
            "balance_after": result.BalanceAfter,
        }),
    })
    return result, nil
}

// rollbackRedeem 把 status 从 used 回滚到 unused,用于 Credit 失败时补偿。
// 仅写 audit warning,不返回错误。
func (s *service) rollbackRedeem(ctx context.Context, codeID int64) {
    err := s.cfg.DB.WithContext(ctx).Model(&Code{}).
        Where("id = ? AND status = ?", codeID, StatusUsed).
        Updates(map[string]any{
            "status":  StatusUnused,
            "used_by": nil,
            "used_at": nil,
        }).Error
    if err != nil {
        s.cfg.Log.Error("redeem rollback failed",
            zap.Int64("code_id", codeID), zap.Error(err))
    }
    _ = s.cfg.Audit.Log(ctx, audit.Entry{
        Action:     "redeem.rollback",
        TargetType: "redeem_code",
        TargetID:   ptrInt64(codeID),
    })
}
```

四种失败语义 details.reason 总结:

| reason | message | 触发 |
|---|---|---|
| `format` | 兑换码格式无效 | normalize 失败(长度 / 非法字符) |
| `not_found` | 兑换码不存在 | hash 查不到 |
| `used` | 兑换码已被使用 | status = used 或并发已使用 |
| `disabled` | 兑换码已被禁用 | status = disabled |
| `expired` | 兑换码已过期 | now > expires_at |

> 全部用同一个错误码 `CodeRedeemInvalid`(对外展示) + `details.reason`(给前端做精确文案 / 埋点)。安全考虑:`not_found` 与 `used` 的反馈在 message 上**有意区分**(便于用户排查),并不算严重信息泄露 — 兑换码不是身份凭证。

### 4.4 手动充值汇率换算

```go
// internal/payment/manual/exchange.go
package manual

import "math"

// ComputeQuota 把人民币金额按"当时汇率"换算成 quota。
//
//   amountYuan = amountMoney / 10000.0
//   amountUSD  = amountYuan / exchangeRateCNYPerUSD
//   amountQuota = floor(amountUSD * baseQuotaPerDollar)
//
// 全部用 float64 做中间运算,只在最后一步 floor 成 int64。
// 因为 quota 是整数,这里**向下取整**,极小的浮点误差不会让用户多收 / 少收。
//
// 失败:exchangeRate <= 0 或 baseQuotaPerDollar <= 0 时返回 0,调用方应当配置异常报错(handler 层兜底)。
func ComputeQuota(amountMoney int64, exchangeRateCNYPerUSD float64, baseQuotaPerDollar int64) int64 {
    if exchangeRateCNYPerUSD <= 0 || baseQuotaPerDollar <= 0 {
        return 0
    }
    yuan := float64(amountMoney) / 10000.0
    usd := yuan / exchangeRateCNYPerUSD
    return int64(math.Floor(usd * float64(baseQuotaPerDollar)))
}
```

测试矩阵:

| amountMoney(厘) | rate | base/$ | 期望 quota |
|---|---|---|---|
| 1_000_000 (100 元) | 7.0 | 500_000 | 7_142_857 |
| 100_000_000 (10000 元) | 7.0 | 500_000 | 714_285_714 |
| 0 | 7.0 | 500_000 | 0 |
| 1_000_000 | 0 | 500_000 | 0(配置异常) |
| 1_000_000 | 7.0 | 0 | 0(配置异常) |
| 999 (0.0999 元) | 7.0 | 500_000 | 7(floor) |

### 4.5 状态写 / Credit 调用的失败回滚

manual + redeem 两条入账路径都是 **"写自身状态 → 调 wallet.Credit"** 两步。`wallet.Credit` 内部已是单事务(M1-06),无法和"自身状态"放进一个跨表事务(状态在 manual_recharges / redeem_codes,wallet 在 wallets + ledger_entries,且 Credit 可能要走 Redis 路径),所以本 spec 选择**显式补偿**而不是 2PC:

```
[Approve / Redeem]
  Tx-A: 自身表 pending → approved/used    成功
     |
     v
  Tx-B: wallet.Credit                    成功 → 完成
                                          失败 → rollback Tx-A(写 audit recharge.rollback / redeem.rollback)
```

补偿语义:

- **manual.Approve** Credit 失败:`status` 从 approved → pending,`reviewer_id / review_note / reviewed_at` 清空,`amount_quota` 重置 0
- **redeem.Redeem** Credit 失败:`status` 从 used → unused,`used_by / used_at` 清空

补偿本身可能也失败(数据库都不可用了),此时**接受最终一致**:
- 写明显的 `*.rollback_failed` audit + ERROR 级日志
- 管理员可以通过 audit 找出 "approved 但没 ledger 入账" / "used 但没 ledger 入账" 的脏数据,手工修正

> 这是工程权衡。线性历史上"两阶段补偿失败"概率极低(本地 DB 都崩了),用 audit 兜底比上 saga 框架更轻。

## 6. 前后台联动

> 本 spec 仅给字段契约 / 路由 / 文案规范,具体 UI 实现见 [M1-09 后台前端](./2026-05-21-里程碑1-09-后台前端-设计稿.md) 与 [M1-10 用户前台](./2026-05-21-里程碑1-10-用户前台-设计稿.md)。

### 6.1 用户前台(web/user)

#### 6.1.1 申请充值页面 `/console/recharge`

- 入口:用户控制台侧栏 "充值" 菜单
- 显示当前余额 + 当前汇率(从 `GET /api/public/config` 拿;具体 endpoint 在 [M1-12](./2026-05-21-里程碑1-12-公告和系统设置-设计稿.md))
- 表单字段:`amount_yuan`(number,带 min/max placeholder)、`note`(textarea)
- 提交按钮:POST /api/user/payment/manual
- 列表:同页下方表格显示我的历史申请(GET /api/user/payment/manual),pending 单显示"取消"按钮
- 状态徽章配色:pending=info / approved=success / rejected=danger / canceled=muted

#### 6.1.2 兑换码 `/console/redeem`

- 单输入框 + 立即兑换按钮
- 成功显示 toast:`已成功兑换 +500,000 quota,当前余额 1,500,000`
- 失败按 `details.reason` 文案区分:
  - format → "兑换码格式无效,请检查输入"
  - not_found → "兑换码不存在,请确认"
  - used → "兑换码已被使用"
  - disabled → "兑换码已被禁用,请联系管理员"
  - expired → "兑换码已过期"

### 6.2 管理后台(web/admin)

#### 6.2.1 充值审批列表 `/admin/payments/recharges`

- 顶部 tab 按状态过滤:`全部 / 待审批(默认) / 已通过 / 已驳回 / 已取消`
- 表格列:申请人(username + email)、金额(元)、申请备注、申请时间、状态、操作
- 操作按钮:
  - pending:`通过` / `驳回`(都弹一个备注输入对话框,提交后调 approve/reject)
  - 非 pending:`查看详情`(展开 reviewer / reviewed_at / review_note)
- 审批通过后实时刷新当前用户余额展示(`balance_after`)

#### 6.2.2 兑换码管理 `/admin/payments/redeem`

- 顶部按钮:`批量生成`、`导出 CSV`
- 过滤:批次号 + 状态
- 表格列:code_display(`ABCD-****-****-****`)、batch_no、amount_quota、status、used_by、used_at、expires_at、创建人、created_at
- 行操作:`禁用`(unused 状态显示)、勾选多行显示"批量禁用"
- "批量生成"对话框:count(1..1000)、amount_quota、expires_at(datepicker)、batch_no(可空)
- 生成成功后**全屏 Modal 强提示**:
  - 标题:`兑换码已生成,请立即保存`
  - 警告语:`服务器不保存明文,关闭后无法恢复`
  - 文本框显示全部明文(`XXXX-XXXX-XXXX-XXXX` 一行一码)
  - 操作:`复制全部` / `下载 .txt` / `下载 .csv (含明文,仅此一次)` / `我已保存,关闭`
- "下载 .csv(含明文)" 是前端用 `codes[]` 自己拼,与 export 路由的"hash-only 导出"区分

### 6.3 设置项展示

[M1-12](./2026-05-21-里程碑1-12-公告和系统设置-设计稿.md) 的设置页应当包含以下分组的可视化编辑:

- `manual_recharge.enabled`(toggle)
- `manual_recharge.min_amount_cny` / `manual_recharge.max_amount_cny`(数字)

## 7. 错误码

本 spec **不新增错误码**,全部复用 [总纲 §8 + M1-01](./2026-05-21-里程碑1-01-基础设施增量-设计稿.md#7-错误码补充) 已声明的:

| 码 | 场景 |
|---|---|
| `CodeInvalidParam` (40004) | amount_yuan 超范围 / count 超范围 / amount_quota ≤ 0 / not_pending / not_unused / 缺字段 |
| `CodeMissingParam` (40003) | body 缺 amount_yuan / code |
| `CodeForbidden` (40006) | 非管理员调 admin 路由 / 用户取消他人单 |
| `CodeOrderNotFound` (70010) | 单据 / 兑换码 id 不存在(由 [总纲 §8](./2026-05-21-里程碑1-总体设计纲要.md) 与 M0 codes.go 提供) |
| `CodeRedeemInvalid` (70011) | 兑换码 5 种失败,统一码 + details.reason 区分 |
| `CodeBalanceInsufficient` (70001) | 本 spec 不主动抛(只在 Credit 失败时上层兜底,实际不发生) |
| `CodeDatabase` (10002) | DB 写失败(包装层) |
| `CodeInternal` (10001) | 配置异常 / wallet.Credit 失败 / 补偿失败 |
| `CodeNotLoggedIn` (20001) | 未登录访问 user/admin 路由(由中间件拦截) |

> M0 的 `pkg/apierr/codes.go` 已有 `CodeOrderNotFound = 70010` 和 `CodeRedeemInvalid = 70011`,本 spec 直接使用。M1-01 i18n 表也已经包含两条消息,详见 [M1-01 §7](./2026-05-21-里程碑1-01-基础设施增量-设计稿.md#7-错误码补充)。

### 7.1 错误响应示例(用户侧 normal JSON)

```json
{
  "code": 70011,
  "message": "兑换码已过期",
  "details": { "reason": "expired" }
}
```

handler 用 `apierr.New(...).WithDetails(...)` 构造,中间件 `ErrorResponse("json")` 渲染。

## 8. 配置项

本 spec 不新增 setting key — 全部已经在 [M1-01 §8](./2026-05-21-里程碑1-01-基础设施增量-设计稿.md#8-配置项补充) 的 seed 中写入。仅消费:

| key | 读取者 | 默认值 |
|---|---|---|
| `manual_recharge.enabled` | `manual.Apply` 入口 | `true` |
| `manual_recharge.min_amount_cny` | `manual.Apply` 校验 | `100` |
| `manual_recharge.max_amount_cny` | `manual.Apply` 校验 | `100000` |
| `manual_recharge.exchange_rate_cny_per_usd` | `manual.Approve` 计算 quota | `7.0` |
| `pricing.base_quota_per_dollar` | `manual.Approve` 计算 quota | `500000` |
| `redeem.default_expires_days` | `redeem.BatchCreate` 默认过期 | `365` |

读取统一走 `setting.Store.GetXxx(ctx, key, default)`,自带本地缓存(60s TTL)+ Pub/Sub 失效。

> 注意:`manual.Approve` 读取的是**审批那一刻**的汇率与 base/$,而非申请那一刻的。这是有意的设计 — 若审批延迟一周而汇率剧变,我们以审批时为准;申请单上的 `amount_quota=0` 直到审批才填,前端在用户列表上若显示"预估到账 quota",必须明确标注"按当前汇率预估,实际以审批为准"。

# 0. 预备 — 用 M1-02 注册的 user(alice / role=0)和 admin(root / role=2),登录拿 session cookie

# 4. alice 查余额
curl -H 'Cookie: sess=<alice>' /api/user/wallet
# → balance = 14285714

# 5. 管理员批量生成 3 张 1k quota 的码
curl -X POST -H 'Cookie: sess=<root>' /api/admin/payments/redeem_codes/batch \

# 6. alice 兑第一张

# → balance_after = 14286714

# 7. 再兑同一张
curl -X POST -H 'Cookie: sess=<alice>' /api/user/payment/redeem \
  -d '{"code":"<plain1>"}'
# → 400, details.reason="used"

# 8. 管理员禁用第二张
curl -X POST -H 'Cookie: sess=<root>' /api/admin/payments/redeem_codes/<id2>/disable \

# 9. alice 兑被禁用的
curl -X POST -H 'Cookie: sess=<alice>' /api/user/payment/redeem \
